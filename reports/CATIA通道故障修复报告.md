# CATIA 通道故障排查与修复报告

> 故障现象（用户现场截图）：把「内六角螺栓 M5x16」发到 CATIA，CATIA 里只出来
> 一根螺杆 + 一个螺钉头，日志报：
> `孔: 缺少对象` / `弹性垫圈 ⌀8.8×1.2 : 缺少对象`，
> `MakeSketch(7) Sketches.Add failed: 方法 Update 失败`，
> 最后 `features done: -2/4`。

---

## 一、根因：一条**零深凹槽**把整棵 Part 毒死了

从 CATIA 侧留下的推送日志（`%TEMP%\ai_modeler_push_*.log`）逐行还原出的链条：

```
1:15:29    [3/6] 内六角孔 对边4
1:15:29  PlaneAt(5.5) hsf=True ；AddNewPlaneOffset off=True err=0
1:15:29      FAILED: 方法 Update 失败          ← 第 3 条特征让 Part 进入报错状态
1:15:29  PlaneAt(-1) hsf=True ；…
1:15:29  MakeSketch(-1) Sketches.Add failed: 方法 Update 失败   ← 之后全都连带失败
1:15:29      FAILED: 缺少对象
```

真正的问题在第 3 条特征「内六角孔」上。它是一条**六边形轮廓的凹槽**，
导出表里是这样的：

```
poly_cut|0|0|5.5|0|0|0|0|内六角孔 对边4|1.7321,1;0,2;…     ← 最后一格 depth = 0
```

**`depth = 0`**。原因在 `ai_modeler/catia_export.py`：凸台转切除时只改了 `kind` 和 `z`，

```python
if is_cut and not e['kind'].endswith('_cut'):
    e['kind'] = e['kind'].replace('_pad', '_cut')
    e['z'] = e['z'] + e['h']          # ← 只挪了草图位置
    # 缺一句： e['depth'] = e['h']
```

而切除类导出读的是 **`depth`**，不是 `h`：

```python
hv = e.get('depth', 0.0) if kind.endswith('_cut') else e.get('h', 0.0)
```

于是导出了一个零深凹槽。**零深凹槽在 CATIA 里不是"没效果"，而是让整棵 Part
进入 update 报错状态**，接下来每一次 `Sketches.Add` 都失败 —— 用户看到的
"只出了杆和头、其余全报缺少对象"就是这个连锁反应。

---

## 二、连带查出的三个同源缺陷

修完主因后，我把**全部 523 个真实型号**过了一遍导出（新写的
`tools/check_catia_export_real.py`），又抓出三个同类问题：

| # | 缺陷 | 后果 | 状态 |
|---|---|---|---|
| 1 | `poly_cut` 的 `depth = 0`（凸台转切除时漏搬） | **整棵 Part 报废**（本次故障） | ✅ 已修 + 加了拦截 |
| 2 | 六角孔做小了、还埋进了头里 | 对边只有 0.866s（M5 做成 3.46 而非 4）；头顶留 1 mm 盖子，等于没有内六角孔 | ✅ 已修 |
| 3 | 垫圈内孔被"钳"到螺杆直径 | `_clamp_cuts` 取 `min(所有直径)`，对"螺钉+两个垫圈"这种多体件就是螺杆 ⌀5 → 两个垫圈孔都被钳成 ⌀4.8，又被当成重复切除合并掉一个 | ✅ 已修（改取 `max`） |
| 4 | 吊环的环体在 **Y 轴**上 | CATIA 导出通道只认 Z 轴 → 环体被**静默跳过**，CATIA 里只剩一根螺杆 | ✅ 已修（导出器支持 X/Y/Z 三轴） |

还有一个**既有缺陷**（不在本次改动范围内，如实列出，本轮未修）：

- `多槽带轮` 的 3 条 V 形槽原本被导成 3 个 `poly_cut`，同样是 `depth=0`；
  更本质的是**V 槽是回转切除**，而本通道只有"草图+凸台/凹槽"两种线性操作，
  原理上做不出环形槽。现在改成**只出准确的光轮盘体**，并把标准槽参数
  （标准号、bd、hf、ha、e、槽角）写进提示，让用户用「旋转槽(Groove)」补 ——
  **不再伪造做不出效果的假特征**。

## 三、修了什么（逐条）

| 文件 | 改动 |
|---|---|
| `ai_modeler/catia_export.py` | 凸台→切除转换时**补 `depth = h`**；新增**零深拦截**（任何拉伸/切除厚度 ≤0 的特征一律兜底并报警，绝不发给 CATIA）；`hole`/`cylinder` 支持 X/Y/Z 三轴（含按轴取包围盒范围）；记录格式加第 11 段"轴字母"；带轮不再伪造 V 槽切除，改为光轮 + 标准参数提示 |
| `catia_plugin/catia_build_core.vbs.txt` | `PlaneAt(ax, off)` 按轴挑基准面（Z→PlaneXY / X→PlaneYZ / Y→PlaneZX）；`MakeSketch(ax, off)`；`BuildOne` 读第 11 段轴字母（10 段老表按 Z 兜底）；**宏侧再拦一道零深特征**（拒绝而不是毒死 Part）；顺手把文件里两行乱码中文改成 ASCII（该文件要求纯 ASCII，CATScript 读非 ASCII 会报无效字符） |
| `ai_modeler/catia_tpl_helpers.txt` | Python-COM 通道同样按轴取基准面（`_plane_for(part, z, ax)`） |
| `ai_modeler/realparts.py` | 六角孔：对边按 `s/√3` 算外接半径（使对边 = s）；底面摆在 `hk − 深度`（内核 `prism` 的 `center` 是**底面**，不是中心）；垫圈内孔改到**螺杆并入之前**切（否则 ⌀5.3 的内孔会把 ⌀5 的螺杆掏空） |
| `ai_modeler/reallib.py` | 六角孔深按 ISO 4762 取 `0.5 × 头高`（M5 2.5 / M6 3 / M8 4 / M10 5 / M12 6，与该标准逐档一致；旧值 0.6 倍在 M10 会做成 6） |
| `ai_modeler/partlib.py` | `_clamp_cuts` 外轮廓由 `min` 改 `max`（多体件不能被最小的那段钳住） |
| `catia_plugin/catia_build_core.vbs.txt` | 增加零深特征拒绝逻辑 |

## 五、这次故障留下的两条经验

1. **导出的"零厚度"必须拦死。** 在 CATIA 里零深凸台/凹槽不是一个"没效果的操作"，
   而是让整棵 Part 报错、后续全部失败的毒药。现在在**两处**都拦：Python 导出端
   兜底 + 宏端拒绝。
2. **验收不能只看包围盒。** 这次两个几何错误（六角孔做小、垫圈孔被钳）都
   **完全不影响包围盒** —— 换汤不换药的外轮廓照样是 40×20×20。所以孔类特征
   改用体积法核对解析值；这条已固化成 `tools/check_bolt_real_geometry.py`。
