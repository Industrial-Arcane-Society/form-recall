## 三、语言与口径升级（这是这次改动量最大的部分）

### 1. 把"自我否定式"表述改成"口径 + 分级 + 验证路径"

原文大量出现"本报告不宣称 / 不能作为 / 不作推定"，虽然诚实，但读起来像在自我否认，评审看不到能力。
升级后统一改成三段式：**先把口径说清楚 → 再给证据分级 → 最后给验证路径**。例如：

* 原文："Agent 模式当前不会自动生成 CATPart……因此本产品是 CAD 建模前端的智能辅助与候选生成工具，不将模型结果表述为已满足制造公差或可直接投产。"
* 升级："交付物为 .aimodel / STL / 三视图预览 / geometry-report.json。Agent 模式当前不自动生成 CATPart、也不在 CATIA 中做 B-Rep 验证；CATIA 导出与插件通道由用户确认候选后另行调用。因此定位是 **CAD 建模前端的智能辅助与候选生成工具**。"（保留边界，但先说交付了什么）

### 2. 建立了统一的证据分级（贯穿全文）

【已实现】以当前代码为准 ｜【有量化记录】以可复跑脚本产出的报告为准 ｜【待验收】标注未完成实验并给出验收协议。
封面之后新增一段口径声明，作品简介的状态表也按这三档重排。

### 3. 收口了"几何复现率三个数值互相冲突"这个硬伤

原文档写"不同报告分别记录 99.8% / 91.9% / 67.7%，不能解释为同一基准上的连续提升，本报告不选最高分"——
诚实但没有结论。升级后解释了**差异来源**（判据脚本版本、数据版本、评分修正不同），
给出**现行统一口径**：以 `tools/bench_detail_fidelity.py` 对实测 STEP 的圆柱面（直径/轴线/位置）做 F1 计分、编造的孔同样扣分，
当前数据集上 99.8%（498/502）；并写明**提交前冻结数据、脚本、真值与排除规则后复跑一次**，把复跑记录随报告提交。

### 4. 表格内容精准化

* 测试表（4.3）每行"证据边界"改为"**能支撑 / 不能支撑**"两段式，避免读者误读；
* 技术选型表、工具表、扩展性表、竞品对比表、不足与规划表等逐格补全（共 139 个单元格）；
* 术语统一：快速模式 / Agent 创造模式 / 特征树 / geometry revision / preview_generation / 复核记录 / 判据 / 口径。

### 5. 修正笔误

原文多处写作 `reports/提示词测试报告。md`（句号误打成"。"），已全部修正为 `.md`。

## 六、本次升级是怎么做的（可复现）

用脚本在原 docx 上**就地修改**，不改结构：

```
python tools\upgrade_report.py --probe    # 先检查锚点是否唯一（29 个锚点全部唯一）
python tools\upgrade_report.py --apply    # 应用升级，输出到桌面
```

随后用 Word 打开升级稿、更新目录域与页码、保存。整个过程可重复执行（每次都从原始文档重新生成，不会叠加）。
