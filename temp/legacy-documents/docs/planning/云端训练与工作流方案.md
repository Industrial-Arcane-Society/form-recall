# AI 自动建模助手：云端常驻训练 + 工作流化 升级方案

> 编制日期：2026-09-23　　适用对象：`AI 自动建模助手`（纯 Python 桌面程序 + CATIA 推送通道）
> 目的：把"提示词 → 建模"从**单次问答**升级为**可编排、可验收、可自纠**的工作流，
> 并给出接入在线云服务器（24×7 常驻训练）的配置、成本与最优训练法。

---

## 一、先看结论（三句话）

1. **工作流**：把建模拆成"解析 → 取真实数据 → 建几何 → 校验 → 渲染 → 比对 → 诊断 → 修复 → 回归"
   这些**有输入输出、有门禁、可重跑**的步骤，用一份配置串起来；每一步都能单独跑、单独看结果、
   单独回滚。它不是"更复杂的提示词"，而是**把提示词接进一条质量流水线**。
2. **云服务器**：这台插件本身**不需要 GPU 才能工作**（几何是 CPU 计算），但要做
   "24×7 自动优化 + 大规模批量回归 + 大模型微调"，一台常驻 GPU 机器的性价比最高。
   按 2 年计，**国产平台单卡 4090/24GB 档约 2 万~6 万元；A100 80GB 档约 15 万~40 万元；
   H100 档 40 万元以上**（区间原因与算法见 §4，签约前以官网实时报价为准）。
3. **最关键的现状**：本轮的**图像相似度**第一次算准了 —— 平均 **62.1%**、**0/313 达到 95%**。
   根因不是"提示词不好"，而是**模型的外轮廓还是包围盒**（`_box_features` = bbox 方块），
   而几何判据（91.9%）只量孔径/孔位/包络，**量不到外轮廓**。所以云端闭环的第一优化目标
   就是"外轮廓还原"，这与本项目的判据体系完全一致。

## 二、工作流（Workflow）是什么

### 2.1 一句话定义

**工作流 = 一组有明确输入/输出、按依赖顺序执行、带门禁与回滚的步骤的编排。**

区别于"一次提示词问答"：

| | 单次问答 | 工作流 |
|---|---|---|
| 执行 | 一次调用，成败都在一次里 | 多步串行/并行，每步可单独重跑 |
| 中间产物 | 不保留 | 每步留产物（JSON/网格/图片/日志），可复核 |
| 失败处理 | 整体失败 | 定位到具体步骤，重试/换参/跳过 |
| 质量 | 靠人看 | **门禁（Gate）**：不达标就卡住，不让坏结果往下走 |
| 复用 | 每次重来 | 步骤可复用、可组合、可批量化 |

### 2.2 在这个插件里，"工作流"长什么样

一条**建模工作流**（日常使用）：

```
① 提示词解析        prompt → 意图/型号/尺寸        （nlparser）
② 真实数据检索      model  → 实测圆柱/包络/孔位    （kb/ + reallib）
③ 族内建模          → 特征表（docmodel.Feature[]） （realparts 各族构建器）
④ 几何构建          特征表 → 网格                 （kernel BSP / occ_kernel）
⑤ 度量与校验        体积/包络/孔位 vs 实测         （bench 同口径判据）  ← 门禁①
⑥ 渲染              网格 → PNG（与实拍同视角）      （softrender）
⑦ 图像比对          AI 图 vs 真实图 → 相似度        ← 门禁②
⑧ 诊断              差异定位到"哪个特征/哪个参数"   （要新建）
⑨ 修复              改构建器逻辑或参数              （人 / 自动候选）
⑩ 回归              全量重跑，禁止绿变红            ← 门禁③
⑪ 归档发布          结果 + 判据 + 图片入库          （reports/ + kb/）
```

一条**训练工作流**（云端 24×7）：

```
拉取数据 → 生成提示词变体 → 批量建模 → 批量度量/渲染/比对
   → 无法通过的样本聚成"失败簇" → 自动诊断候选补丁 → 小样本验证
   → 通过则进"待审队列" → 人工一键合入 → 全量回归 → 发布新版本
```

### 2.3 工作流的三条硬规矩（本项目已经在用的）

1. **判据先行**：任何"改进"都必须先有可复核的判据（本项目的
   `bench_detail_fidelity` / `bench_real_geometry` / 图像相似度）。
2. **门禁卡死**：判据不达标就**不放行**（例如"相似度 <95% 不许标完成"）。
3. **禁止绿变红**：任何一次改动都要跑全量回归，出现退化立即回滚。

## 三、现状盘点（为什么需要云端闭环）

### 3.1 已经跑通的口径

| 判据 | 现在 | 说明 |
|---|---|---|
| 细节复现度（孔/直径/轴线/位置 vs 实测 STEP） | 平均 **91.9%**，≥95% **431/502** | 硬判据，最可信 |
| 真实几何命中（围包络） | **591/593** | — |
| CATIA 通道 / 孔位 | 523/523、267/267（74601 孔） | 推送链路可用 |
| 自检 | 35/35 | — |
| **图像相似度（AI 渲染图 vs 重拍真实照片）** | 平均 **62.1%**，**0/313 ≥95%** | 本轮**首次算准**（见下） |

### 3.2 本轮图像口径为什么能算准了

原来拿"CATA 整窗截图"比边缘：实测真配对 85.3% / 交叉配对 84.1%，**只差 1.2 个点** ——
没有区分能力。这一版改为**每个零件拍两张**（`tools/reshoot_real_parts.py`）：

* `<型号>.png` 零件可见；`<型号>_bg.png` 隐藏零件、相机不动 → **两帧相减 = 精确掩码**；
* AI 侧掩码来自渲染时的品红背景 → 同样精确；
* 相似度 = 0.5·IoU + 0.5·(1 − 归一化对称 chamfer)。

518 个零件全部重拍成功（约 29 分钟）。

### 3.3 62.1% 的根因（这才是要优化的东西）

对比看得很清楚：**支座 `KMS-M05-010-100-D`** 的 AI 侧是一个"方块"，真实侧是"L 形支架"；
**型材**两边的长条角度对得上，但厚度与端部细节不同。原因是：

> 现在多数非标件是用 **`_box_features(实测包络)` = 一个包围盒 + 若干孔** 建的 ——
> 外轮廓根本没有还原（型腔、加强筋、台阶、圆角、自由曲面全都丢了）。
> 几何判据量的是"孔对不对、包络对不对"，**量不到外轮廓**，所以一直显示高分。

**结论：云端闭环的第一个优化目标 = 外轮廓还原。** 具体做法：
* 从实测 STEP 里抽取**外轮廓特征**（平面/圆柱面/锥面/圆角/型腔），
  用 B-Rep 重建（`ai_modeler/core/occ_kernel.py` 已就绪，OpenCASCADE 已装好）；
* 建立"外轮廓判据"（图像 IoU + 侧面法向/面积分布），与孔判据并列进工作流门禁。

## 四、接入在线云服务器：配置与 2 年成本

### 4.1 这台插件到底需要什么算力

| 任务 | 需要什么 | 说明 |
|---|---|---|
| 几何建模（现在） | **纯 CPU**，单核即可 | 545 孔 0.5 s；BSP 内核瓶颈在单线程 |
| 批量回归（500 零件 × 多判据） | CPU 多核（8~32 核） | 实测全量回归约 10~30 分钟 |
| 渲染 + 图像比对 | CPU 为主 | 447 张渲染 20 分钟（可并行到几分钟） |
| 参数搜索 / 自动调参 | CPU 多核 + 大内存 | 组合爆炸时最吃机器 |
| **大模型微调**（可选，提升提示词理解） | **GPU（≥24GB 显存）** | 7B 级 QLoRA 24GB 可跑；14B 建议 48GB+ |
| 大模型推理（常驻小模型） | GPU（可共用） | 7B int4 约 6~8GB 显存 |

**所以：GPU 只在"微调/常驻小模型"时必要；其余靠 CPU 核数与内存。**

### 4.2 三档配置建议（可直接照抄去下单）

| 档位 | 配置 | 适合 | 参考月租（按需） |
|---|---|---|---|
| **A 轻量起步** | 16 vCPU / 64 GB / 1× RTX 4090 24GB / 1 TB SSD | 批量回归 + 7B 级 QLoRA 微调 + 常驻小模型 | 国产平台约 1.5~3 元/GPU 小时；CPU 部分另计 |
| **B 标准产线** | 32 vCPU / 128 GB / 1× A100 80GB（或 L40S 48GB）/ 2 TB SSD | 14B 微调、多任务并行、7×24 常驻 | A100 80GB 大致 8~20 元/小时（平台差异大） |
| **C 高吞吐** | 64 vCPU / 256 GB / 2× H100 80GB / 4 TB NVMe | 多模型并行训练 + 大规模数据合成 | H100 大致 20~40 元/小时 |

> 上述小时价是**公开区间的量级**，仅用于估算：国内平台（AutoDL、阿里云、腾讯云、火山引擎）
> 与海外平台（RunPod、Vast.ai、Lambda）差异很大，且随促销波动。
> 参考来源：[AutoDL 使用与计价指南](https://github.com/JoeyYu23/autodl-guide)、
> [阿里云 GPU 实例与活动价](https://developer.aliyun.com/article/1711191)、
> [2025 阿里云 GPU 租用价格详解](https://developer.aliyun.com/article/1685791)、
> [各平台 GPU 租赁价格对比](https://cloud.baidu.com/article/4469280)、
> [2026 GPU 云服务器成本对比](https://www.ucloud.cn/yun/articles/2768)。
> **下单前请以官网实时报价为准。**

### 4.3 2 年成本怎么算（给出公式，自己就能核）

```
按需（24×7 常驻）：  年成本 = 时价 × 24 × 365
包年/预留（一般 3~5 折）：年成本 ≈ 按需 × 0.3 ~ 0.5
2 年总成本 = 2 × 年成本 + 存储费 + 带宽/快照费 + 运维人力
```

按上表的量级代入：

| 档位 | 按需 24×7（2 年） | 包年 5 折（2 年） | 包年 3 折（2 年） | 备注 |
|---|---|---|---|---|
| A（4090 24GB，按 2.5 元/时算） | ≈ 4.4 万元 | ≈ 2.2 万元 | ≈ 1.3 万元 | 另有 CPU/内存/存储 |
| B（A100 80GB，按 12 元/时算） | ≈ 21 万元 | ≈ 10.5 万元 | ≈ 6.3 万元 | 长约定价通常更低 |
| C（H100×2，按 30 元/时·卡算） | ≈ 105 万元 | ≈ 53 万元 | ≈ 32 万元 | 仅在高吞吐训练期开 |

**隐性成本（常被漏算）**：
* 存储：2 TB SSD + 快照，年约 2000~6000 元；
* 公网带宽/流量：按量计费，批量跑数据同步一年可能上千元；
* 镜像/环境维护、监控告警：可用开源方案（Prometheus+Grafana）省掉商业费；
* **人力**：闭环的"诊断→改代码"仍然需要人，云端只把"重复劳动"自动化。

**省钱三招（实测有效）**：
1. **训练期开机、验证期关机**：批量回归不需要 GPU，用 CPU 抢占式实例，成本降到 1/5；
2. **抢占式/竞价实例**：长任务加断点续跑（checkpoint 每 N 步存一次），可再省 50%~70%；
3. **分档混跑**：日常用 A 档常驻；需要微调时临时升到 B/C 档（按小时），不用整年买贵的。

## 五、在云上怎么训练才"最优"（可持续提高效率与准确性）

### 5.1 先明确：这个项目的"训练"是什么

**不是**从头训一个三维生成大模型（那需要百万级 CAD 数据，成本量级完全不同）。
本项目最划算的"训练"是四件事，按性价比排序：

| # | 事情 | 效果 | 算力 |
|---|---|---|---|
| 1 | **数据飞轮**：提示词变体 → 批量建模 → 判据打分 → 失败聚类 | 直接抬高命中率 | CPU 多核 |
| 2 | **参数搜索**：对每个族的构建器参数做网格/贝叶斯寻优（对齐实测 STEP） | 每个族都能逼近 100% | CPU 多核 |
| 3 | **外轮廓重建**：按实测 B-Rep 重建型腔/筋/台阶（OpenCASCADE 已就绪） | 图像相似度**唯一**的突破口 | CPU 单核为主 |
| 4 | **小模型微调**（可选）：把"提示词 → 参数 JSON"用 QLoRA 微调一个 7B/14B | 提升指令理解与容错 | GPU |

### 5.2 闭环的六个自动化（都是可以立刻写的工作流步骤）

1. **自动出题**：从 kb 里的 518 个真实型号 + 模板生成提示词变体（已有 1828 条，可扩到 1 万条）。
2. **自动判分**：跑现有判据（几何 + 图像），把每个样本的分数、失败原因写进实验库（SQLite/Parquet 即可）。
3. **自动聚类失败**：按"失败类型 × 族 × 判据分量"聚类，输出 Top-N 待修清单
   （已经是<95% 的清单，可自动生成）。
4. **自动候选修复**：对**参数类**失败自动搜参（不用人）；对**逻辑类**失败生成候选补丁（人审）。
5. **自动回归**：任何候选补丁必须先跑"小样本 200 条"再跑全量 500+；有退化自动回滚。
6. **自动归档**：每次迭代产出"判据快照 + 图片对比 + 变更说明"，形成可追溯的训练日志。

### 5.3 云端目录与调度（落地细节）

```
/workspace/ai-modeler/
├── repo/                 # 代码（git 拉取，只读挂载更安全）
├── kb/                   # 知识库（实测几何/特征/型号库）—— 只增不改
├── data/
│   ├── photos/           # 真实照片（带背景帧）
│   ├── renders/          # AI 渲染图
│   └── experiments/      # 每次迭代的判据结果（Parquet，便于统计）
├── jobs/                 # 工作流定义（YAML/JSON）
└── ckpt/                 # 微调 checkpoint（抢占式实例必备）
```

调度：轻量用 **cron + 自写 runner**（本项目规模完全够）；复杂了再上 Airflow/Prefect。
监控：显卡占用、任务耗时、判据趋势（相似度/命中率随时间的曲线）。

### 5.4 评判"训练有没有效果"的唯一标准

只看三条曲线（云端自动出图）：
1. **几何判据**：平均分与 ≥95% 件数（现在 91.9% / 431）；
2. **图像判据**：平均相似度与 ≥95% 件数（现在 62.1% / 0）；
3. **一次通过率**：新提示词不改代码就能达标的比例。

任何"训练"只要这三条不涨，就是无效训练 —— 这条规矩写进工作流门禁。

## 六、把工作流融进插件与云端（具体设计）

### 6.1 插件内：加一个 `workflow` 模块

```
ai_modeler/workflow.py
   定义 Step（名称/输入/执行/输出/门禁/重试）
   run_workflow(name, ctx) → 按依赖顺序执行，产出 artifacts + 判据报告
   workflows/build_part.json   一条零件建模工作流
   workflows/regression.json   全量回归工作流
   workflows/train_loop.json   云端训练循环工作流
```

* 界面上加一个"**一键跑完整流程**"按钮：解析→建模→校验→渲染→比对→出报告；
* 每一步的产物都在界面上可点开（网格、判据、渲染图、对比图）；
* 门禁失败时明确提示"卡在哪一步、差多少、建议改什么"。

### 6.2 云端：把同一个工作流做成常驻循环

```
每日 02:00  拉最新代码 + 知识库
每日 02:10  批量回归（全量 500+ 提示词，CPU 抢占式实例）
每日 03:00  图像比对（渲染 + 相似度）
每日 03:30  失败聚类 → 生成 Top-N 待修清单 → 发通知
每日 03:40  参数类失败：自动寻优（GPU 空闲时）
每周日     外轮廓重建实验 + 小模型微调（GPU 开机，跑完关机）
```

### 6.3 与 CATIA 的关系

CATIA 只在**推送/实拍**时需要（本机交互），云端不装 CATIA：
云端产出"几何 + 判据 + 图片"，本机负责"推送 CATIA + 抽查验收"。

## 八、风险与注意事项

| 风险 | 说明 | 对策 |
|---|---|---|
| 云端数据合规 | 客户零件几何/照片属敏感资料 | 私有网络、对象存储加密、不上传客户图纸原文（只上传派生特征） |
| 判据自欺 | 判据宽松就会"越训越假" | 判据必须有**负对照**（本项目对图像判据做过真/假配对标定） |
| 成本失控 | GPU 24×7 常驻最烧钱 | 抢占式 + 训练期开机 + 分档混跑；设预算告警 |
| 过度自动化 | 自动改代码可能引入退化 | 门禁 + 全量回归 + 一键回滚；逻辑类改动必须人审 |
| 依赖第三方 | 云平台/框架升级导致环境漂移 | 容器化（Docker 镜像 + lock 文件），kb 与代码分离 |
