# 理性讨论：这个项目（AI 建模插件 + 工作流 + 云端训练）能不能申请软著和专利

> 说明：本文是**技术侧的理性分析**，不是法律意见；具体个案请以代理机构/律师的判断为准。
> 文中涉及的费用与时限均标注了来源，政策会变，**办理前请以官方最新公告为准**。
> 讨论日期：2026-09-24

---

## 0. 结论先说（三句话）

1. **软件著作权（软著）：完全可以，而且条件很好 —— 建议现在就办。**
   它是"登记制 + 形式审查"，我们手上的东西（**183 个 Python 文件 / 5.3 万行 / 40 个模块 / 17 份 Word / 2862 行设计文档**）远超"源程序 60 页 + 文档 60 页"的要求，属于"材料挑得出来"的那一类。
2. **专利：有可能，但只能走发明专利，而且要挑对技术点 —— 必须先查新再决定。**
   纯"用 AI 自动建模"这种上位描述大概率被认定为**智力活动的规则和方法**而不予保护（专利法第 25 条）；
   但这个项目里确实有几处**具体的技术手段 + 可量化的技术效果**（例如"实测中心与网格中心不一致导致的孔位错位修正"、"双帧差分获取零件掩码"、"布尔剪枝的反向判据"），这些**作为权利要求里的具体技术特征是有价值的**。
3. **最硬的一条红线：先申请、后公开。** 一旦公开发布（把仓库转成公开、发论文、参加公开演示），**新颖性就没了**（宽限期只覆盖极少数情形）。我们现在的仓库是**私密**的 ✓ 目前没有风险，但顺序不能反。

## 1. 三种保护的边界（先分清，再谈申请）

| | **软件著作权（软著）** | **发明专利** | **商业秘密（技术秘密）** |
|---|---|---|---|
| 保护什么 | 代码的**表达**（源程序、文档） | **技术方案**（方法/系统/装置） | 未公开的信息（数据、规则、参数） |
| 怎么取得 | 登记（形式审查），权利自创作完成即产生 | 申请 → 实质审查 → 授权 | 不申请，靠保密措施 |
| 要不要公开 | 只公开"前后各 30 页"节选 | **全文公开**（18 个月后） | 永不公开 |
| 门槛 | 低（有独创性即可） | 高（新颖性/创造性/实用性） | 低，但泄露即失效 |
| 周期 | 约 1~2 个月（可加急） | 约 2~3 年（优先审查可缩短） | —— |
| 成本 | 官费已免，代理约几百元起 | 官费+代理数千至万元级 | 主要是管理成本 |
| 保护期 | 法人 50 年 / 自然人终生+50 年 | 20 年（自申请日起） | 保密多久保护多久 |
| 对我们的价值 | **证明权属、招投标/评奖加分、维权凭证** | 排他权（能挡别人用同样的技术方案） | 保住"型号→真实几何"这类数据库优势 |

**一句话**：软著保护"我写的这套代码"，专利保护"我发明的这个方法"，商业秘密保护"我攒下来的这些数据与经验"。
**三者不互斥，最务实的组合是"软著 + 1~2 件发明 + 核心数据当商业秘密"。**

## 2. 软著：条件够，建议现在就办

### 2.1 法律性质（避免误解）

* 软著是**登记**，不是"授予"：权利自软件开发完成之日产生，登记主要是**权属证明**与维权凭证；
* 登记做的是**形式审查**：看材料齐不齐、格式对不对，不实质审查"代码写得好不好"；
* 因此**只保护表达、不保护思想** —— 别人换个写法实现同样的功能，不构成侵权。这也是为什么"方法的保护"要去申请专利。

### 2.2 需要的材料（与我们的底数对照）

按中国版权保护中心的通用要求（[所需文件](https://www.ccopyright.com/index.php?optionid=1080)、[《计算机软件著作权登记办法》](https://wipolex-res.wipo.int/edocs/lexdocs/laws/zh/cn/cn070zh.pdf)）：

| 材料 | 要求 | 我们手上的 |
|---|---|---|
| 源程序 | 前 30 页 + 后 30 页（共 60 页，每页约 50 行） | **5.34 万行**（`ai_modeler` 2.87 万行 + `tools` 2.39 万行），挑 60 页毫无压力，且能挑**最能体现独创性**的部分 |
| 软件说明书 | 前 30 页 + 后 30 页（设计说明/用户手册） | `docs/` 2862 行 + `reports/` 4557 行 + **17 份 Word**（含《操作说明》《升级方向》《云端训练与工作流方案》） |
| 申请表 / 身份证明 | 按中心模板填 | 现成 |
| 权属证明 | 职务/委托开发要说明 | **需要先确认归属**（见第 4 节） |

> 结论：**材料充裕**，30 个工作日左右（可加急）能拿到登记证书。

### 2.3 费用与新政

* 软件著作权登记**已不收取登记费**（费用主要是代理服务费，几百元量级）；
* 有媒体报道"2026-03-15 起软著申请新政：免费申请 + 加强 AI 生成材料的诚信监管、黑名单制度"
  （见 [报道一](https://shuaici.blog.csdn.net/article/details/162043001)、[报道二](https://naipnews.naipo.com/42789/print/)）
  —— **以官方公告为准**；方向上要注意：**申请材料必须真实**，不能拿 AI 生成的水文充数。

### 2.4 提交时的三条实务禁忌

1. **不要放客户数据**：`零件参数/` 里的 CATPart/STEP、以及从它派生的 `kb/real_features.json`、
   `kb/real_brep/*.npz` 都属于**客户资产**，不进申请材料、也不开源；
2. **不要放第三方源码**：numpy / scipy / Pillow / OpenCV / OpenCASCADE(cadquery-ocp) 的代码
   一行都不要进 60 页节选（我们的自研代码足够挑）；
3. **说明书里别写客户型号**：用"某型材/某支座"这类脱敏表述。

## 3. 专利：可能，但要挑对"技术点"

### 3.1 法律边界（决定"能不能报"）

* 《专利法》第 25 条：**智力活动的规则和方法不授予专利权**；
* 但《专利审查指南》同时明确：如果一项权利要求**整体上既包含智力活动规则的内容、又包含技术特征**，
  则**不应依据第 25 条整体排除**
  （见 CNIPA 审查指南原文：["仅由所记录的程序本身限定的计算机可读存储介质…由于其实质上仅仅涉及智力活动的规则和方法，因而不属于专利保护的客体"](https://www.cnipa.gov.cn/module/download/downfile.jsp?classid=0&showname=%E4%B8%93%E5%88%A9%E5%AE%A1%E6%9F%A5%E6%8C%87%E5%8D%972023%EF%BC%882025%E5%B9%B4%E4%BF%AE%E8%AE%A2%EF%BC%89.pdf&filename=3f6306029ff741dfad6cee9282ec6efc.pdf)
  及 ["既包含智力活动的规则和方法的内容，又包含技术特征…不应依据专利法第二十五条排除"](http://www.cnipa.gov.cn/attach/0/73584f10eee149d59689e26f078c2c0c.pdf)）。
* 实务判据（通俗版）：**是不是解决了"技术问题"、用了"技术手段"、取得"技术效果"**。
  * "用 AI 帮工程师建模，提高效率" → 太空，容易被认定为智力活动 ✗
  * "针对 STEP 实测圆柱面的轴线与直径，按 XX 规则重建孔特征，使体积误差从 X% 降到 Y%" → 有技术手段、有可测效果 ✓

* **专利类型只能选"发明"**：
  * 实用新型只保护**产品的形状、构造**，纯方法/纯软件**不能**申请；
  * 外观设计不适用；
  * 所以如果以后做了硬件（比如"建模工作站/采集装置"），才可以另外考虑实用新型。

### 3.2 我们项目里的 6 个候选技术点（逐个诚实评估）

| # | 技术点 | 是不是技术方案 | 创造性障碍（在先技术） | 建议 |
|---|---|---|---|---|
| 1 | **实测驱动的零件几何复刻**：从 CATIA 导出的 STEP 里解析圆柱面（直径/轴线/位置）+ 三维包络 + B-Rep，建成"型号→真实几何"知识库，再据此用**参数化 / 直写网格 / OCCT** 三条通道重建零件 | ✓ 有（几何重建方法） | 逆向工程、特征识别、CAD 自动建模已有大量在先技术 → **上位写法难**；但**具体限定**（见下）有机会 | **重点候选**：把"实测中心 vs 网格中心不一致导致孔位整体错位"的修正、以及"直写网格 vs 布尔路径的切换判据"写进权利要求 |
| 2 | **局部化布尔加速**：BSP 累加器就地进行差集；**结点包围盒 + 面片包围盒双重剪枝**；共面片按"同向/反向"分流（且指出"整树取反时剪枝方向相反"这一反例） | ✓ 有（计算方法） | BSP/CSG 是几十年前的老技术，通用剪枝几乎必然被驳 ✗；"面片级二次剪枝 + 方向性判据"相对具体 | **次选**：作为"1"的从属权利要求写（别单独报） |
| 3 | **自然语言 → 零件族/参数映射**（含型号 token 解析、真实库覆盖、单位/规格归一） | △ 偏信息处理 | 大模型+参数抽取的专利极多 ✗ | **不建议单独报** |
| 4 | **双帧差分获取零件掩码 + 视向重拟合 + 容差口径的建模质量验收方法**：同一零件拍"可见/隐藏"两帧相减得精确掩码；用几何先验锁尺度、候选视向重拟合；1 px 容差 IoU 评价 | ✓ 有（测量/检测方法） | 背景差分是常见手段，但"针对 CAD 截图 + 视向重拟合 + 与建模闭环"的组合比较具体 | **重点候选**（尤其"两帧相减 + 视向重拟合"的组合） |
| 5 | **判据门禁闭环 + 云端自动寻优**（建模→度量→渲染→比对→归因→改参→回归，带门禁与回滚） | △ 偏管理/流程 | 流程编排类几乎不可专利 ✗；但"**以判据为目标的参数自动寻优方法**"（含具体的搜索空间与收敛判据）可能可以 | **弱**：可作为"1"或"4"的一部分，别单独报 |
| 6 | **CATIA 特征表推送方法**：把几何特征表经宏/COM 推入 CATIA；含坐标轴映射（PlaneZX 的面内轴序）、**零深特征保护**（零深会让整棵 Part 报错）、自由曲面件改走 STEP 通道 | ✓ 有（与 CAD 系统交互的方法） | 比较工程化，属于"别人没这么干过"的细节 | **可报**：把"零深/退化特征的防护 + 双通道（特征表/STEP）选择"写清楚 |

> 判断依据一句总结：**越是"我们的具体踩坑限定"，越可能过创造性；越是"用 AI 做 XX"，越可能被驳。**

## 4. 申请前必须先澄清的三件事（比技术更重要）

### 4.1 权利归属

* **职务开发**：如果是你在公司履职期间、用公司资源开发，一般属于**职务作品/职务发明**，
  申请人是公司（软件著作权法第 18 条 / 专利法第 6 条有默认规则）；
* **委托开发**：归谁**按合同约定**；没约定时，著作权一般归受托人、专利权一般归完成方；
* **自己做**：归你个人。
* → **先看清有没有劳动合同/委托合同/客户协议里的知识产权条款**，再决定以谁的名义申请。
  这一步做错，后面维权会非常被动。

### 4.2 客户数据（最容易被忽略的风险）

`零件参数/`（518 个 CATPart）、从它导出的 STEP、以及派生的
`kb/real_features.json`、`kb/real_brep/*.npz`、518 张实拍照片 —— 这些都是**客户/项目数据**，可能含保密义务。
* 申请材料里**不要出现**这些数据；
* 对外文档只讲**方法**，不讲**具体型号与尺寸**（我们很多报告已经这么做了，继续保持）；
* 仓库保持**私密**；要给别人看时，用协作包那种"脱敏 + 抽样"的形式。

### 4.3 开源许可合规（影响商业化，不影响软著登记）

| 组件 | 许可 | 对我们的约束 |
|---|---|---|
| numpy / scipy | BSD-3 | 宽松，可商用 |
| Pillow | MIT-CMU | 宽松 |
| OpenCV | Apache-2.0 | 宽松（注意其可选的专利条款） |
| OpenCASCADE（`cadquery-ocp`） | **LGPL-2.1 with exception** | 动态链接/独立进程使用一般没问题；**静态捆绑或修改其源码**要遵守 LGPL |
| Python 标准库 | PSF | 宽松 |

* 软著登记的是**我们的自研代码**，第三方库不进去；
* 商业化分发时，注意不要把 LGPL 组件改造成静态链接；保留版权声明与许可文本。

## 7. 追加讨论：软著到底难不难办、好不好过？

### 7.1 一句话答案

**难度很低，通过率很高 —— 但"通过"卡的是形式，不是技术。**

* 软著是**登记制 + 形式审查**：审查员只看"材料齐不齐、格不格式、信息自洽不自洽"，
  **不评价你的技术先不先进、有没有创新**（那是专利要管的事）；
* 所以不存在"技术不够好被驳回"这回事 —— 被卡住的**九成以上是材料问题**；
* 官方**不公布通过率**（网上各种"通过率 xx%"都不是官方数据，别当依据）。
  实务上的说法是：**驳回很少，绝大多数是"补正"**（指出问题 → 改完重新提交 → 通过），
  真正一驳到底的主要是"明显不是自己开发的"或"含违规内容"。

### 7.2 真正会被卡住的 10 种情形（这才是要防的）

| # | 情形 | 我们项目的风险 | 怎么处理 |
|---|---|---|---|
| 1 | 源程序页数/格式不对（要**前 30 页 + 后 30 页**、每页行数达标、页眉含软件名+版本号） | 无 | 用模板抽页，统一页眉 |
| 2 | 源码里**混入第三方代码**（开源库源码） | 低（我们没 vendor 任何库） | 只抽自研目录 `ai_modeler/`、`tools/` |
| 3 | 源码/文档里**含客户数据** | **有**：源码注释里出现 `KMS-M05-010-100-D`、`EGT001 SW80x088` 这类真实型号；`kb/real_features.json` 是客户实测尺寸 | **必须脱敏**：型号换成"某支座/某型材"，实测数据文件一概不放 |
| 4 | 材料之间**信息不自洽**（软件名/版本号/完成日期三处不一致） | 需要注意 | 统一写成"某某软件 V1.0"、完成日期早于申请日 |
| 5 | **软件名称不规范**（含"中国/国家/国际/最"等字眼；与已登记重名） | 无 | 用"AI 自动建模助手软件 V1.0"这类中性名 |

### 7.3 我们项目的"底子"评估

**加分项**（决定"好过"）：
* 代码量足、模块多：183 个 Python 文件 / 5.34 万行 / 40 个模块 → 60 页源码**挑得出精华**；
* 文档齐全且真实：17 份 Word + `docs/` 2862 行 + `reports/` 4557 行 → 说明书改写即可；
* 有**完整的可运行链路**与**版本演进记录**（实测判据数字一路可查）→ 真实性无争议；
* 有实测数据支撑（几何 99.8% / 图像 84.5%）→ 说明书里作为"技术效果"很有说服力。

**需要处理的两处**（决定"少跑一趟"）：
1. **脱敏**：源码注释与文档里的客户型号、尺寸、照片；
2. **归属**：先确认是职务作品/委托开发还是个人作品。

### 7.4 流程与时长（参考，以官方公告为准）

```
准备材料 → 中国版权保护中心线上提交 → 受理 → 形式审查 → 发证
                      （材料齐的话，一般 30~60 个工作日；可加急）
```

* **费用**：登记费已**免收**；自己办基本零成本，找代理一般是**几百元**服务费（省事、少跑补正）；
* **加急**：可选，需另付费（通过代理办理），能压到几个工作日到十几个工作日。

### 7.5 提高一次通过率的 6 条实操建议

1. **一件一报、名称规范、版本 V1.0**，材料之间数字自洽；
2. 源码 60 页**只挑自研核心**（`kernel.py`/`docmodel.py`/`directmesh.py`/`reallib.py`/`realparts.py`/`nlparser.py`…），
   **跳过**含客户型号与数据的文件；
3. 说明书直接用现有文档改写（去掉型号、照片、实测尺寸），**不要用 AI 生成的水文**；
4. 先做**脱敏脚本**跑一遍，人工再核对一遍"型号/尺寸/客户名"三个关键词；
5. **保留开发过程证据**：版本演进说明、判据报告时间线（若之后装了 git，提交历史是最好的证据）；
6. 拿不准就找代理（几百元），他们天天办这个，补正率能明显降低。

### 7.6 结论

**软件著作权属于"只要你真写了软件、材料做规范，基本都能过"的那一类。**
我们项目的难点不在"能不能过"，而在**脱敏**和**归属确认**这两件事上 ——
这两件办妥，剩下就是走流程。
