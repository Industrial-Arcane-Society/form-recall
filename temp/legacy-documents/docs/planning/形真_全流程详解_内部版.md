## 第 0 章 三分钟看懂这个项目

### 0.1 一句话

**一句中文话，换一个能在 CATIA 上机的真实零件模型 —— 而且能拿出数字证明"像不像"。**

### 0.2 三句话

1. **别人让 AI"想象"零件，我们让 AI"照着真零件复刻"。**
   几何数据全部来自真实零件的实测文件（CATIA 导出的 STEP），不是模型凭空生成的。
2. **复刻完必须考试。** 我们有两把尺子：几何相似度（孔位/孔径/外形，现在 **99.8%**）、
   图像相似度（和真实照片比长相，现在 **84.5%**）。
3. **考试不及格不许过关。** 每次改动都自动跑全套考试，任何一项退步就**回滚**（这叫"门禁"）。

### 0.3 一个比喻（讲 PPT 时最好用）

> 我们给每个零件办了一张**"几何身份证"**：上面记着它真实的长宽、每个孔的直径和位置。
> AI 拿着这张身份证把零件"复刻"出来，复刻完还要过一道**"人脸识别"**——
> 把复刻出来的零件和真实零件摆在一起比，打分，不到 95 分就要回去重做。

## 第 1 章 背景：为什么会有这个项目

### 1.1 行业现状（东莞最典型）

* 东莞的 3C、五金、模具、夹具工装行业，特点是**非标件多、批量小、交期紧**：
  一套夹具里可能有几十个零件，每个都不一样，很多只做一两件。
* 这类零件的三维建模，现在几乎全靠**设计员在 CATIA / SolidWorks 里手工画**：
  * 一个中等复杂度的零件 **1~4 小时**；
  * 新手要更久，而且画出来**和老师傅不一样**（尺寸习惯、细节处理都不同）；
  * 越急越容易出错，改一个尺寸要重新推一遍。
* 结果：**设计环节成了交期的瓶颈**，而且严重依赖少数几个老师傅。

### 1.2 现在市面上的"AI 建模"为什么不顶用

| 常见做法 | 问题 |
|---|---|
| 让大模型直接"生成"几何 | 尺寸靠猜 → 装不上、做不出来 → 工厂不敢用 |
| 生成"看起来像"的三维图片/网格 | 好看但**不能加工**，没有精确的孔位与配合面 |
| 用扫描仪逆向（点云重建） | 需要额外设备、现场扫件，且得到的是三角面片，不是可编辑的特征模型 |
| 通用参数化模板 | 只覆盖标准件，非标件一多就废 |

**我们的切入点**：不猜尺寸，**用真实零件的实测数据**去复刻，并且**给出可复核的相似度数字**。

### 1.3 比赛定位（写项目书时要贴住）

比赛强调 **"真实场景、真实数据、真实需求"**，赛道是**开放创新**。我们三条全部对得上：

| 比赛要求 | 我们的对应 |
|---|---|
| 真实场景 | 东莞工厂的夹具/工装/非标件建模，一线真实工序 |
| 真实数据 | **518 个真实零件的 CATIA 文件**，导出的 521 个 STEP、量出的 518 套真实几何 |
| 真实需求 | 设计员手工建模慢、结果不一致、依赖老师傅 |
| 开放创新 | 自研几何内核 + 自建判据闭环 + 对接 CATIA，不是套壳调用现成大模型 |

## 第 2 章 我们解决的问题（用痛点说话）

| 痛点 | 量化 | 我们的改法 |
|---|---|---|
| 手工建模慢 | 1~4 小时/件 | 一句话触发，几十秒出模型 |
| 结果不一致 | 换人换结果 | 同一句话 → 同一套参数 → 同一个结果 |
| 靠老师傅 | 人走断档 | 把经验固化成"型号 → 真实几何"档案库 |
| AI 生成不可信 | 尺寸靠猜 | 几何全部来自实测，且**每一件都打分** |
| 改完不知道有没有变差 | 靠感觉 | 门禁 + 全量回归，退步就回滚 |

## 第 3 章 核心思想：三个关键词

### 3.1 真 —— 数据是真的

* 所有几何来自**真实零件的实测文件**（CATIA 导出 STEP）；
* 每个圆孔的**直径、轴线、位置、深度**都是从文件里一个个量出来的；
* 外轮廓也是真的：**含内部的型腔、加强筋、台阶**（不是拿一个方块糊弄 —— 这一点我们吃过教训，见 7.3）；
* 标准件（螺栓等）按 **ISO / GB 国家标准**计算。

### 3.2 判据 —— 好坏是可量化的

"像不像"不能靠感觉。我们定义了两把尺子（第 4.6、4.7 节详解）：

| 尺子 | 量什么 | 现在的分数 |
|---|---|---|
| **几何相似度** | 孔位、孔径、轴线、外形包络对不对 | **99.8%**（498/502 件 ≥95%） |
| **图像相似度** | 从同一角度看，和**真实照片**长得像不像 | **84.5%** |

### 3.3 闭环 —— 会自己纠错

模型建完自动考试 → 不及格 → 定位到"哪一类问题" → 改建模逻辑 → **全量重跑** →
变差就回滚。这套循环就是所谓**工作流**（第 4.8 节解释）。

## 第 4 章 运行原理详解（一步一步讲）

> 这一章是全文最核心的部分。每一小节的结构都是：**干什么 → 怎么干 → 为什么这么干 → 现在什么水平**。

### 4.1 第一步：真身数据从哪来

**干什么**：把工厂里的 518 个 CATIA 零件，一个个导出成"通用几何文件"。

**怎么干**：用 CATIA 的批处理脚本（`启动脚本/导出真实几何_双击运行.vbs`）自动打开每个零件、导出成 **STEP** 格式。

**为什么**：STEP 是几何界的"PDF"——任何三维软件都能读，而且是**精确的数学描述**（不是照片、不是网格）。有了它，后面才能量尺寸。

**打个比方**：这一步相当于给 518 个零件**做了 518 份"体检报告"**，报告里写着每个零件真实的尺寸与形状。

**现状**：521 个 STEP（有 3 个源文件本身是空零件，我们如实记着）。

---

### 4.2 第二步：建"真身档案库"

**干什么**：把 STEP 里的信息量出来，整理成"按型号就能查"的档案库。

**怎么干**（两件事）：

1. **量特征**：解析每个 STEP，提取所有**圆柱面** → 得到每个孔的 `直径 / 轴向 / 位置 / 起止`；
   再量出零件的**三维包络**（长宽高）。
2. **存网格**：用工业级几何库（OpenCASCADE）把零件读进来，转成**紧凑的三角面数据**存起来 ——
   这就是"零件的真实外形"，连型腔、加强筋都在里面。

**为什么这么做**：
* 光有长宽高不够（那就成了"方块 + 几个孔"，我们吃过这个亏）；
* 存成网格后，任何下游（渲染、比对、导出）都能直接用，**不用重新解析**。

**现状**：518 个零件的真实网格（约 120 MB）、521 套特征数据，都带索引，可复核。

---

### 4.3 第三步：怎么"听懂人话"

**干什么**：把用户的一句中文，翻译成机器能执行的"要建什么"。

**怎么干**：分三层理解
1. **零件族**：这是螺栓？型材？支座？还是法兰？（不同族有不同造法）
2. **型号/规格**：例如 `KMS-M05-010-100-D`、`EGT001 SW80x088`、`M5x16`；
3. **参数**：直径、长度、厚度、孔数、分度圆…… 缺的参数按"标准值/典型值"补上。

**为什么**：用户不会按计算机的格式说话。这一步做不好，后面全错。

**我们额外做了一件诚实的事**：凡是**没有明说、由程序补的参数**，都会在界面上标注
"这些参数没写，已按典型值代入"，不让用户以为是我们量出来的。

---

### 4.4 第四步：查档案（有就有，没有就说没有）

**干什么**：拿型号去真身档案库查真实数据。

**怎么干**：
* **查得到** → 直接用实测数据（孔位、外轮廓、型腔全都用真的）；
* **查不到** → 退回两条路：① 标准件按国标公式算；② 通用件按"包络 + 典型孔"建，
  并在特征名里**写明"这是估的"**。

**为什么**：宁可少建，绝不编造。这是工厂能信任我们的前提。

---

### 4.5 第五步：动手建模（我们有三把工具）

同样是"建一个零件"，我们准备了三条造法，程序会**自动挑最合适的**：

| 造法 | 原理（大白话） | 用在哪 | 实测成绩 |
|---|---|---|---|
| **参数化** | **像填空**：按标准公式把尺寸算出来，再生成几何 | 标准件（内六角螺栓、垫圈…） | 螺栓 54 个型号复现度 **100%** |
| **直写网格** | **一次成型**：一根长料 + 几百个孔，不用一刀刀切，直接算出带孔的表面 | 型材（EGT 型材，最长 4078 mm） | **545 个孔 0.5 秒**建完，体积误差 0.36% |
| **布尔运算** | **像雕刻**：先有一块料，再把要挖的地方"减掉" | 一般机加件（支座、阀岛、连接件…） | 49 个孔一次算完 **0.05 秒**（旧方法 27 秒，快约 500 倍） |

**为什么要有三条**：零件形态差异太大 —— 用错工具，要么慢，要么不准。

**这里有一段值得写进项目书的技术故事**：
我们的布尔运算（"雕刻"）原来每切一刀都要把**整个零件**重算一遍，孔一多就崩
（192 个孔时体积误差 2%）。后来改成了"**只碰刀口附近的那几块面**"（专业叫局部化/剪枝），
不仅快了 500 倍，**还顺手查出一个隐藏很久的错**：旧方法对"刀比零件长"的孔（也就是所有通孔）
会**多切** —— 实测方形块打一个通孔，体积多切 4.72%，圆管甚至多切 94.7%。
这个问题以前一直没被发现，因为**外形尺寸看起来是对的**。现在我们用"和独立算出来的体积对比"
把它锁死了（10 个用例全过）。

---

### 4.6 第六步：几何判据怎么打分（第一把尺子）

**干什么**：模型建完，立刻和真身档案比，算一个 0~100 的分。

**怎么干**（用大白话讲清三个概念）：

* **召回率（有没有漏）**：真实零件上有 13 个孔，模型里建出了几个？
* **精确率（有没有编）**：模型里的 13 个孔，真实零件上都有吗？（**编造出来的孔也要扣分**）
* **综合分**：两个比例都不高，分就低。位置允许差 0.5 毫米、直径允许差 0.2 毫米。

**为什么这么设计**：只查"漏没漏"不够 —— 有的做法为了凑数**乱加孔**，看起来"建全了"，
实际装不上。两个方向都查，才叫公平。

**现状**：平均 **99.8%**，498/502 件达到 95% 以上；没达标的 4 件都是**源文件本身有问题**
（用装配体导出的 STEP，包围盒被远处参考几何污染了），我们如实标着。

---

### 4.7 第七步：图像判据怎么打分（第二把尺子，也是最像"人眼"的）

**干什么**：把模型**渲染成一张图**，和真实零件的**照片**摆在一起比"长得像不像"。

**为什么需要第二把尺子**：几何判据只量"孔对不对、包络对不对"，
**量不到外轮廓的细节**（型腔、加强筋、台阶这些）。我们就是被第二把尺子抓出来的
（见 7.3 的"方块事件"）。

**怎么干**（这一步我们踩坑最多，讲清楚很有说服力）：

1. **让两边都可比**：
   * 模型这边：渲染时把背景涂成**特殊颜色**，于是轮廓是**精确**的（不用猜边界）；
   * 真实那边：每个零件**拍两张**——一张正常、一张把零件**隐藏**掉（相机不动），
     两张相减 = **零件的精确轮廓**。截图上的工具栏、背景、杂点全部抵消掉了。
2. **对齐**：真实照片和渲染图的大小、位置不可能完全一样，先自动对齐
   （允许旋转 ±12°、平移若干像素，尺度用几何关系先锁住）。
3. **打分**：算两个数
   * **重叠率（IoU）**：两个轮廓重叠的面积占比；
   * **边缘贴合度**：轮廓线离得远不远。
   * 最后综合成一个 0~100 的相似度。
4. **一个公平性修正**：两张图是**各自独立产生**的（一个渲染、一个截图），
   边缘差 1 个像素不该算"形状不同"，所以用 **1 像素容差**；同时把严格的数也一并记录，两个都写在报告里。

**现状**：平均 **84.5%**（中位数 87.8%，最好的 96.1%）。
* 最早是 62.1% → 换上真实外形 71.7% → 加"视向拟合"73.1% → 加容差口径 **84.5%**；
* 中途发现最大误差来源不是模型，而是**照片的相机角度**：支座那一族仅仅把相机对齐，
  就从 51% 跳到 **94%**（模型一个字没改）。

### 4.8 第八步：闭环与门禁（这就是"工作流"）

**先解释"工作流"是什么**（队友一定要懂这个概念）：

> 工作流 = **把多道工序串成一条流水线，每一步都有明确的输入输出、可以单独重跑、可以回滚**。
>
> 和"问一次答一次"的区别：

| | 单次问答 | 工作流 |
|---|---|---|
| 执行 | 一次调用，成不成都在这一次 | 多步串行，每步可单独重跑 |
| 中间产物 | 不保留 | 每步留证据（模型/图片/分数/日志） |
| 出错 | 整体失败 | 定位到具体哪一步 |
| 质量 | 靠人看 | **门禁**：不达标不许往下走 |
| 复用 | 每次重来 | 步骤可复用、可批量化、可上云 |

**我们的工作流有 11 个环节**（画成流程图就是这个项目的"运行原理图"）：
导出真实几何 → 建真身档案 → 模型侧接入 → 出渲染轮廓 → 出真实轮廓 →
两道门禁 → 相似度比对 → 视向拟合 → 低于 95% 清单与归因 → 硬判据回归 → 产出留痕。

**三道门禁（写创新点时用）**：

| 门禁 | 内容 | 现在的及格线 |
|---|---|---|
| ① 数据门禁 | 照片对是否可用（两帧背景是否一致、轮廓占比是否合理），不可用就**如实标"不可比"**，不硬算 | 本批 150 件被判不可用（多为小零件） |
| ② 判据门禁 | 几何/图像相似度不到 95% 就进"待修清单" | 几何 498/502 已达标 |
| ③ 回归门禁 | 任何改动跑全量回归，**任何一项退步就回滚** | 自检 47/47、CATIA 523/523、孔位 267/267 |

### 4.9 云端训练：让系统"越用越准"

**先澄清一个容易误解的点**：这里的"训练"**不是**从头训一个三维生成大模型（那要百万级 CAD 数据），
而是四件很实在的事：

| # | 做什么 | 为什么有效 | 靠什么算力 |
|---|---|---|---|
| 1 | **数据飞轮**：自动出题（提示词变体）→ 批量建模 → 自动打分 → 把失败案例聚类 | 直接抬高命中率 | 多核 CPU |
| 2 | **参数寻优**：对每个零件族的建模参数做自动搜索，让它对齐实测数据 | 每个族都能逼近满分 | 多核 CPU |
| 3 | **外轮廓重建**：把真实 B-Rep 里的型腔/加强筋/台阶复刻出来 | 图像相似度唯一的突破口 | CPU 为主 |
| 4 | **小模型微调**（可选）：把"提示词 → 参数"用我们自己的 1828 条数据再教一遍 | 说话更随便也能听懂 | GPU（24 GB 显存起步） |

**7×24 小时怎么跑**：每天固定时间拉取最新代码 → 全量跑一遍判据 → 出趋势报告 →
自动挑出"退步的零件"和"最差的一批" → 自动寻优/生成修复候选 → 人审核后合并。
这套就是**工作流搬到云上**，也是我们后面要做的重点。

## 第 5 章 一个完整例子走一遍（讲 PPT 时用这个）

### 例子 A：`内六角螺栓 M5x16`（标准件，走"填空"）

| 步骤 | 发生什么 |
|---|---|
| ① 听懂 | 识别为"内六角螺钉"族，型号 M5x16（M5 = 螺纹直径 5 mm，16 = 螺杆长 16 mm） |
| ② 查档 | 标准件库里有这个型号：头径、头高、对边、弹垫/平垫尺寸都按 ISO 4762 / GB/T 97.1 查表 |
| ③ 建模 | 参数化：圆柱杆 + 六角头 + 内六角孔 + 弹垫 + 平垫 |
| ④ 打分 | 几何相似度 **100%**（六角孔的切除体积与国标公式算出来的完全一致） |
| ⑤ 上图 | 推进 CATIA；同时出图与实拍对比 |

### 例子 B：`EGT型材 EGT001 SW80x088`（型材，走"一次成型"）

| 步骤 | 发生什么 |
|---|---|
| ① 听懂 | 识别为"EGT 型材"族，型号 EGT001 SW80x088（截面 80×80，长 88） |
| ② 查档 | 档案库里有它的真实几何：13 个实测孔（1 个 ⌀26 + 12 个 ⌀11），还有**内部型腔** |
| ③ 建模 | 优先"复刻真实外形"（含型腔）；同时保留一条备用造法（等截面 + 全部实测孔） |
| ④ 打分 | 几何 **100%**；图像相似度约 88%（型材是细长条，对像素级边缘很敏感） |

## 第 6 章 技术家底（写"技术先进性"时挑着用）

### 6.1 自研几何内核（不用第三方 CAD 内核也能算）

* 我们自己写了一套几何布尔运算内核（并集/差集/交集），不依赖商业内核；
* 2026 年这一轮做了两件关键优化：
  1. **局部化**：只碰刀口附近的面（不是每次都全模型重算）；
  2. **双重剪枝 + 共面处理**：用包围盒筛掉"离得远"的面，并解决"面和刀正好贴平"这类边界情况。
* 效果：49 个孔一次算完 0.05 秒（原来 27 秒）；精度也更高（体积误差 0.08%，那还是"真圆 vs 用多边形近似"的差别）。

### 6.2 可选接入工业级内核（OpenCASCADE）

* 装上开源工业内核后，多孔复杂件更快更准；**没装也能跑**（自动回退到自研内核）；
* 用它还能直接导出**标准 STEP 文件**，在 CATIA 里以实体形式打开。

### 6.3 直连 CATIA（不只是"生成图片"）

* 生成的不只是三维图片，而是**可以直接推进 CATIA 的特征与模型**；
* 通道上解决了几个只有真机才会遇到的问题，例如：
  * **坐标轴映射**：CATIA 的草图平面（PlaneZX 之类）两个坐标轴顺序与我们的数据不一致，
    不换算的话孔会**沿对角线镜像**（我们专门写了一个检查：把导出的孔位反算回零件坐标，
    和实测逐孔比对，74601 个孔全部对上）；
  * **零深特征保护**：一个"深度为 0"的槽会让 CATIA 整个零件进入报错状态，
    后续所有特征全部失败（这是现场事故，我们加了双端防护）；
  * **双通道**：能用特征表达的走特征表；自由曲面件改走 STEP 导入 —— 不假装能建。

### 6.4 判据工程（让数字可信）

* **负对照**：图像判据上线前，我们先测"故意配错的照片"能不能被识破 ——
  早期版本"真配对 85.3% / 错配对 84.1%"，只差 1.2 个点（**没有区分能力**），
  于是**推翻重做**，才有了现在的双帧差分方案；
* **独立验证**：布尔运算的正确性不是"自己跟自己比"，是和**独立算出来的体积**比；
* **口径写清**：每个数字都注明了容差、样本数、失败原因，报告里连"多少件没法比"都写在明面上。

## 第 7 章 现在的成绩，与诚实的不足

### 7.1 成绩（都能复核）

| 指标 | 数字 | 怎么量的 |
|---|---|---|
| 真实零件入库 | **521 个 STEP / 518 套真实几何** | 从 518 个 CATIA 零件导出并解析 |
| 提示词数据 | **1828 条**（训练 1453 / 测试 375 / 负例 12） | 自动生成 + 自检每条都能解析 |
| **几何相似度** | **平均 99.8%，498/502 件 ≥95%** | 与实测 STEP 的孔特征逐项比（位置 ±0.5 mm、直径 ±0.2 mm） |

| 布尔运算 | 49 孔 **0.05 秒**（旧 27 秒） | 与独立体积对照（10/10 通过） |
| 自检 | **47/47** | 内核/解析/MCP/CATIA/界面全链路 |

### 7.2 不足（写项目书时要主动说，显得可信）

| 不足 | 现状 | 计划 |
|---|---|---|
| 图像相似度还没到 95% | 84.5% | 主要是**照片侧**的问题（相机角度、小零件对比度），见下 |
| 150 件照片"不可比" | 多为小零件（隐藏前后差异被界面噪声淹没） | 改拍摄协议：三帧拍摄 + 用"高亮选中"代替"隐藏" |
| 部分零件源数据本身就坏 | 4 件（装配体导出的 STEP，包围盒被远处参考几何污染） | 换成单件导出；这几件我们如实标着"不达标" |
| 库里没有的新零件 | 走标准/典型值兜底 | 扩大档案库；参数寻优自动逼近 |

### 7.3 一个必须讲的故事："方块事件"（最能体现我们的诚实）

**背景**：早期我们的几何判据一直显示 91.9%（很高），但用户反馈"除了螺丝，别的零件只有大体形状"。

**原因**：非标件当时是用"**包围盒 + 几个孔**"建的 —— 也就是说，
一个 L 形支座，我们建出来是**一个方块**。而几何判据只量"孔对不对、长宽高对不对"，
**量不到外轮廓**，所以一直给高分。

**怎么发现的**：我们上线了第二把尺子（图像相似度）—— 它一眼就看出来了：
模型是方块，真实是 L 形，相似度只有 62%。

**怎么修的**：把真实零件的**实测外形（含型腔、加强筋、台阶）**直接作为模型几何，
几何判据同时从 91.9% 提到 **99.8%**。

> **这个故事写进 PPT 极有说服力**：说明我们不只是"能建模"，而是**知道自己的模型准不准**，
> 并且**愿意推翻自己**。

## 第 11 章 常见问题 Q&A（答辩用）

**Q1：这不就是调个大模型 API 吗？**
不是。大模型只负责"听懂人话"这一小步；几何是自研内核算的，数据是实测的，
判断标准是我们自己定义的，CATIA 通道也是自己打通的。

**Q2：AI 生成的模型敢直接加工吗？**
模型不是"生成"的是"复刻"的：孔位、孔径、外轮廓都来自实测数据，
而且每件都有相似度分数。分数低的会进"待修清单"，不会默默通过。

**Q3：你们和扫描仪逆向有什么区别？**
扫描仪需要设备和现场扫件，得到的是三角面片；我们是**用现成的零件文件**（STEP）
复刻出**可编辑、可加工、可推进 CATIA** 的模型。

**Q4：怎么保证不会越改越差？**
三道门禁 + 全量回归。每次改动跑全套判据，任何一项退步就回滚（这是硬规则）。

**Q5：你们的数据从哪来？合法吗？**
来自本项目合作方提供的 518 个零件文件，仅用于建模与验收；
我们的仓库是**私密**的，对外材料里不含客户型号与尺寸。

**Q6：为什么图像相似度只有 84.5%？**
因为它是**最严格**的一把尺子 —— 把"相机角度、照片噪声、像素级边缘"都算进去了。
我们已经证明：只要把相机角度对齐，同一批零件能从 51% 提到 94%，
说明剩下的差距主要在**测量侧**，不在模型侧。

**Q7：多久能落地？**
CATIA 通道已经能用（523/523 型号可推送），本地部署即可试用；
云端闭环是下一阶段。

**Q8：只能做夹具零件吗？**
不止。只要有零件文件（STEP）就能建库复刻；标准件走国标；参数化件（法兰、轴等）本来就能直接建。

## 第 12 章 名词小抄（写 PPT 时直接换词）

| 专业词 | 大白话 |
|---|---|
| STEP | 三维模型的通用交换格式，相当于"几何的 PDF" |
| CATIA | 汽车/航空/夹具行业最常用的三维设计软件（我们直接对接） |
| B-Rep | 用"面和边界"精确描述实体的方式（比一堆三角面更精确） |
| 三角面/网格 | 用很多小三角形拼出形状，适合显示，不适合精确加工 |
| 布尔运算 | 把两个实体加/减/交（打孔、挖槽就是"减"） |
| 相似度 / IoU | 两个形状重叠的比例，越高越像 |
| 召回率 | 该有的有没有漏（真实的孔，模型建出来了吗） |
| 精确率 | 有没有多编（模型里的孔，真实零件上有吗） |
| 判据 | 打分规则：拿什么标准判断"像不像、对不对" |
| 门禁 | 及格线：不达标不许往下走 |
| 工作流 | 把多道工序串成流水线，每步可查、可重跑、可回滚 |
| 回归测试 | 改完之后把**全部**用例重跑一遍，看有没有变差 |
| 微调 | 拿自己的数据再教一遍已经会说话的大模型，让它更懂行话 |
| 实测数据 | 从真实零件的三维文件里量出来的尺寸（不是估的、不是猜的） |
| 视向 | 相机从哪个角度看零件（角度不同，看到的轮廓不同） |
| 掩码 | 把零件从背景里"抠"出来的黑白图，用来比形状 |
