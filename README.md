# AI 自动建模助手

> 用一句中文描述，直接生成可用的三维模型 —— 内置几何内核、三维预览、STL 导出，
> 并能作为 MCP 服务端让 AI 客户端直接调用建模工具。

> 当前版本 **v1.3.0**：**带轮按国家标准生成真实轮槽**（GB/T 10412—2002 / GB/T 10413—2002；
> 同步带轮按 GB/T 11361 / JB/T 7512.2 标准节距生成真实轮齿），零件库 **41 类**
> （含曲轴 / 凸轮轴 / 斜齿轮 / 锥齿轮 / 叶轮 / 活塞 / 连杆 / 万向节 / 涡旋盘 / 三角转子等高难度件），
> 自带**纯标准库三维渲染器**可一键截图；每次生成都会给出 **「提示词 → 生成特征」对照表**
> （说明这句话建出了什么、依据哪条标准）。变更详情见 `使用说明.md` 的「版本变化」。

## 一、快速开始

1. 双击桌面上的 **「AI 自动建模助手」** 快捷方式（或双击文件夹里的
   `启动 AI自动建模助手.vbs`）。构建过 Tauri 桌面程序后，入口会启动新的三栏工作区。
2. 在左侧对话区用中文描述零件，例如：

   ```
   画一个 120×80×15 的长方体, 四角圆角 R8, 中心打一个直径 20 的通孔
   ```

3. 按 `Enter` 发送（`Shift+Enter` 换行），中间三维视口显示模型；Agent 模式还支持粘贴或选择参考图片。
4. 在右侧特征树选中项目后编辑参数并重建；顶部工具栏和「更多」菜单提供工程保存、STL / OBJ / 报告 / CATIA 脚本导出、模型截图、设置和集成工具。

> **Windows 安装版包含 CPython 3.13、`ai_modeler/` Python 源码和完整运行源码**，不要求目标电脑预装 Python，也不依赖开发仓库目录。首次打开时可选官方 PyPI、清华或阿里云镜像，将运行依赖安装到当前 Windows 用户的数据目录；安装目录保持只读，初始安装包不携带体积较大的科学计算和 CAD 依赖。`python -m ai_modeler` 是开发仓库入口，会把当前解释器交给 Tauri；开发环境可用 `--legacy-ui` 回到 Tk 界面。

从源码构建 Windows 安装包，需要 Node.js、Rust 工具链，以及构建机上的 Python + pip。首次构建会下载经过 SHA-256 校验的官方 CPython 运行时和 pip 引导 wheel，并把源代码放进安装资源；Python 运行依赖在用户首次启动时按所选镜像安装。MSI 和 NSIS 安装包生成在 `ui-web/src-tauri/target/release/bundle/`：

```powershell
cd ui-web
npm install
npm run tauri:build
```

需要使用 Agent 创造模式时，再安装 Agent SDK 并配置模型：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/01_安装依赖.ps1
```

配置「工具 → AI 大模型设置」后，可在 Agent 对话中使用参考图建模。纯规则快速模式不需要 Agent SDK；需要图片识别、LLM 工具调用和联网搜索时，安装 `deepseek-harness-sdk==0.1.5rc1`。

## 四、作为 MCP 服务端（让 AI 直接建模）

本程序内置 **21 个 MCP 工具**，可被 Claude、Codex、dsh 等支持 MCP 的 AI 客户端直接调用。

在界面上点 **「工具 → MCP 服务配置」**，复制那段 JSON 粘贴到客户端的 MCP 配置里即可：

```json
{
  "mcpServers": {
    "ai-modeler": {
      "command": "C:\...\python.exe",
      "args": ["C:\...\ai_modeler\mcp_server.py"],
      "cwd": "C:\...\ai自动建模插件"
    }
  }
}
```

工具一览（部分）：

`build_from_text`（自然语言建模）、`add_box`、`add_cylinder`、`add_sphere`、
`add_gear`、`add_prism`、`add_hole`、`add_pocket`、
`add_fillet`、`add_chamfer`、`add_pattern_linear`、`add_pattern_circular`、
`cut_box`、`get_feature_tree`、`get_stats`、`set_feature_param`、
`delete_feature`、`export_model`、`load_project`、`clear_model`、`list_examples`

命令行也可以直接启动：

```bash
python -m ai_modeler --mcp-config     # 打印 MCP 客户端配置
python -m ai_modeler --mcp            # 以 stdio 方式运行 MCP 服务
```

## 六点五、联网搜索与本地大模型

### 联网搜索（内置，不需要 Key）

本地规则引擎不认识的说法（例如 **M8 内六角螺栓**、**6204 轴承**、**4040 铝型材**），
程序会自动去 Bing 检索 → 过滤掉不相关结果 → 打开详情页抠出尺寸参数 →
给出**一条建议描述**，你确认后才建模。开关在 **工具 → 联网搜索设置**，关掉即完全离线。

- 实现：@@ai_modeler/online.py@@（标准库 urllib，无第三方依赖）
- 相关性过滤：中文二元词命中才算相关，避免「M8 螺栓」搜出「问界 M8 汽车」
- 型号规则：M8→公称直径 8；6204 轴承→内径 04×5=20mm；型材 4040→截面 40×40

### 本地 DeepSeek（可选，一键装）

双击 **安装本地DeepSeek.bat**，或者程序里 **工具 → 安装 / 管理本地 DeepSeek…**

- 免管理员、免安装，全部放在 @@local_ai/@@ 里，删目录即卸载
- 针对国内网络适配：引擎走 GitHub 加速镜像，模型走 hf-mirror 国内镜像
  （实测 5.5 MB/s + 22 MB/s；官方源在国内基本不可用）
- 模型可选 1.5b / 7b / 8b（DeepSeek-R1-Distill 系列，Q4_K_M 量化）
- 装好后程序优先用它解析描述，失败自动回退到内置规则引擎

## 七、与 CATIA V5 的关系

> **CATIA 是达索系统的商业授权软件，必须自行购买或通过学校/单位申请正版授权，
> 本项目无法也不应代为安装。** 详细的正规获取途径见 `使用说明.md` 第八章。

本程序的建模能力由**内置几何内核**（BSP-CSG 布尔运算）提供，因此在没有 CATIA 的电脑上
也能完整建模、预览、导出 STL。

CATIA 装好之后，本程序**无需改动**即可接上去，提供两条通道：

### 通道 A：CATIA 宏插件（推荐）

`catia_plugin/AI自动建模助手.CATScript` 是一个真正的 CATIA 插件：

    CATIA 宏 ──调用──▶ Python 后端（中文 → 特征表）
             ◀─返回──  Unicode 特征表
    CATIA 宏 ──用 Sketch / Pad / Pocket / Shaft 重建模型

* 只使用 CATIA **最稳定的四个 API**，对每次切除**测量体积自动纠正方向**，不易因版本差异出错
* 安装：`安装CATIA插件.bat`（或 **工具 → 安装 / 修复 CATIA 插件**）
* 注册：CATIA → 工具 → 宏 → 宏… → 选 `AI自动建模助手.CATScript` → 运行

### 通道 B：导出 CATIA 自动化脚本

**文件 → 导出 CATIA 自动化脚本** 生成一个 `.py`，
在装有 CATIA + `pywin32` 的机器上直接运行，即可重建同一棵特征树并保存为 `.CATPart`。

特征表会**展开阵列**（不依赖版本相关的阵列 API），并逐条报告成功/失败。

### 通道 C：从助手**直接建到 CATIA**（推荐）

工具 → **推送到 CATIA V5…**（工具栏也有「推送 CATIA」按钮）：助手在 CATIA 里新建 Part 文档并
逐条重建特征，可顺手另存 `.CATPart`。走 Windows 自带的 `cscript` + COM，**不需要 pywin32**。

```bash
python -m ai_modeler --push "法兰 外径 160 厚 20 内径 60, 均布 6 个直径 12 的螺栓孔" --save 法兰.CATPart
```

> **验证范围说明（2026-09-17 更新）**：本机已装 **CATIA V5-6R2023 (B33)**，两条通道都已在真机跑通：
> 助手 `工具 → 推送到 CATIA V5…` 把「法兰」建出 **8/8 个特征**并另存 `.CATPart`；
> 宏侧同一份构建核心同样 **8/8**（`tools\test_catia_macro.py`）。
> 真机联调修掉了 4 个兼容问题（详见 `操作说明_CATIA连接版.md` 第十一章）：
> ① 宏必须是**纯 ASCII + CRLF**，CATIA 的 CATScript 加载器不接受 UTF-16/BOM（否则报 `无效字符 / ScriptingERR_1002`）；
> ② 中文版 CATIA 的零件几何体不能用 `Bodies.Item("PartBody")` 取，改用 `Part.MainBody`；
> ③ 偏移平面上的草图必须先 `OpenEdition`；
> ④ 往 HybridBody 加偏移平面后需把 `Part.InWorkObject` 切回实体 Body，否则 Pad/Pocket 全部失败。
> 另外 `SaveAs` 遇到中文路径会卡死，已改为"先存 ASCII 临时路径再搬文件"。
> 离线部分仍然全绿：`tools/test_catia_bridge.py` 5/5、`python -m ai_modeler --selftest` 34/34。
>
> **几何级校验（2026-09-17 补充）**：只看"操作数对不对"是不够的 —— CATIA 里"凸台朝 +Z 长、
> 凹槽朝 −Z 切"，切除草图一旦放在材料下方就会**空切**：日志全成功、操作数也对，模型上却没有孔。
> 所以现在把**量几何**固定成流程：`tools\check_catia_solid.py` 让 CATIA 导出 STL，逐个孔检查
> "孔壁环"（绕孔心、半径≈孔半径、沿 z 有高度）。真机 6 例全过（齿轮/法兰/四角孔/凹槽/带轮毂齿轮/三角转子），
> 批量跑用 `tools\run_solid_sweep.py`；另有 `tools\audit_catia_export.py`（70 用例 0 失败）与
> `tools\check_catia_coverage.py`（39/41，剩 2 类是弹簧的已知限制）。
>
> 这一轮真机遍历还修掉了一个**几何错位**：三角转子的中心孔被放在**包围盒中心 (0, 5.32)**，
> 而它的真实轴心（质心）在 (0,0) —— 孔偏轴 5.3 mm。原因是导出器把"轴心"取成了包围盒中心
> （Reuleaux 三角形/凸轮的包围盒本来就不对称）。现在轴心一律取零件自身的 `center`。
> 同类修复还有：凹槽/键槽连写不再丢特征、同一个孔不再被切两遍（操作数虚高）。

## 九、常见问题

**Q：双击快捷方式没反应？**
用 `启动 AI自动建模助手(带控制台).bat` 启动，会显示具体错误信息。

**Q：提示未找到 Python？**
安装 Python 3.9+（<https://www.python.org/downloads/>），安装时勾选
*Add Python to PATH*，然后重新运行 `安装桌面快捷方式.bat`。

**Q：模型算得慢？**
特征越多、圆柱分段越多越慢（法兰、齿轮这类复杂件约 0.3–1 秒）。
可在右侧「参数」页把「圆周分段」调小（如 24）。

**Q：导出的 STL 能直接 3D 打印吗？**
可以。导出的 STL 是二进制标准格式，三角面片法向朝外。
唯一例外是「叶盘」的叶片采用了网格组合模式（不参与布尔运算），
各叶片之间以及与轮盘之间是相互重叠的独立壳体，切片软件通常能正常处理。

## 附：十四、复杂提示词的识别（本轮大修 + 100 条基准评测）

### 14.1 起因：一张图纸式长句被建成了完全不对的东西

用户输入一条液压缸缸筒的图纸式描述（外径 Ø25 / 内孔 Ø20 / 壁厚 2.5 / 法兰 Ø33×4 / 过渡圆角 R0.8），
结果建出一个 **160×160×20** 的大圆盘。查下来是三个叠在一起的老问题：

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | `Ø`（U+00D8）没被规范化，只有 `Φ/φ/∅/ø` 被认 | 「外径Ø25」整段读不到数字，零件库模板以为自己没拿到尺寸，**静默套用典型值**（法兰 160/20/内孔60） | 直径符号全部归一到 `⌀`（含 `Ø/Ф/ф/ϕ`） |
| 2 | `壁厚2.5` 被当成高度 | 「厚」这个别名命中了「壁厚」里的"厚" | 提取时排除 `壁厚`，并新增"壁厚 + 外径/内径 → 推另一个" |
| 3 | 长句里参数分散在多段，模板只用第一段 | 「缸筒 总长180, 筒体外径Ø63 内孔Ø50」的第一段只有总长 | 新增"把紧跟其后的纯尺寸段并进零件"的合并逻辑 |

还顺手修掉一批**用户看不出报错、但模型是错的**问题：

| # | 问题 | 说明 |
|---|---|---|
| 4 | 解析器**无限递归崩溃**（RecursionError） | 零件库摘出的"附加要求"又匹配到同一个零件名，自己调自己且永不缩小 → 加三重保险（深度上限 / 子句必须变短 / 同段不重复） |
| 5 | `内孔` 被当成"切除动作" | 于是**整个零件库被跳过**，联轴器/缸筒/垫圈全部退回通用规则建错 |
| 6 | 参数别名读不到就**静默套典型值** | 联轴器"长72"被套成 120、垫圈"内孔20.5"被套成 10 → 现在别名读不到会用**通用维度词兜底**，并由参数自己的中文别名决定语义（"轴孔直径"是内孔，不是外径） |
| 7 | 孔类参数**凭空套典型值** | 用户没写内孔时给法兰挖了个 Ø60 的洞 → 改为"绝不套"，缺孔就不挖 |
| 8 | 同一个孔被切两遍 | 零件库自带的孔 + 描述里又写了一遍 → 自动合并 |
| 9 | 「均布8个Ø14」位置式硬填 | 早先只要数字个数对得上就按顺序硬填，`法兰 Ø210×22` 把内径填成 210 → 位置式现在要求"后面**只有裸数字**" |
| 10 | 通用解析器不认 `铝板/钢板/箱体/凸台` | 新增这些关键词（凸台 = 圆柱） |
| 11 | 顺序描述不堆叠 | 「缸筒 Ø25/Ø20 长40, 端面法兰 Ø33 厚4」原本法兰陷在筒里，总高还是 40 → 现在默认**堆在前一个零件的顶面**（说了"同心/总长"则不堆） |
| 12 | 斜齿轮建模超时（20~36 秒，甚至 27 万面后放弃） | 内核按**直齿近似**（齿数/齿顶圆/中心孔都仍正确，CATIA 导出本来也是这么近似的） |
| 13 | 连杆"厚度"被算成大头外径 | 大头/小头改成**轴线沿 Z 的环**，厚度取"杆厚" |

### 14.2 交付了一套可复跑的评测基准（100 条提示词）

- 用例：`tools/bench/cases_A.json`（50 条）+ `tools/bench/cases_B.json`（50 条），
  覆盖基础体 / 板类 / 盘类 / 管件 / 箱体槽类 / 齿轮类 / 复合件 / 轴类标准件，
  其中约 38 条是**图纸式长句**（≥4 参数 + 多特征 + `Ø × ± °`）。期望值来自描述的工程意图。

- 相似度口径：`0.5*bbox + 0.4*holes + 0.1*pockets`

### 14.3 一个必须记下来的事故：`partlib.py` 被写坏又救回来了

本轮中途我用 PowerShell 的 `Get-Content/Set-Content` 去改 `ai_modeler\partlib.py`，
而这里的 PowerShell 是 **5.1**：读文件默认按 GBK 解码、写回又带 BOM，结果把整个
零件库文件变成了双重编码乱码（380 个字节被替换成 `?`，零件库静默失效）。

救回来的办法（已写成可复用的脚本思路）：

1. 乱码是"UTF-8 字节被按 GBK 解码"造成的 → 用 `gb18030` 编码回字节再按 UTF-8 解码即可逆；
2. 被 `?` 顶掉的字符，用**损坏前的 `.pyc`**（`__pycache__\partlib.cpython-314.pyc`）当基准：
   `.pyc` 的字节码是完好的，可以 `SourcelessFileLoader` 直接导入，于是 41 类零件的
   别名/参数/注释全部**精确取回**，再用它重排表区；
3. ASCII 部分（字典结构、`build=`/`bbox=` 表达式）本来就没坏，直接用；
4. 最后做**等价性验证**：新旧模块的 PARTS/MEDIUM/HARD/TYPICAL、CUT_WORDS/CUT_EXCEPT
   逐项比对 + 45 条典型参数的 bbox 行为对拍，全部一致才算过。

> **教训**：这个项目的源码一律用**文件工具或 Python** 读写，不要用 PowerShell 的
> 文本 cmdlet（PS 5.1 会按 ANSI 解码 UTF-8 源码）。

### 本轮抓到并修掉的 9 个真问题（都是"建出来不对"而不是"报错"）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **中心孔被真的切了 4~6 个** | 长句里「中心孔Ø30」和「分度圆Ø90 上均布6个Ø8」常被并成一段，判定时先看"有没有个数"，于是中心孔被标成"分度圆均布" | 孔位判定改成**先认"中心孔"**，再认分度圆均布；并让"分度圆/均布"修饰挂到**下一个**孔上（暂存 pending_pcd/pending_count） |
| 2 | 分度圆直径全成了默认 60 | 「分度圆Ø100 上均布8个Ø12」被切成两段，修饰先落到上一个中心孔上 | 同上：修饰只作用于**孔阵**，否则暂存给下一个孔 |
| 3 | 「外圆R3」被当成直径 3 | 抓直径时允许了 R 前缀（R3 是圆角半径） | 该分支只允许 ⌀ |
| 4 | 一个尺寸被填给多个参数（连杆小头外径=大头孔径=48） | 语义兜底把同一个"内径"分配给了 d/dh/dh2 | 一个测量值只能分配给一个参数 |
| 5 | 螺栓「M12×80」完全解析不出来 | 极对规则只认"外径×厚度"，没把 L（长度）算进去 | 极对的第二个数也允许填 L |
| 6 | 「顶面居中一个凸台」不堆叠，总高不对 | 「居中」被当成"不要堆叠"的指令 | 只有"同心/同轴/套在/穿过"才不堆叠 |
| 7 | 「回转底座 Ø160 高35」被做成回转体 | 零件名里带"回转"就触发了回转体分支 | 有 外径+高 且没有轮廓/回转动作词时按圆柱做；真回转体（回转体/车削/回转360度）不受影响 |
| 8 | 十字轴「四个轴颈相位90°均布」被再阵列一遍 | 复合件自带的结构被当成阵列动作 | 复合件 + 只有"相位/均布"字样时不再阵列 |
| 9 | 斜齿轮没中心孔时外形算错（齿宽45 → Z=85） | 用带**退化内环**的棱柱建外形，轮廓被算到界外 | 无孔时改用普通拉伸；有孔才用带内环的棱柱 |
| 10 | 「空心轴 … 总长140, 左端台阶Ø58长25」多出一个 Ø46×140 的圆柱 | 同句附加要求把"总长/台阶"等**零件自身参数**也当成了切除要求 | 附加短语在下一个参数名处截断 |
| 11 | 「四角Ø11通孔…顶面沉孔Ø18深6」只切了 1 个沉孔 | 沉孔没说位置时没有继承上一组孔 | 沉孔/沉台/扩孔继承上一组孔的位置与数量 |
