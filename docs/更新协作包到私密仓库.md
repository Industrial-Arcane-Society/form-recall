## 7. 五个必须知道的坑（都是我们真踩过的）

### 坑 1：改完 `.gitignore` 不等于"文件就进去了"

git 对待已忽略文件有两套逻辑，很多人在这里绕不出来：

* **情况 A（我们这次）**：`catia_export.py` **从来没进过仓库**（一直被忽略、从没 `git add` 成功过）。
  → 修好 `.gitignore` 后，重新 `git add -A` 它就进来了。**不需要别的动作**。
* **情况 B**：某文件曾经用 `git add -f` 强行提交过，现在想忽略它。
  → 光加忽略规则**没用**，git 会继续跟踪已入库的文件。必须：
  ```powershell
  git rm --cached 要忽略的文件
  git commit -m "chore: 停止跟踪 XXX"
  ```
* **记住一句话**：`.gitignore` 只对**未跟踪**文件生效；对**已在库**的文件一律无效。

### 坑 2：资源管理器看不见 `.gitignore` / `.github`

以 `.` 开头的文件在 Windows 资源管理器里默认隐藏，GitHub Desktop 的 Changed Files 里也会显示。
我们包里**必须有** `.gitignore`、`.gitattributes`、`.github/pull_request_template.md`、
`.github/workflows/acceptance.yml` 这 4 个隐藏文件 —— 少一个，
队友那边就没有 PR 模板和 CI，代码风格立刻散掉。

**怎么确认它们在包里**：


### 坑 3：大文件推不上去

* GitHub **单个文件上限 100 MB**（超过直接拒绝推送），仓库建议 <1 GB；
* 本包**最大文件 12.34 MB**（`kb/real_features.json`），离上限很远，安全；
* 真正的大数据（`_wheels/` 513 MB、`kb/real_brep*/` 180 MB、现场照片）**故意不进包**，
  原因和重建办法写在 `README.md` 第三节 与 `kb/README_数据说明.md`；
* 万一不小心把大文件提交了，**改一次再提交是删不掉的**（历史里还在），要么用 `git filter-repo`，要么干脆重建仓库——所以**提交前先看包体积**。

### 坑 4：脚本编码 —— 比缺文件更阴，双击就是"一闪而过"

这条是**这次重新打包时自己查出来的**，而且比缺文件更难发现：文件在、内容对，
但**编码不对，脚本根本跑不起来**。

| 文件类型 | 谁在跑它 | 必须是什么编码 | 不然会怎样 |
|---|---|---|---|
| `.ps1` | Windows PowerShell 5.1（双击 / `powershell -File`） | **UTF-8 with BOM** | 它按 GBK 读无 BOM 的 UTF-8 → 中文乱码 → **语法解析失败** |
| `.bat` / `.cmd` | cmd.exe（代码页 936） | **GBK(ANSI)** + CRLF | 中文提示全乱码，含中文路径就走错 |
| `.vbs` | Windows Script Host | **GBK(ANSI)** 或 UTF-16LE | 路径里的中文被读坏 → 脚本报"找不到文件" |

**实测证据**（用真正的 Windows PowerShell 5.1 解析器逐文件解析）：

```
=== 修之前 ===
[OK]          01_安装依赖.ps1
[PARSE-FAIL 2] 02_跑全流程.ps1      ← The string is missing the terminator: "  (line 38)
[PARSE-FAIL 4] 03_重建大数据.ps1     ← Missing closing '}' in statement block  (line 18)
[PARSE-FAIL 2] 04_验收基准.ps1      ← Missing closing '}' in statement block  (line 11)
[PARSE-FAIL 6] 05_打包协作包.ps1     ← Missing ')' in function parameter list  (line 17)

=== 修之后 ===
[OK] 01_安装依赖.ps1
[OK] 02_跑全流程.ps1
[OK] 03_重建大数据.ps1
[OK] 04_验收基准.ps1
[OK] 05_打包协作包.ps1
```

**也就是说：四个"一键脚本"里有三个本来是坏的**——队友双击 04 只会看到窗口一闪，
不会有人告诉他"是编码问题"。这类问题光看代码 review 是看不出来的。

**修法（已做成工具，幂等，可以反复跑）**：

```powershell
# 先看有没有问题
python tools\fix_script_encoding.py --dir <仓库目录> --check
# 再修（.ps1 加 BOM；.bat/.vbs 转 GBK；UTF-16 和纯 ASCII 的不动）
python tools\fix_script_encoding.py --dir <仓库目录>
```

`tools\check_share_pack.py` 现在把这条也当判据了（"脚本编码不对 = 0"），所以不会再悄悄退化。

> 顺带一个教训：**用编辑器/自动化工具改完 `.ps1` 后要确认 BOM 还在**。
> 有些工具（包括我们的某些脚本步骤）会把 BOM 吃掉，文件看起来一模一样，跑起来就报语法错误。

### 坑 5：换行符（CRLF / LF）—— 和编码是**两件**事，都要管

`.gitattributes` 管的是"进仓库时怎么存、检出到你机器上变成什么样"。原来的写法是：

```gitattributes
* text=auto eol=lf                       # ← 错：把 Windows 脚本也强制成 LF
*.py text working-tree-encoding=UTF-8    # ← 更错：见下
```

两个问题（第一次 `git add` 时 ~150 个文件刷了一屏 CRLF 警告，才发现）：

1. `eol=lf` 会把 `.ps1` / `.bat` / `.vbs` 也存成 LF —— 队友克隆出来就是**LF 的 .bat**，
   cmd 处理标签、`goto`、括号块时会出现很难查的怪问题；
2. **`working-tree-encoding=UTF-8` 是危险项**：它让 git 按 UTF-8 重新编码工作区文件，
   而我们的 `.bat` / `.vbs` 已经是 **GBK(ANSI)**（cmd 与 WSH 只认 GBK），
   这条会把中文彻底改坏 —— 等于把坑 4 的修复再推翻一次。

**改成的写法**（按文件类型逐条写死，不依赖每个人各自的 `core.autocrlf`）：

```gitattributes
* text=auto                 # 默认只判断是不是文本，不强制换行

*.ps1  text eol=crlf        # Windows 脚本必须 CRLF
*.bat  text eol=crlf
*.cmd  text eol=crlf
*.vbs  text eol=crlf
*.CATScript text eol=crlf

*.py   text eol=lf          # 源码/数据统一 LF
*.md   text eol=lf
*.json text eol=lf
*.jsonl text eol=lf
*.txt  text eol=lf

*.png *.jpg *.docx *.xlsx *.npz *.stp *.stl *.zip  binary   # 二进制绝不碰
```

**验证办法**（改完 `.gitattributes` 一定要重新规范化一次，否则已暂存的内容还是按老规则算的）：

```powershell
git add --renormalize -A     # 按新属性重新算一遍（只处理已跟踪文件）
git add -A                   # 新增文件要单独再来一次（renormalize 不管未跟踪文件，实测踩过）
git check-attr text eol -- scripts\01_安装依赖.ps1   # 应输出 eol: crlf
git status --short           # 应没有刷屏的 CRLF 警告
```

## 8. 常见报错对照表

| 报错 / 现象 | 原因 | 怎么办 |
|---|---|---|
| **「Add local repository」报 `... isn't a Git repository`** | 包是 zip 解出来的，**里面没有 `.git`**（故意不放） | 跑 `powershell -File scripts\06_初始化Git仓库.ps1`，再点 Add local repository |
| `ModuleNotFoundError: No module named 'ai_modeler.xxx'` | 该 `.py` 被 `.gitignore` 忽略了 | `git check-ignore -v <文件>` 查规则 → 把规则改窄（前加 `/`）→ 重新 `git add -A` |
| `FileNotFoundError: kb\xxx.json` | 运行时依赖的 kb 数据没进包 | 加进 `check_share_pack.py` 的 `MUST` 清单并补文件，重跑校验 |
| **脚本双击一闪而过 / `Missing closing '}'` / `The string is missing the terminator`** | `.ps1` 缺 UTF-8 BOM（PS 5.1 按 GBK 读） | `python tools\fix_script_encoding.py --dir <目录>` |
| **`.bat` 里中文变问号/乱码，路径走错** | `.bat` 存成了 UTF-8 | 同上工具，会转成 GBK(ANSI) |
| **`.vbs` 报"找不到文件"，但路径明明存在** | `.vbs` 存成了 UTF-8，WSH 按 ANSI 读中文路径 | 同上工具，会转成 GBK |
| 队友在 macOS/Linux 解压后**目录全没了、文件名字里带反斜杠** | zip 是用 `Compress-Archive` 打的（条目名是反斜杠） | 用 `python tools\make_share_zip.py` 重新打包 |
| **`git add` 时刷屏 `CRLF will be replaced by LF`** | `.gitattributes` 强制了 `eol=lf`，Windows 脚本也被卷进去 | 按坑 5 改成按类型写死，再 `git add --renormalize -A` + `git add -A` |
| `remote: Support for password authentication was removed` | 用了登录密码 | 改用 PAT（第 4.2 节） |
| `Updates were rejected because the remote contains work...` | 队友先推了东西 | `git pull --rebase` 再 `git push` |
| `fatal: not a git repository` | 在错误的目录执行 | `cd` 到协作包目录再执行 |
| GitHub Desktop 看不见某些文件 | 隐藏文件（`.` 开头）或已被忽略 | `Get-ChildItem -Force` 确认；`git check-ignore -v` 查规则 |
| 推送卡在 `Writing objects` 很久 | 包太大 / 网络慢 | 确认没把 `_wheels`、`real_brep` 提交进去 |
