# 夹具单元协同设计 · 五步 Workflow 接口契约

> 本文件是「新增 workflow 层」与「五步向导 UI」之间的唯一契约。两侧按此实现，互不改对方文件。
> 依据：《final 研制报告》第 3–7 章；案例页「一套气动夹紧单元的协同设计」。

## 0. 设计原则（来自研制报告，必须遵守）

1. **前置不满足不进下一步**：每阶段有显式 `enter` 校验，返回缺项清单。
2. **P01 固定点偏移锁死为 0**：任何阶段都不能改；只能改外围结构参数。
3. **参数一变，下游结论全部失效**：计划、检查、复核勾选都要作废（`invalidate_from`）。
4. **检查结论四分**：`pass / fail / not_run / not_applicable`，**不得合并成一个笼统绿灯**。
5. **模拟标记不可被人工勾选改写**：`simulated/cad_connected/real_cad_files_created` 是事实字段。
6. **不宣称未实现的能力**：未接 CATIA 时所有工具条目 `simulated=True`。
7. **检查未通过不得进入复核**（研制报告 5.2 / 6.2）：`can_enter(5)` 先跑
   `blocking_failures(project)`，有 `severity='block'` 的 `fail` 就阻断，缺项文案写成
   「检查未通过：<检查名>（<detail>）」。默认案例压臂间距 d=3<5 必须被拦，改到 L=75 才放行
   ——这条在自检和单测里都锁着。

## 1. 包结构

```
ai_modeler/workflow/
    __init__.py      # 对外导出：FixtureProject, STAGES, WorkflowEngine, 便捷函数
    models.py        # dataclass 数据模型 + 序列化
    stages.py        # 五阶段定义、状态机、失效传播
    rules.py         # 工程规则校验（含 d = L - 62 + 4s 演示公式）
    report.py        # 校核输出：单元记录 JSON / Markdown 摘要
```

`models.py` 只依赖标准库；`stages/rules/report` 依赖 `models`，不依赖 tkinter、不依赖 ai_modeler 其它包（便于单测）。

## 2. 数据模型（models.py）

全部 `@dataclass`，需提供 `to_dict()` / `from_dict()`，字段名即 JSON 键名（snake_case）。

```python
@dataclass
class InputFile:          # 工程输入资料
    key: str              # 'workpiece' | 'prp' | 'rules' | 'std_parts'
    label: str            # 中文名，如「工件数模」
    path: str = ''        # 可为空（表示缺失）
    required: bool = True
    version: str = ''     # 版本/日期字符串
    loaded: bool = False  # 是否已确认可用

@dataclass
class PrpPoint:           # 定位夹紧点
    pid: str              # 'P01'
    role: str             # 'primary' | 'assist'
    x: float; y: float; z: float
    nx: float = 0.0; ny: float = 0.0; nz: float = 1.0   # 夹紧方向
    offset: float = 0.0            # 偏移量 mm
    offset_locked: bool = False    # P01 必须 True
    offset_range: tuple = (0.0, 0.0)   # 可调范围 mm，primary 为 (0,0)

@dataclass
class RuleSpec:           # 工程规则条目
    rule_id: str          # 'R-GAP-01'
    title: str            # 「压臂最小间距」
    source: str           # 来源：企业标准 / 示例约定
    applies_to: str       # 适用对象：'clamp_unit'
    unit: str             # 'mm'
    method: str           # 'min' | 'max' | 'range' | 'formula'
    target: float = 0.0   # 阈值
    target_max: float = 0.0
    formula: str = ''     # method='formula' 时的表达式说明（人类可读）
    severity: str = 'block'   # 'block' | 'warn'
    confirmed: bool = False   # 是否经企业/设计师确认（未确认只能当示例）

@dataclass
class PartSpec:           # 单元部件
    key: str              # 'base_plate' | 'support' | 'contact_block' | 'clamp_arm' | 'cylinder' | 'pin' | 'screw'
    name: str             # 中文名
    category: str         # '自制件' | '外购件' | '标准件'
    params: dict          # 尺寸参数，见 §5 默认值
    spec: str = ''        # 型号

@dataclass
class JointSpec:          # 装配关系
    a: str; b: str        # 部件 key
    kind: str             # 'fix' | 'revolute' | 'prismatic' | 'contact'
    axis: str = ''        # 'X'|'Y'|'Z'
    travel: float = 0.0   # 行程 mm 或角度 deg

@dataclass
class CheckResult:        # 检查结论
    check_id: str
    title: str
    status: str           # 'pass' | 'fail' | 'not_run' | 'not_applicable'
    detail: str = ''
    value: float = 0.0
    limit: float = 0.0
    unit: str = 'mm'
    simulated: bool = True
    rule_id: str = ''
    stage: int = 0        # 产生该结论的阶段 1..5

@dataclass
class TraceEvent:         # 可追溯事件
    ts: str               # ISO 时间
    stage: int
    action: str           # 'enter'|'commit'|'param_change'|'invalidate'|'export'
    detail: str = ''
    revision: int = 0

@dataclass
class FixtureProject:
    unit_id: str = 'UN200'
    unit_name: str = '气动夹紧单元'
    case_note: str = ''            # 典型案例一句话
    inputs: list = field(default_factory=list)
    points: list = field(default_factory=list)
    rules: list = field(default_factory=list)
    parts: list = field(default_factory=list)
    joints: list = field(default_factory=list)
    checks: list = field(default_factory=list)
    history: list = field(default_factory=list)
    stage: int = 1                 # 当前阶段 1..5
    revision: int = 1
    # 事实字段：不得由 UI 勾选改写
    simulated: bool = True
    cad_connected: bool = False
    model_api_called: bool = False
    real_cad_files_created: bool = False
```

`FACT_KEYS = ('simulated','cad_connected','model_api_called','real_cad_files_created')`。

## 3. 状态机（stages.py）

```python
STAGES = [
  (1, '工程输入', '工件数模与定位基准'),
  (2, '单元规划', '结构布局与任务分解'),
  (3, '参数建模', '机加工件与接口构建'),
  (4, '关联装配', '标准件配置与机构联动'),
  (5, '校核输出', '几何记录与方案复核'),
]

def stage_meta(stage: int) -> dict          # {'index','name','subtitle','outputs':[...]}

class WorkflowEngine:
    def __init__(self, project: FixtureProject): ...
    @property
    def project(self) -> FixtureProject
    def can_enter(self, stage: int) -> tuple[bool, list[str]]
        """返回 (是否可进入, 缺项说明列表)。缺项必须具体，如
        '缺少必需资料：工件数模' / 'P01 偏移必须锁定为 0' / '压臂长度未设置'。"""
    def commit(self, stage: int) -> None
        """记录 commit 事件；校验不过则 raise WorkflowError(缺项)。"""
    def set_param(self, part_key: str, name: str, value: float) -> list[str]
        """改部件参数。若值非法 raise ValueError。
        成功后：revision += 1；stages.py::invalidate_from(stage_of(part))；
        返回被置为失效的检查项 title 列表。P01 锁定 → 禁止改 offset。"""
    def invalidate_from(self, stage: int) -> int
        """把所有 stage >= N 的 CheckResult 置为 'not_run'，撤回复核勾选，
        revision 不变（由 set_param 负责 +1），返回作废条数。"""
    def reset(self) -> None

class WorkflowError(Exception):
    def __init__(self, message: str, missing: list[str]): ...
```

## 4. 规则校验（rules.py）

```python
def evaluate(project: FixtureProject) -> list[CheckResult]
```
至少实现 5 条，`check_id` 前缀 `W-`：

| check_id | 条件 | pass 判据 |
|---|---|---|
| W-INPUT-01 | 必需资料齐全且 loaded | 缺项 → fail，detail 列缺项名 |
| W-P01-01 | P01.offset == 0 且 offset_locked | 否则 fail |
| W-ARM-01 | 演示公式 `d = L - 62 + 4s`，s=侧向1/上侧0，要求 d >= 5 | d < 5 → fail，并给出建议 L |
| W-P02-01 | P02.offset 在 offset_range 内 | 越界 → fail |
| W-PART-01 | 部件齐全且关键尺寸 > 0 | 缺件/零尺寸 → fail |
| W-ASSY-01 | 装配关系存在（revolute 压臂 + prismatic 气缸） | 缺 → not_run |
| W-MOTION-01 | 完整运动轨迹 | **恒为 not_run**（无真实运动仿真，禁止报通过） |
| W-MANUF-01 | 制造/强度校核 | **恒为 not_applicable** |

辅助函数：
```python
def arm_clearance(arm_length: float, layout: str) -> float   # layout='top'|'side'
def suggest_arm_length(layout: str, required: float) -> float
```

## 5. 默认案例（UN200，与图片/报告一致）

`build_demo_project() -> FixtureProject`（放在 `models.py` 或 `__init__.py`）：

- 基板 600×380×20，2 mm 钣金件
- 压臂长度 `L=65`，上侧布置，要求间距 5（默认 d=3 → **故意失败**，触发修正分支）
- 修正建议：L=75 → d=13
- P01 固定点偏移 0（锁定），P02 辅助点偏移 2，范围 [0,4]
- 气缸行程 0–65°，压臂开闭
- 部件：base_plate / support / contact_block / clamp_arm / cylinder / pin / screw

## 6. 校核输出（report.py）

```python
def unit_record(project) -> dict            # 完整可复核记录（含 facts、checks、history）
def summary_markdown(project) -> str        # 人读摘要：五阶段状态 + 检查四分统计
def export_unit_record(project, path) -> Path
def export_summary(project, path) -> Path
```

`unit_record` 必须包含：
- `schema`: `'fixture-unit/1'`
- `facts`: 四个事实字段原样
- `stages`: 每阶段 `{index,name,committed}`
- `checks`: 全量，含 status/simulated/rule_id/stage
- `counts`: `{'pass':n,'fail':n,'not_run':n,'not_applicable':n}`
- `revision`, `unit_id`, `points`, `parts`, `joints`, `history`
