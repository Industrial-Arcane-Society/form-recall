# 研究章程：多模态建模 Agent 的可复现评估

**状态：**研究治理约定；不是实验结果。

**适用系统：**本地桌面 CAD 建模系统，输入为零件文字描述和/或参考图片，输出为可编辑候选模型及验证记录。

**证据快照：**主线基线为本次审计时的 `main@3abd8164960ff5639abf504f9e1d44261b9c53c7`；迁移进展另以未合入的 `feat/rust-dsh-acp-host@56f3dc0780deb749701432e3a65c65712009cbd5` 标识。引用架构结论时必须注明来自主线还是功能分支，不得把分支实现写成主线能力。

## 1. 背景与问题边界

非标零件建模要求把文字、图像证据、尺寸假设转为有顺序、有来源、可编辑的 CAD 特征。参考图可能缺少尺度、包含遮挡或只展示部分视角；因此“模型生成了”“几何内核接受了”和“模型复现了目标”是不同主张，必须分别取证。

本项目的研究动机来自自身工作流中的问题和用户反馈：识图与比例估计不稳定，Agent 工具步骤可能冗余，几何转换、预览和审查之间可能产生不一致。这里描述的是**项目内观察与待测问题**，不构成行业规模、市场痛点普遍性或与商业产品优劣的证据。涉及行业趋势、竞品或用户群体的主张，须另行收集可追溯来源，不得由本章程推断。

研究范围覆盖两种产品路径：不使用 LLM 的快速模式，以及由 DSH 决策并调用建模工具的 Agent 创造模式。主线当前基线仍由 Vue/Tauri 调用 Python bridge；DSH 会话也由 Python 接入层驱动。Rust ACP Host 与私有 DSH Runtime 已在上述功能分支实现，但尚未合入主线；即使在该分支，CADPlan 和几何工具仍有 Python 过渡实现。分支状态及证据限制见[当前系统审计](02-current-system-audit.md)。目标架构图不作为已实现能力的证据。

## 2. 研究对象与问题

基本观测单位为一次建模任务运行：固定一份文字/图片输入、一个软件与模型配置，记录从接收到最终候选或失败终止的全部事件。多视图图片默认描述同一零件；输入集合、零件身份、视角和不可判断区域应先经标注，不得用模型自己的解释代替标注。

1. **Agent 决策：**由 DSH 选择工具和复核动作时，任务相关性、重复调用与候选质量如何变化？
2. **证据到特征：**系统能否把每个关键特征与其来源（用户尺寸、图纸标注、图像估算、标准资料或未知）对应起来？
3. **增量建模：**局部修改是否保留未涉及的特征、来源和几何状态？
4. **复核与修正：**几何检查和按视角图像审查分别能发现什么差异？新版本能否由新证据关闭已登记差异？
5. **运行与迁移：**Rust ACP、Cordis 插件、Python 几何过渡层及最终 CATIA 通道各自造成哪些成功、失败和延迟？

## 3. 假设、可观察量与反驳条件

以下假设是待检验命题。实验前应在单项记录中指定主要终点、数据集版本、条件和分析方式；不能只报告支持假设的例子。

| 假设 | 操作化的主要观察量 | 反驳或不支持条件 |
|---|---|---|
| Agent 自主选择工具，比固定阶段脚本更少执行无效步骤 | 工具序列的人工相关性标注、无状态变化的重复调用率、任务完成率、总耗时 | 在预先定义的相同输入与配置下，固定流程达到相当或更高完成率，且无效调用或耗时更低 |
| 增量特征工具比反复重写完整计划更能保持已有建模状态 | 预期不变的特征 ID/参数/来源保留率、参数错误率、失败回滚率 | 增量条件造成更多状态损坏、来源丢失或不可复现的 revision |
| 几何验收与视觉验收提供互补信息 | 分别测量几何有效率/尺寸误差与逐视图差异检出率/关闭率，并检查不一致案例 | 两类测量没有独立诊断价值，或其中一类无法可靠复测 |
| 原图逐张与匹配单视图比较，比拼贴多视图更少混淆 | 盲标注的差异召回率、误报率、视角归属准确率及复核耗时 | 单视图条件无改善，或成本增加且修正质量未提升 |
| Rust 迁移边界可以在行为兼容的同时减少 Python 业务依赖 | 固定 fixtures 的输入输出一致率、B-Rep 属性差值、Python 进程/调用清单 | 关键行为不可兼容、几何超出预设容差，或非 CATIA Python 依赖没有实际收缩 |

目前没有在本文件中提供这些假设的结果或显著性判断。

## 4. 指标预注册与比较原则

指标定义、容差、异常处理、纳入/排除规则和聚合统计写入[验证协议](../02-methods/01-validation-protocol.md)。实验开始后不得为改善结果临时更换主要指标；如必须改动，保留原方案，说明日期、原因及分析影响，并把新增分析标为探索性。

比较时必须指出对照条件。全流程比较应冻结输入、模型服务配置、提示词、知识库与运行环境，按平衡顺序执行同一输入；若比较目标本身包括提示词或工具变化，应声明是在比较“整套系统”，不能将结果归因于某一个组件。几何转换器比较应给不同转换器提供完全相同的 CADPlan fixtures。图片复核方式比较应只改变视图呈现，其余请求条件保持一致。重复运行次数由样本集规模、运行成本和预期变异度论证；没有功效/样本量依据时，只作描述性或探索性结论，不声称总体显著差异。

## 5. 证据等级与数据记录

每个结论注明证据等级：

- **需求/来源证据：**用户明确尺寸、可读图纸标注、被允许使用的标准资料；记录来源、许可、页码/区域与哈希。图像比例推算必须标记 `image_estimate`，且不伪装成制造尺寸。
- **标注证据：**由独立标注者建立的真值或可见事实清单，记录视角、遮挡、容差、标注者和争议处理。Agent 自述不能充当真值。
- **代码证据：**准确提交、文件、符号和静态路径，只支持“源码定义/连接了什么”。
- **运行证据：**原始请求/事件、运行配置、stdout/stderr、退出码、耗时、输出哈希；只能支持该次实际运行所观察到的行为。
- **几何证据：**内核返回的 B-Rep、拓扑、包围盒、尺寸及检查程序版本；不等同于图像吻合。
- **视觉证据：**原图和匹配单视图、视角标注、定位差异、检查者记录、修正前后 revision；单独的相似度分数不构成通过。
- **CATIA 证据：**实际 CATPart、CATIA 版本、特征树、重新打开结果、测量值与操作日志。STL、AIMODEL、本地预览不能代替它。

原始输入、逐次运行记录、模型、日志和派生分析应分别保存，不覆盖失败记录。试验文件放在 `temp/experiments/<study-id>/`，至少包括输入清单/哈希、运行配置、逐次原始记录、派生指标、失败样本和报告；应用运行数据仍可能保存在本机用户数据目录，试验结束时需显式导出所需证据并清理密钥。记录中不得写 API key、访问令牌或不应共享的个人数据。数据许可与保留策略应随样例清单登记。

## 6. 失败分析、偏差与威胁

失败不归为笼统的“模型不聪明”。记录可复核的首要失败层：输入/附件丢失、视觉事实误读、尺度假设、CADPlan/特征参数、插件注册/工具执行、几何内核/转换、复核证据不匹配、宿主/会话/运行时、UI 状态或 CATIA 通道。一个案例允许多层原因，并注明“已证实”或“推断”。保留无模型、工具错误、几何无效、尺寸偏差、视觉误判、超时和取消等负例。

至少讨论以下威胁：

- **内部效度：**模型非确定性、服务端更新、温度/推理配置、重试和网络波动；同一轮里同时改变提示词、工具和运行时会造成归因混淆。
- **构念效度：**特征数量、成功返回、体积或模型自评分不是“复现质量”的充分度量。
- **标注效度：**无尺寸图缺少毫米真值；遮挡或透视让某些几何不可观察；专家间容差判断可能不同。
- **外部效度：**小型自建样例集不能代表全部零件、用户和 CATIA 环境；不得泛化为行业精度。
- **污染与泄漏：**知识库、历史会话、示例模型或提示词可能包含测试答案；冷启动盲测应使用隔离会话并记录允许/禁止资料。
- **测量与报告偏差：**不同渲染器、视角、亮度、网格细分或日志缺失可能改变观察；失败和未完成运行仍须计入样本流图。

## 7. 结论边界与可复现条件

静态检查、单测、构建、真实 DSH 控制面、真实 provider 请求、图片上行、工具建模、B-Rep 检查、多模态复核和 CATIA 验证是不同层级，结论只可覆盖实际完成的层级。某一验证成功不得外推为后续层也成功。

复现者至少需要：Git commit/工作树差异、样例清单及 SHA-256、运行时 manifest 与哈希、操作系统和关键依赖、DSH/provider/model/route/reasoning 设置、提示词和工具 schema 版本、运行命令/手动步骤、逐次事件与输出路径、容差和指标脚本。provider 未公开的服务端版本或实际 token 数据要标成不可观测，不填猜测值。若不能复现，应保留失败环境与差异，降低结论强度，而不是删去该次记录。
