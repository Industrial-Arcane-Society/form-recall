# 前端界面与设计系统规范

本规范统一 Vue 桌面 UI 的视觉、交互和事件呈现。设计参考 Codex 对话工作区与 DSH Web 的流式信息层次；只复用可观察的交互原则，不复制未核验的内部实现。新增页面必须沿用现有 token 和组件，不在单页另造一套样式。

## 设计目标

1. **有响应感**：发送后立即出现用户消息、Agent 当前状态和可读的工作进展；慢速思考期间有稳定状态，不让整个对话像卡死。
2. **对话优先**：左侧对话负责完整上下文、附件、模型设置和状态；建模过程在中心画布同步呈现，右侧只保留特征与参数检查。
3. **结果可追溯**：思考内容、工具过程、模型预览、未解决项和最终结果视觉分层，状态文本准确描述实际收到的事件。
4. **密度可控**：技术日志默认折叠，点击后可查详细请求、工具、耗时和结果；用户可随时停止当前 session。

## 当前 CSS tokens

以 `src/apps/desktop/src/style.css` 的现行 tokens 为来源。修改 token 后同步检查亮/暗两种主题。

| Token | 当前值 | 用途 |
|---|---|---|
| `--ink` | `#1e2d3a` | 正文和标题 |
| `--muted` | `#687989` | 次级文本、说明、时间 |
| `--line` | `#dce3e9` | 分隔线、控件边界 |
| `--panel` | `#ffffff` | 主卡片和侧栏 |
| `--panel-soft` | `#f5f7f9` | 次级区域和悬停背景 |
| `--canvas` | `#eef2f6` | 画布周围工作区 |
| `--accent` | `#416b91` | 主交互色 |
| `--accent-dark` | `#315675` | 强调/选中态 |
| `--accent-soft` | `#eaf1f7` | 柔和强调背景 |
| `--success / --warning / --danger` | `#20866c / #ad7625 / #b84f4d` | 状态色 |
| `--radius-control / --radius-card` | `10px / 12px` | 控件/卡片圆角 |

亮/暗主题中的 ink、muted、line、panel、panel-soft、canvas、accent 必须对比清晰。状态不能仅用颜色表达，必须配文案或图标。

## 布局与响应

- 桌面主框架依次为顶栏、工作区、状态栏；主工作区由对话、模型视口、特征检查器组成。
- 工作区列宽使用可拖拽分隔器。对话区保证输入、附件与运行状态始终可见；视口保留独立缩放和旋转空间；Inspector 不抢占画布。
- 当前 Tauri 窗口最小尺寸约 1180×720。低于该尺寸时采用分栏/抽屉切换，不截断输入或工具状态。
- 弹层有清楚的关闭方式、边界和焦点；不靠固定位置覆盖关键状态。

## 对话组件规则

- 用户、Agent、工具事件和系统状态采用不同视觉样式，按时间顺序呈现。
- 参考图以缩略图卡片展示；多图可移除、查看原图并保留原始顺序。图片失败要给出可读错误。
- 长思考和工具细节采用可折叠区块：运行时显示“正在思考/执行工具”与经过时间；完成后自动收起，用户可展开查看已持久化内容。
- 进度提示来自真实事件；禁止在后端无活动或请求已失败时继续显示“正在处理”。连接/请求错误有明确的重试或停止入口。
- 输入区支持发送、换行、粘贴图片、附件管理、模式/模型选择和停止。Enter 行为在界面有可见提示并提供键盘替代。
- 代码/参数/日志用等宽字体；自然语言说明用常规正文样式，不把原始 JSON 堆进主对话。

## 模型和特征状态

- 新特征第一次落入有效模型时尽快推送预览；每次成功几何更新同步显示 revision、特征数量和尺寸。
- 几何错误不能静默使用上个版本冒充最新结果；需标出最后成功 revision 与本次失败动作。
- 建模中间结果持续更新右侧视口。结果卡显示本次动作、已完成项、未解决差异、导出入口。
- 辅助线、网格和坐标轴属于可独立开关的视图辅助层，不写入零件几何。

## 字体、间距和动效

- 拉丁 UI 使用当前 `DM Sans` / `Manrope` 体系，中文优先 `Microsoft YaHei UI` / `Segoe UI`；正文 14px，说明和时间不小于 12px。
- 继续复用 4px 间距节奏；同一组件内对齐、内边距和按钮高度保持一致。
- 动效仅用于状态变化、轻量展开和切换；短促、可中断，遵守减少动态效果偏好。加载状态优先使用进度文本/局部 skeleton，避免全屏遮罩。
- 图标来源与线宽一致；操作按钮必须有文字或可访问名称。

## 可访问性与验收

- 键盘可到达主要操作，焦点轮廓沿用全局样式；ESC 只关闭可关闭的界面层，不误停 Agent。
- 为动态图像、运行状态和错误提供屏幕阅读器可识别的说明；颜色对比满足桌面可读性。
- UI feature 至少核对：默认/亮暗主题、长消息、图片、多轮工具流、工具失败、停止/取消、窄窗口布局和无模型空状态。

## 变更纪律

新增 CSS 变量放 `:root` 和主题覆写处；表单、按钮、状态、卡片使用共享组件。每项视觉特性引用本规范并更新这里的 token/行为，不能形成组件内部一次性色值体系。
