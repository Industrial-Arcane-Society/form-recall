# 桌面前端设计系统与验收规范

本文是 Tauri + Vue 桌面端的前端设计约束和研究记录入口。它把当前代码中已经存在的界面行为与后续改动必须遵守的规则分开记录，避免把计划中的体验误写成已经实现。

## 1. 范围与证据状态

本规范覆盖桌面端顶栏、模式切换、对话和图片、三维视口、特征检查器、日志/状态、主题、响应式、键盘操作、可访问性、共享组件和界面验收。建模算法、Agent 决策和几何内核不属于本文件的设计范围；界面显示这些功能时必须准确反映其实际事件和结果。

每项描述使用以下状态约定：

- **现状**：本次从仓库代码直接确认的行为或样式。
- **规范**：新设计和后续改动必须满足的可执行约束。
- **待验收**：代码本身不能证明最终视觉或运行体验，需要启动桌面应用并记录证据。

## 2. 产品体验原则

1. **对话驱动建模**：用户描述、参考图、Agent 回复和关键操作保持在一个连续会话里；模型预览随着有效建模结果更新。
2. **几何始终可检查**：三维模型拥有工作区的视觉主位；特征、参数、统计和日志在 Inspector 中按需切换。
3. **状态有证据**：运行、成功、警告、失败、取消分别使用准确文案和图形状态。界面只呈现收到的实际事件；没有事件时不能伪造“正在思考”或“预览已更新”。
4. **估算可辨认**：来自参考图推断的尺寸、结构和不确定性要保留来源说明。界面不得把图像估值呈现为用户输入的制造尺寸。
5. **一个系统，多种工作模式**：快速模式与 Agent 模式复用品牌、布局、输入区和模型检查方式；差异通过模式说明、能力可用性和运行反馈表达。
6. **证据先于装饰**：阴影、边线、网格和高光必须帮助判断几何形状，不得让面片、穿透或参考辅助线误导用户对实体边界的理解。

界面可以借鉴通用的对话连续性、即时状态反馈和工作区分区原则。不得照搬其他产品的品牌、布局细节或未核实行为；每项界面选择都要能由本项目的建模任务和验收证据解释。

## 3. 当前信息架构

### 3.1 窗口和主框架

**现状**：Tauri 主窗口初始为 `1600 × 980`，最小尺寸为 `1180 × 720`，可调整大小。Vue 主框架从上到下由顶栏、工作区和底栏组成。工作区是三列：对话栏、模型视口、Inspector；两侧分隔条可用指针拖动，两侧栏也可手动收起。

**规范**：

- 主操作按任务顺序呈现：选模式/工程操作 → 描述或附图 → 生成过程 → 检查几何 → 编辑特征/查看日志 → 保存或导出。
- 三维视口在可用宽度不足时优先保留；不要让对话输入、运行状态或停止操作被视口遮挡。
- 只有当前任务确实需要时才新增常驻面板。次要设置、集成和帮助放进有标题、有关闭入口的弹层或按需面板。
- 收起栏必须提供可见的重新打开入口；收起不能销毁当前会话、模型或面板选择。

### 3.2 对话栏与模式

**现状**：对话栏包含标题/示例/新对话控制、模式切换、模式说明、消息历史和固定在底部的输入区。模式为“Agent 模式”和“快速建模”：Agent 支持多轮会话及参考图片；快速模式走本地描述解析，界面禁用图片按钮，粘贴图片时提示切换到 Agent 模式。Enter 发送、Shift+Enter 换行。Agent 思考区以 `<details>` 显示，流式时展开、结束时自动收起；工具事件显示在消息流中。

**规范**：

- 两种模式的选中态必须有可见背景/边界，同时暴露给辅助技术（例如 `aria-pressed` 或有正确角色的单选组）。模式说明必须准确列出图片、多轮上下文、联网等能力限制。
- 切换模式不应清空草稿、附件或会话；若某模式无法提交现有附件，必须在切换前或切换后解释如何处理。
- 用户消息、Agent 回复、工具进度、思考内容和错误有明确的语义标签和视觉层级；不得仅靠头像颜色区分。
- 工具/诊断明细默认折叠或以短摘要呈现；当前动作与下一可用操作保持可见。运行结束后思考区自动收起，但允许用户重新展开。
- 文本、代码、日志均允许换行和滚动，不横向撑破面板；不得把原始协议 JSON 当作普通回复。
- 输入区无论消息多长都留在对话栏底部；加载图片期间显示真实加载状态并阻止重复提交。

### 3.3 参考图片

**现状**：Agent 模式支持选择多张图片与粘贴图片；待发送附件显示缩略图和可访问名称，失败时显示“预览不可用”占位。发送后缩略图显示在用户消息中。界面筛选 PNG/JPG/WEBP/BMP/GIF。

**规范**：

- 图片卡片保持原始顺序并显示缩略图；移除、失败和格式不支持均提供文字状态。缩略图不得被压缩到无法辨认工件主体。
- 用户可在发送前移除附件；发送后图片应与对应用户消息绑定，而非堆在会话末尾。
- 图片的加载、读取失败和 Agent 不支持该格式必须分别反馈。**现状与待核对**：界面接收 BMP，但 ACP/DSH 图片通道的格式能力需要按实际运行版本核验；前端允许扩展名不等于模型已收到该图片。
- 多图表示同一工件时保留用户提供的顺序；如后续有视角标签，标签应和对应缩略图绑定。

### 3.4 模型视口

**现状**：中心区域使用 Three.js 呈现 GLB 网格，并叠加 Agent 阶段预览图、空状态、坐标图例、毫米标注和模型状态。顶部有等轴、前、左、右、顶视、适应视图、特征边线、参考网格和坐标轴按钮；设置中可选透视/正交投影。`CadViewport.vue` 使用半球光和两个方向光，边线由几何边缘叠加生成。OrbitControls 提供旋转/平移/缩放交互。

**规范**：

- 用户必须能区分最终/当前可编辑网格、Agent 阶段截图、辅助线和坐标/网格；预览图不得伪装为已写入工程的几何。
- 视图工具用名称或有意义的辅助文本表达当前状态；开关显示选中态并同时提供 `aria-pressed`。
- 阶段预览变化需标注预览阶段/版本；模型网格更新失败时保留最后成功模型并明确标明其版本与本次错误。
- 网格、坐标轴和特征边线是显示辅助，不进入几何导出。视图按钮的视角名称与投影方向需用已知几何样例核实。
- 光照需保持关键侧面明暗可分辨且无过曝、过暗或 z-fighting。单色/近似平面模型的视图验收必须包含正视、等轴和侧视对照。

### 3.5 Inspector、特征与状态日志

**现状**：右侧 Inspector 有特征树、参数、统计、日志和标准零件库五个标签。特征树支持选择、重命名、启用/停用、排序、删除；参数面板提供数值编辑与应用重建。模型统计包含尺寸、面片、三角面、体积、表面积和特征类型计数。事件日志保留最近 260 条，并在日志标签中查看。

**规范**：

- 当前选择项、未启用特征和参数修改前后的状态必须可辨认；破坏性操作（删除、清空）要有恢复策略或确认。
- 参数名需用用户能理解的名称；单位始终紧邻数值。无法编辑的参数不得显示为看似可编辑的输入框。
- 统计和日志标明对应模型 revision/任务；旧 revision 的状态不得混入最新模型状态而不作区分。
- 状态颜色必须配文字或图标。成功、运行、警告、失败、取消使用一致的语义，不为不同页面另造含义。
- 长日志可滚动、可复制、可清空；会话主流保留简短进展，完整诊断放在日志视图。

## 4. 布局与响应式规则

### 4.1 现有布局能力

| 尺寸/行为 | 当前事实 |
|---|---|
| 支持下限 | Tauri 与 CSS 都将主窗口最小宽度设为 1180 px，最小高度 720 px |
| 分栏 | 对话默认 328 px，Inspector 默认 320 px；拖动时对话约束为 300–480 px，Inspector 约束为 280–440 px，视口保留至少约 500 px |
| 断点 | CSS 在 1370 px 和 1260 px 主要压缩顶栏/视图工具/标签及输入工具；没有自动改为抽屉或移动端单栏 |
| 收起 | 对话栏、Inspector 可由用户手动收起，并由视口工具栏按钮重新打开 |
| 高度 | 页面主体禁止浏览器整体滚动；消息区和 Inspector 内容区各自滚动 |

不得把当前实现描述为窄屏自适应/移动布局。低于 1180 × 720 的视口不在当前支持范围内。

### 4.2 后续响应式验收约束

- 设计时至少提供 `1600 × 980`、`1370 × 800`、`1260 × 720`、`1180 × 720` 四档截图；另测 Windows 125%/150% 缩放下实际可用空间。
- 在支持下限内，模式切换、输入区、发送/停止按钮、状态文案、顶栏关键操作和模型视口操作不能被裁切或仅靠悬停才可发现。
- 可压缩次要文字、标签间距和非关键装饰；关键操作不得缩成无名称图标。必要时由用户手动收起侧栏，但不得自动丢弃输入或状态。
- 若未来增加窄于 1180 px 的支持，必须另行设计单栏/抽屉模式、焦点顺序和恢复布局行为，并更新本节最小支持范围；仅加一个 CSS 断点不算验收完成。

### 5.1 已定义变量

### 5.2 新增样式要求

- 新增颜色只能用于已定义的语义 token；确有新语义时，先在 `:root` 定义浅色 token，再在 `.theme-dark` 定义深色值，并记录用途。
- 禁止在单个组件中新增一次性色值来表达重复的正文、边框、选中、错误、成功或悬浮语义。阴影、透明叠层和 3D 材质例外，但须在代码评审说明原因。
- `--muted` 仅用于次要信息。主要文字/小号说明目标对比度至少 4.5:1；大号文字及非文本控件边界至少 3:1（按 WCAG 2.2 AA 目标验收）。颜色对比须使用最终前景/背景配对计算，不能根据色值主观判断。
- 交互状态至少区分默认、悬停、键盘聚焦、按下/选中、禁用；禁止只用颜色变化表达状态。
- 新组件优先使用已有 4 px 间距倍数；密集数据可使用 2 px 子增量，但相邻组件仍按 4 px 主节奏对齐。圆角优先使用现有 10/12 px token；更小内嵌控件需要统一定义，不各写不同值。
- 不得以纯色作为状态唯一提示；成功/警告/错误必须提供可读标签，辅助技术也能获得相同状态。

### 5.3 字体与排版

**现状**：全局 font-family 声明 `DM Sans`、`Microsoft YaHei UI`、`Segoe UI`；局部规则还引用 `Manrope` 与 `DM Mono`。`index.html` 未载入或打包这些字体，因此实际显示可能取决于系统回退。

**规范**：中文正文优先系统中文 UI 字体，英文 UI 可用项目实际打包的无衬线字体；代码、尺寸、坐标和日志使用等宽字体。未经打包或平台测试的字体不能写成保证存在。正文建议 14–16 CSS px，次级说明不得低于 12 CSS px；关键尺寸/状态不应使用浅灰小字。字号、行高与缩放需在 100%、125%、150% 屏幕缩放下进行视觉检查。

## 6. 共享组件和交互约定

当前可复用前端组件包括 `UiIcon.vue`、`AttachmentPreview.vue`、`CadViewport.vue`、`ModelStats.vue` 和 `DependencySetup.vue`。新增 UI 应先查找这些组件及 `style.css` 中现有模式；同一种卡片、按钮、标签、状态或弹层重复出现两次以上时，优先抽取共享样式/组件，禁止继续复制粘贴变体。

- **图标**：使用 `UiIcon.vue` 的 Lucide 图标。图标组件设置 `aria-hidden="true"`；因此图标按钮的父级必须通过可见文字、`aria-label` 或合适的原生名称提供可读名称。`title` 可作提示，不能替代关键操作的辅助名称。
- **按钮**：主操作只设一个清晰视觉主级；次级和破坏性动作区分明显。图标按钮命中区至少 32 × 32 CSS px，常用主按钮至少 36 px 高。
- **消息/进度**：统一由消息类型、状态标签和时间/任务归属表达；避免孤立的重复“AgentLoop”占位条。没有文本的空消息不占据历史区域。
- **附件**：同一组件同时支持待发送可删除和历史只读两种状态；图片错误时保持卡片尺寸稳定，避免布局跳动。
- **弹层**：设置、集成、帮助、搜索等弹层使用共享背景遮罩、标题区、关闭按钮、内容滚动区和底部操作区；一次只让最上层接收键盘关闭/焦点。
- **图表/数据**：尺寸数字和单位同一行或明确成对显示；图表必须有可读数值，不只用条长/颜色传递数据。
- **空状态**：说明当前状态、下一步操作；若没有模型，应提供输入/建模入口，而不是空白占位。

## 7. 键盘、屏幕阅读器与输入设备

### 7.1 已核实的键盘行为

当前全局快捷键为 `Ctrl/⌘+S` 保存、`Ctrl/⌘+O` 打开、`Ctrl/⌘+N` 新建、`F` 适应模型；输入框中 `Enter` 发送、`Shift+Enter` 换行。`Escape` 当前只关闭更多菜单，不负责关闭所有弹层，也不取消 Agent。拖拽分隔条当前为指针事件，没有键盘调节实现。

### 7.2 可执行的无障碍规范

- 页面可交互元素按视觉顺序可用 Tab/Shift+Tab 到达；焦点轮廓清晰、不被裁切。`:focus-visible` 规则必须覆盖按钮、链接、输入、模式选项、标签页、特征行、视口工具和弹层控件。
- 对话状态/后台进度通过 `aria-live="polite"` 等语义发布，错误用适当的 alert/live 区；不可对每个 token 更新重复朗读，可按状态/阶段节流。
- 模式选择和边线/网格/坐标轴开关暴露选中状态；特征树行具备键盘选择及可读的名称、类型、启用状态。不可点击的 `<div>` 不应承担唯一交互语义。
- 分隔条提供键盘调整方式，或改为有名称、可访问的替代宽度设置控件；不能仅支持指针拖动。
- 弹层使用 `role="dialog"`、`aria-modal="true"` 和关联标题；打开后焦点进入弹层，Tab 不离开弹层，关闭后焦点回到触发按钮。Escape 关闭当前最上层非破坏性弹层；生成任务只通过清晰的“停止”按钮取消。
- 每张参考图有替代文本；图标若只是装饰保持隐藏，若承担信息必须提供文本替代。
- 支持 `prefers-reduced-motion: reduce`，关闭或缩短非必要脉冲、过渡和视口动画；信息不能只由动画呈现。
- 键盘与辅助技术验收不得用“有 title”替代可访问名称，不得要求悬停才能发现关键操作。

以上是**目标规范**。当前代码只对按钮/输入/选择框提供基础焦点轮廓，输入区和附件删除按钮有部分 ARIA 名称，安装日志有 `aria-live`；主消息流、运行状态、模式选择、Inspector 标签和鼠标分隔条尚未达到上述完整要求。源码未发现 reduced-motion 规则、完整弹层焦点管理或视口键盘控制，须作为后续 UI 工作项，不得标记为已通过。

### 7.3 视口指针操作

模型旋转、平移、缩放必须在帮助提示和无障碍替代说明中使用一致的动作描述。相机视角切换应可直接通过具名按钮完成；几何检查不能要求用户精准拖动到某个角度。视口焦点进入后，浏览器/全局快捷键不能意外触发模型之外的命令。

## 8. 主题与动态效果

**现状**：顶栏主题按钮切换浅色/深色 CSS class；当前状态保存在 Vue 运行状态，没有看到持久化逻辑。深色变量集中覆写了主要表面、文字、边框和强调色，但多个组件仍通过散落的 `.theme-dark` 规则处理，部分状态色没有主题 token。

**规范**：

- 新组件必须在浅色和深色主题中同时检查正文、占位符、边界、选中、禁用、错误和弹层状态。不能仅证明主面板背景切换成功。
- 主题选择是否随重启保存应明确；若不保存，重新打开窗口应显示默认主题且不能误导用户以为偏好已持久化。
- 动效只反馈状态变化、轻量展开和切换；不得通过长动画延迟发送或停止。后台任务期间动画不能成为唯一进度信息。
- 三维场景的模型材质、线框和灯光不自动继承 UI token，但必须同时检查浅/深画布对边界、孔洞、凹槽和遮挡的可读性。

## 9. 视觉与功能验收矩阵

任何新增/重构的界面功能至少记录运行版本、窗口尺寸、操作步骤、通过/失败、截图路径和剩余问题。若项目决定增加截图基准，应将基准放在可定位的测试目录，标出运行系统、DPI、主题与模型样例，并对更新原因进行评审。

| 验收场景 | 通过标准 | 当前证据状态 |

## 10. UI 变更流程与研究记录

每个前端功能/视觉改动按以下顺序记录：

1. 写明用户任务、当前痛点、支持的工作模式和不确定项。
2. 引用现状代码或运行截图作为基线；把代码事实、推断、设计目标分开。
3. 说明布局、交互、状态、错误、空状态、键盘和无障碍方案；列出新增/修改 token 和共享组件。
4. 先做类型检查/构建，再按验收矩阵在桌面窗口运行；构建通过不代表视觉验收通过。
5. 记录环境、尺寸、DPI、输入样例、截图/日志路径、结果和失败项。
6. 如结果不符合预期，保留原问题和修改证据；不得只以主观“看起来不错”收尾。

设计文档的定位是**可追溯的研究记录与执行规范**，不是宣传文案。每项结论要指向代码、运行截图、测试或外部资料；没有依据的产品能力标记为待验证，不补造性能或用户体验结论。

## 11. 本次代码审阅结论

### 已由代码确认

- 主工作区采用 Tauri + Vue，三栏为对话、Three.js 视口、Inspector。
- Agent / 快速建模两种模式共用对话面板；快速模式拒绝图片，Agent 模式提供多模态图片入口。
- 模型工具条有常用标准视图、适应视图、边线/网格/坐标轴开关；Inspector 有五个标签。
- 主窗口最小尺寸为 `1180 × 720`；CSS 的两个响应断点以缩放控件布局为主。
- 前端依赖包括 Vue 3、Three.js 与 Lucide；Tauri API 用于调用桌面能力。

### 明确未验证/待处理

- 未捕获当前安装包或运行中窗口截图；未检查 Windows 高 DPI 下的真实视觉效果。
- 当前前端包没有专门的 UI 单元、组件或端到端测试脚本，也没有源码内的 UI 截图基准。
- 浅/深主题仍有散落的硬编码色值，主题全覆盖和 AA 对比度尚未核验。
- 图片 UI 接受的 BMP 与 ACP 真实多模态输入兼容性需要运行时实测。
- 屏幕阅读器状态播报、标签语义、模态焦点管理、键盘分隔条和减少动态效果均未完整实现。
- 字体声明包含系统/未载入字体，实际 Windows 回退需要截图核验。

任何后续评审都应先更新以上待验证项，再据新证据修订结论；不要把“源码里有处理函数”当成实际可用的用户体验证据。
