# 多模态建模系统验证协议

**性质：**预先规定的数据、对照、指标和留档方法；本文件不是试验结果。

**主线基线：**`main@3abd8164960ff5639abf504f9e1d44261b9c53c7`。

**候选迁移实现：**`feat/rust-dsh-acp-host@56f3dc0780deb749701432e3a65c65712009cbd5`，未合入主线。执行时重新记录实际 commit、工作树差异和运行配置，不得使用当前分支名代替精确版本。

## 1. 研究设计登记

每个研究在运行前建立唯一 `study_id`，说明是**探索性**还是**假设检验**，并填写：

- 研究问题、主要假设、预注册的主要终点与次要终点。
- 研究对象、排除规则、样本量/重复次数及选择依据；不足以进行功效分析时，明确标为描述性研究。
- 对照条件、唯一被操纵的变量、固定变量、运行顺序和随机化方式。
- 数据集版本、样本 ID、输入 SHA-256、标签/尺寸来源、允许与禁止的先验资料。
- 软件 commit、工作树差异、runtime manifest 与依赖哈希，DSH/provider/model/route/reasoning 和安全的推理配置。
- 指标公式、容差、异常值和失败运行的处理方法、统计聚合方式。

注册以后如改变假设、样本、主要指标、容差或排除标准，保留原版本并记录变更原因和时间；变更后的分析标记为探索性，不能覆盖先前结果。

## 2. 数据集与对照条件

### 样本类型

至少按以下输入类别分层，不混成单一“识图能力”分数：

1. 仅文字，含完整尺寸与不完整尺寸。
2. 单张参考图，有尺寸标注与无尺寸标注。
3. 同一零件的多视角图，记录每张视图、遮挡和互相矛盾的证据。
4. 需要标准资料/知识查询的标准件任务。
5. 多轮续话、局部改模和错误恢复任务。
6. 歧义或不可观察项样例，用于测量系统是否保留不确定性。

每项保存任务意图、可观察事实、不可观察事实、关键尺寸真值及其来源。没有真值的无尺寸图，只能评价尺度无关的比例和可见拓扑；不能按模型自选的毫米尺寸计算“绝对误差”并称作真实尺寸准确度。

### 基线与对照

- 对主线 Python DSH 流程与 Rust ACP Host 作全流程比较时，同一输入分别在隔离干净会话中运行；固定 provider/model/route/reasoning、提示词、知识库、工具定义、模型初始状态和网络条件。按平衡或随机顺序执行，避免先运行的一组为后一组暴露答案。
- 若提示词、工具 schema、知识库、几何后端同时改变，该实验只能比较两套端到端系统，不能把差异因果归于 Rust、ACP 或某条工具。
- 比较图像复核策略时，仅改变图像组织方式（拼图或匹配的单视图）；比较 CAD 几何实现时，为各实现输入同一批冻结的 CADPlan fixtures。
- 冷启动盲测使用新 session、禁止读取答案/旧模型/成功报告；记录 Agent 实际能访问的资料。另设已知答案回归集，两者分开汇报。
- 非确定性模型按预注册次数重复同一条件，保留每次运行；provider 暴露不了的采样或服务端版本记作“不可观测”，不填估计值。

## 3. 验收层级与操作化定义

各层分别报告；上层未通过不能由下层代替。

| 验收层 | 操作性通过定义 | 主要度量 |
|---|---|---|
| 输入/运行链路 | run 记录中的文字、每张原图 SHA 与发送给 Agent 的内容相符；工具轨迹确有 DSH 事件及参数/结果 | 图像/文字携带率、工具事件完整率、请求/工具失败率 |
| Agent 任务完成 | 由不知道系统条件的评审者按预先冻结的特征清单确认关键结构、必要限制和输出状态全部达到任务标准 | 逐任务通过率、关键缺陷率、首次候选与修正后候选分开统计 |
| CAD 结构与几何 | 固定 CADPlan 检查项通过，几何内核报告可解析且拓扑检查达到预注册条件 | 特征存在/参数误差、包围盒误差、拓扑有效率、实体/壳统计 |
| 视觉审查与修正 | 每张原图与方向匹配的单视图分别判读；错误意见由独立标注集核验；修正后必须使用新 revision 复查 | 差异 precision/recall、误报/漏报、可行动意见采纳与关闭率 |
| CATIA（若在范围内） | 目标 CATIA 版本重新打开输出 CATPart，特征树/尺寸检查符合预注册标准 | 打开/重建成功率、尺寸偏差、实际 COM 日志 |

### 指标定义

- **输入图携带率** = run 证据中可核对 SHA 且实际 prompt 含对应图像 content block 的输入张数 / 用户提交张数。仅看缩略图、文件名或 UI 文案不算已上传。
- **关键任务通过**：预注册必需结构和约束均通过；未解决的关键失败不能被其他小项抵消。报告二元通过/失败，并列出逐项判据。
- **轴向包围盒相对误差**：有标注真值时，对每轴报告 (|d_{pred}-d_{ref}|/max(|d_{ref}|,\tau))，同时给绝对偏差及 `\tau`。无绝对尺寸真值时只报告明确归一化的长宽高比例误差，不推称毫米准确度。
- **特征/孔位误差**：在标注和预测特征有明确匹配关系时，报告计数差、每孔中心的 XY/Z 欧氏误差（mm）、归一化误差、直径绝对/相对误差、轴向和贯穿状态。遮挡或不可观察特征单独列出，不视为确定缺陷。
- **几何合法性**：按内核版本报告 B-Rep valid、闭合实体/壳、非有限体积、退化/自交检查的原始值。不能把“返回成功”直接记作合法实体。
- **差异检出**：以独立评审预先标注的差异集合为基准，按差异项计算 precision、recall、F1，并按严重度分层；同时报告视角归属正确率。Agent 自报 match/confidence 不作为真值。
- **差异关闭率** = 经独立复核且在新几何 revision 中确实修正的可行动差异数 / 已确认可行动差异数。证据不足、不可观察、拒绝或未复核分别列数，不能当作已关闭。
- **工具效率**：逐个调用人工标记是否产生状态变化、获取必要证据或完成预注册子目标；报告有效调用比例、无变化重复调用比例、总工具调用数、首个有效预览时间与端到端墙钟时间。不得依赖模型自评。
- **资源消耗**：报告 provider 实际返回的 input/output/reasoning token 与费用；provider 不提供某字段时记为缺失。UI 估算和流式字数不是实际 token。
- **迁移兼容性**：同一 fixture 对比旧/新实现的参数化差值、B-Rep 属性、失败类型和输出哈希；浮点几何不能只比较文件字节哈希，须给容差与失败样例。

聚合时逐样本展示分布和失败数；通常报告中位数/IQR、均值/标准差（若有理由）及适当置信区间。样本很小或未作功效设计时写“描述性观察”，不得因少量样例声称统计显著或行业级精度。

## 4. 标注与审查程序

1. 在系统运行前冻结参考特征清单、视图方向、可观察/不可观察区域、尺寸真值来源和每项容差。
2. 由至少一位未参与该次建模的评审者，按盲化后的图像/输出记录候选和差异；条件允许时由第二评审者复核冲突，保存分歧及裁决过程。
3. 分开记录原图识别、CAD 特征解释、几何测量和视觉审查结果，避免同一个 LLM 的推理同时充当输入、参考答案与验收者。
4. 修正后的证据必须标注对应新 revision、视角和文件哈希。旧预览或旧相似度不能关闭当前问题。
5. 若图像不足以判定凹槽深度、孔是否贯穿、背面形状等特征，标成“不可观察/需补充资料”，不得猜测后作为事实。

## 5. 失败与偏差记录

所有已启动样本均进入运行清单，包括成功、失败、超时、取消、部分完成、provider 错误、图像拒收、无效计划和几何拒绝。失败可多标签分类：

- 输入、格式或引用资产丢失；
- 视觉事实、视角、遮挡或比例误判；
- 意图/Plan/特征关系或参数问题；
- 提示词、模型 route、工具选择或重复调用；
- ACP/session/provider/插件注册/工具执行；
- CADPlan 校验、Python worker、OCCT/几何转换；
- 预览渲染或视觉审查；
- Tauri/文件/线程/UI/日志路径；
- CATIA COM/宏/重建/测量。

每个根因标签注明证据类型（直接日志、可复现最小样例或推断）、严重度、影响指标、临时措施与是否会在复跑时消失。预先定义超时和重试；系统自动重试仍属于同一次 run 的事件序列，不能只报告最终成功结果。

## 6. 可复现运行与数据存储

### 试验包

原始数据只追加、不覆盖，存入 `temp/experiments/<study-id>/`：

```text
manifest.json                  # 问题、条件、版本、数据集和预注册指标
inputs/<sample-id>/            # 获准留存的原图/文字及 SHA 清单
runs/<run-id>/                  # 每次运行的事件、配置、日志、输出/失败快照
derived/                        # 由脚本生成的指标表和中间计算
report.md                       # 方法、结果、失败和边界
```

不要将 API key 或个人敏感数据复制到试验包；若原始输入受限制，保留受控位置、授权和 SHA-256，不另行复制。保存输入前检查图像许可和使用范围。

### 主线与迁移分支的存储边界

主线 Python DSH/AgentLoop 有 `temp/agent-logs/` 路径。未合入的 Rust ACP Host 分支会把会话 metadata、用户轮次和图片清单放在应用用户数据目录的 `agent-host/` 会话工作区。二者不能混称为一个自动同步日志目录。按试验包要求复核时，应从实际路径显式导出脱敏记录和输出，并记录导出清单；若没有原始 provider/图片上行事件，就把该项标为未核验。

### 复现清单

每次运行清单含：OS/架构、主线或功能分支 commit、dirty diff、桌面版本、Python/Node/DSH/插件和 OCCT 版本、manifest/锁文件哈希、provider/model/route/reasoning、安全的非秘密配置、样例 ID/输入哈希、启动命令、运行顺序、开始/结束时间、所有工具事件、错误/重试/取消、输出路径和文件哈希、指标脚本版本。若输出不含软件或服务端关键版本，应明确此限制。

## 7. 结果报告门禁

- 严格区分：代码存在、单元/集成测试、固定 runtime 启动、真实 ACP 控制面、真实 provider 请求、图像上行、工具调用、候选几何验证、独立多模态复核、CATIA 验收。
- 对主线与未合入分支分别报告；不把分支通过记入 main 结果。
- 报告样本流：计划数量、启动数量、失败/取消/排除数量与原因。
- 失败、不确定与不可观察项和成功项同时出现；不得静默排除不利样本。
- 结论逐条链接到本次具体 run、源图哈希、CADPlan/revision、几何/视觉报告和指标计算。
- `git diff --check`、静态解析、单测、前端 build、安装包 cold start、DSH 真实模型请求、CATIA 实测分别报告，低层通过不替代高层验收。
