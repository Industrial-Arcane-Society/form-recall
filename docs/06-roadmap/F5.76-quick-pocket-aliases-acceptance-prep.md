# F5.76：Quick pocket alias 兼容与验收

## 范围

Rust Quick 在 `split_clauses` 后逐个 modifier 子句处理 `内腔`、`型腔`、`开口`，将安全的单一别名规范化为现有矩形槽词 `槽`，然后复用既有 slot builder。没有改写完整 prompt、基础体文本或通用分句逻辑。实现位于 `native_quick_parser/legacy_pocket_aliases.rs`，接线和解析合同测试位于 `native_quick_parser.rs`。旧 Python 实测及 Rust 预期收录在 [fixture](../../src/apps/desktop/src-tauri/tests/fixtures/quick_legacy_pocket_aliases_audit.json)。

## 旧 Python 基线

通过 `src/legacy/ai_modeler/core/parsing/nlparser.py::parse` 重放三个别名、缺参、仅别名、零尺寸、型材冲突、复合操作和无分隔符输入。旧 parser 对 `内腔/型腔/开口` 均生成矩形 pocket；其 `make_pocket` 默认规则为 `length=20 mm`、`width=20 mm`、`depth=5 mm`，而显式的非零值覆盖默认值。显式 0 也因 Python 的 `value or default` 语义回退到对应默认值。旧端不发警告或追问。

在旧 Python parser 中，`内腔/型腔/开口` 出现在 `_SPLIT_MARKS` 外，所以无分隔符的“基础体尺寸 + pocket 别名”会只建基础体并静默丢 pocket。相反，`然后` 和旧端对 `并打孔` 的处理能把复合输入拆成 pocket 与孔。旧端的 `型材内腔...` 会进入零件库路由并多出一个 80×80×88 mm 方盒而没有 pocket；Rust Quick 现在已为本文列明的精确两子句输入复现这个堆叠方盒行为，并非真正的 EGT 型材截面。

## Rust 迁移行为

- 对通过 Rust `split_clauses` 后得到的单个安全子句做词法规范化；别名只出现一次，且不存在同子句孔/其他操作、基础形状、型材/材质或句子边界时才改写。
- 缺省及 0 尺寸沿用 slot builder 的旧兼容值。对应 CADPlan 参数来源为 `derived`，并通过结构化 `legacy_slot_dimensions_defaulted` warning 列明补值；用户输入的正尺寸仍是 `user`。
- `开口槽` 已包含 canonical 槽词，不会重复解释。`然后内腔...并打孔...` 由父分句器拆分后，pocket 与 hole 分别解析。
- 未分隔的基础体+pocket 别名以及未能拆分的同子句复合修改返回 `unsupported`，不再静默漏特征。
- `型材`、材质语境不由 pocket helper 转换。精确输入 `长方体 长100宽80高20，然后型材内腔长30宽20深5` 先独立解析基础体，再复用旧 EGT 简化目录中的第二个 `80×80×88 mm` box 并置 `stack=true`；CADPlan 保留旧端 `center=[0,0,0], base=false, stack=true`，原生 OCCT 从现有实体 Z 顶面开始堆叠。其它不完整或多操作模板句不走此窄路由。
- 这条 Rust Quick→CADPlan→OCCT 路径需要 Rust validator 接受布尔参数 `stack`，并由 native geometry builder 实施堆叠定位。Python SDK 的 `FEATURE_SPECS`/`_BOOLEAN_KEYS` 不参与这条路径；本次已撤销对 `src/legacy/ai_modeler/sdk/cadplan.py` 的临时修改，避免扩大 F5.76 范围。

## 验收与边界

fixture 覆盖三个正向别名、缺少不同尺寸、裸别名、零尺寸回退、拆句复合孔、已有槽词，以及无分隔符、同子句复合和型材目录冲突边界。解析合同核对状态、几何参数、来源类型、结构化 warning、型材 stacked 标志与特征数，并用 CADPlan validator 检查有效性。型材冲突额外运行 native Quick→OCCT 单样例 headless 构建。

## 定向 OCCT 几何结果

旧 Python oracle 使用 `ParseResult.doc.stats()` 的网格统计：包围盒 `[-50,-40,0,50,40,108] mm`，尺寸 `100×80×108 mm`，有向网格体积 `723200 mm³`。`doc.stats()` 不报告 B-Rep 有效性或闭合实体数，因此旧端闭合实体数未知。旧端另一个 `doc.brep_report()` 目前未应用 stack 变换，给出不同的未堆叠结果；这里以实际建模/网格统计路径 `doc.stats()` 作为几何基准。

Rust Release 单样例 CLI 对上述精确输入执行 `native_quick_parser::parse` → CADPlan 校验 → OCCT B-Rep 构建，结果 `status=passed`、2 个 plan features（基础 `100×80×20 mm` box 与 EGT 堆叠 `80×80×88 mm` box）、bbox `[-50,-40,0,50,40,108] mm`、尺寸 `100×80×108 mm`、体积 `723199.9999999999 mm³`、`closed_solid_count=1`。这确认此前记录的“旧端多出方盒、Rust 未复制”已修复；当前边界仍是窄路由只覆盖精确的两子句型材别名形式，其它模板句按原 parser 路由处理。Rust 包围盒和体积与旧 Python `doc.stats()` 结果一致；单闭合实体仅是 Rust OCCT 几何自身的验证结果。

`cargo check --tests` 通过。定向 `cargo test` 进程在当前 Windows 环境因 `STATUS_ENTRYPOINT_NOT_FOUND` 无法启动；ignored headless 几何合同已编译，OCCT 几何由 Release probe 实际执行。没有运行 GUI、全量解析矩阵或 CATIA 验证。

## 可复现的旧 Python 命令

在仓库根目录 PowerShell 执行：

```powershell
@'
import sys
sys.path.insert(0, r'src/legacy')
from ai_modeler.core.parsing.nlparser import parse, parse_clauses, normalize
cases = [
    '长方体 长100宽80高20，然后内腔长30宽20',
    '长方体 长100宽80高20，然后型腔长30深5',
    '长方体 长100宽80高20，然后开口',
    '长方体 长100宽80高20，然后开口长0宽20深5',
    '长方体 长100宽80高20，然后型材内腔长30宽20深5',
    '长方体 长100宽80高20，然后内腔长30宽20深5并打孔直径6',
    '长方体 长100宽80高20内腔长30宽20深5',
]
for text in cases:
    result = parse(text)
    print(text, parse_clauses(normalize(text)),
          [(f.kind, f.op, f.params) for f in result.doc.features],
          result.warnings, result.questions)
'@ | python -
```
