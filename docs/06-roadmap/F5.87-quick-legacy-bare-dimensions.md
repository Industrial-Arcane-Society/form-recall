# F5.87: Legacy Quick bare dimensions

## Legacy behavior

On baseline `c6e1926`, direct calls to `Parser().parse(...)` in `src/legacy/ai_modeler/core/parsing/nlparser.py` confirmed:

- `100x60x20` and `100 60 20` both return `ok=true`, `recognized=1`, and step `长方体 100×60×20 mm`.
- Both create a box with dimensions `length=100`, `width=60`, `height=20`, `corner=0`, `corner_mode='fillet'`, `center=(0,0,0)`, `base=true`, and `axis='Z'`.
- `孔距100，数量60，深20` returns one `hole` feature, not a box. `100x60x20 M8内六角螺栓` is recognized by the old part library as a screw.

The legacy path is `Parser.parse` → clause handling → `_looks_like_bare_dims` → `make_box` → `pick3`; the parser extracts the three values in order. `ParseResult` starts with `Document('Part1')`.

## Rust compatibility behavior

Rust previously recognized an `x`-separated dimension triplet but did not infer a base shape, so the bare input required clarification. It now infers a box only when the entire normalized input consists of exactly three positive numbers separated by `x`/`×` or whitespace, optionally followed by a unit. This restores both verified legacy forms while preventing dimension-looking substrings in semantic prose from selecting a box.
