# F5.78：建立旧 Python Quick 与 Rust Quick 语义差异审计

## 背景

F5.73 的快照比较器只比较两个时间点的 Rust 结果；它不能发现“旧 Python 与当前 Rust 输出本来就不一样”。本项新增 `tools/compare_quick_legacy_parity.py`，直接使用 `audit_quick_legacy_samples.py` 已保存的同输入双端结果，比较成功状态、特征数量/种类/操作、旧端实际参数、包围盒和体积差异。

## 比较边界

- 状态、特征签名和旧端具有值的几何参数作为语义差异报告；可用 `--max-state-mismatches`、`--max-feature-signature-mismatches` 和 `--max-parameter-mismatches` 设置失败门禁。
- `segments`、`rings` 等旧网格细分字段单独报告；解释文本与标准说明也单独报告，不与几何参数混为一类。
- 包围盒按毫米容差报告。
- 旧 Python 的三角网格体积统计与 Rust/OCCT 的 B-Rep 体积统计可能使用不同算法。因此体积差仅作诊断，默认不作为通过/失败条件。

## F5.75 后目录快照发现

对 `quick_legacy_catalog_baseline_after_f5_75.json` 的 66 个输入运行后：

- 旧端成功、Rust 完成的配对共 60 项；状态不匹配为 0。
- 发现 1 行特征签名不一致：`螺母` 旧端为圆柱参数体，Rust 为八边形棱柱。F5.61 记录了该项的拓扑修正缘由；本工具保留这个差异供整体兼容验收审查。
- 发现 5 行旧端几何参数差异、4 行网格细分差异、2 行说明文本差异，以及 1 行包围盒超过 `0.02 mm` 的样例。最大包围盒差异来自“多槽带轮”，Z 尺寸相差约 `4.1394 mm`。
- 配对样例的对称体积相对差 `abs(old-rust)/max(abs(old),abs(rust))` 中位数约 `0.1423%`，最大约 `85.0758%`；体积差超过 1% 的样例为 15 个。其中高差异样例需要结合旧网格与 Rust B-Rep 的具体构造器逐项核验，不能只凭状态或包围盒一致宣称形状等价。

这些结果是差异清单，不是迁移完成声明。后续须依据旧 Quick 的 `Parser.parse`、旧特征构造和新 OCCT 构造逐项归因；确认真实几何差异后再修复和复跑，而不是把 mesh/B-Rep 体积差一概视为精度误差。

## 66 个目录样例之外的旧 Quick 成功路径（原审计时状态）

目录的 66 个分类名与旧 `partlib.PARTS` 的 66 个分类名一一对齐；逐个把分类裸名称交给旧 `Parser.parse` 检查，没有发现额外的“仅输入裸分类名即可成功建模”类别。这个结果只说明分类名称集合对齐，**不代表 Quick 的通用语法、特征组合和默认行为已经覆盖完整**。以下三条输入不属于 66 个目录样例，均已通过旧 Python `Parser().parse(input)` 实测。下面关于 Rust 未运行或行为可能有差异的判断，是这份历史审计编写时（F5.78）的状态；请以随后 2026-10-08 的当前复核为准。

### 多主体连续添加

- 最小输入：`圆柱直径20高30，再做一个长方体长100宽60高20`
- 旧 Python 实测：`ok=true`，生成两个 add 特征：`cylinder(radius=10, height=30, center=[0,0,0], base=true, axis=Z, segments=48)`；`box(length=100, width=60, height=20, corner=0, corner_mode=fillet, center=[0,0,0], base=true, axis=Z, stack=true)`。旧解析器在 `Parser.add()` 检查已有实体并给后续主体设置 `stack=true`（`src/legacy/ai_modeler/core/parsing/nlparser.py:1235`）。
- Rust 代码事实：当前通用解析器收集到多个基础体类型时返回 `multiple_base_shapes`，见 `src/apps/desktop/src-tauri/src/native_quick_parser.rs:314-320`。
- 待运行核验：未启动 Rust parser；需要后续通过可运行的 Rust Quick 入口确认此输入实际返回状态及错误内容。

### 圆形盲凹槽

- 最小输入：`圆柱直径50高40，然后圆形凹槽直径20深5`
- 旧 Python 实测：`ok=true`，生成 `cylinder(radius=25, height=40, ...)`，以及 `hole(operation=cut, diameter=20, through=false, depth=5, axis=Z, pos=center, segments=48)`。旧 `make_pocket()` 对圆形凹槽转为圆形盲切（`src/legacy/ai_modeler/core/parsing/nlparser.py:1644`）。
- Rust 代码事实：通用切槽路由会把含“槽”的子句交给 `build_slot()`；该函数只对“圆槽/圆形槽”等词显式拒绝圆形轮廓，其他未给 length/width 的矩形槽会应用 `20×20×5 mm` 默认值（`src/apps/desktop/src-tauri/src/native_quick_parser.rs:12793-12840`）。现有 `quick_legacy_pocket_aliases_audit.json` 未含该圆形凹槽用例。
- 待运行核验：以上源码路径提示该短语可能落成矩形 pocket，但本次没有 Rust 执行证据；应通过运行输出确认，不把代码推断写成已观察到的结果。迁移时应生成圆形盲切，或明确拒绝缺少圆形尺寸的输入，不能把圆形直径静默解释成矩形槽长宽。

### 未定位通孔默认中心

- 最小输入：`长方体100x60x20，然后打直径8通孔`
- 旧 Python 实测：`ok=true`，生成 `box(100,60,20)` 和 `hole(operation=cut, diameter=8, through=true, axis=Z, pos=center, segments=24)`。旧 `make_hole()` 在没有其他位置描述时初始化 `pos='center'`（`src/legacy/ai_modeler/core/parsing/nlparser.py:1530-1541`）。
- Rust 代码与测试事实：`build_hole()` 没识别到中心、四角、PCD 或坐标时增加 `hole_position_missing` 澄清项（`src/apps/desktop/src-tauri/src/native_quick_parser.rs:12165-12166`）；现有单测 `standalone_box_uses_legacy_defaults_and_unpositioned_holes_request_clarification` 也把该行为写为预期（同文件约 `14057` 行）。这条差异不在已保存的旧目录快照输入中。
- 待运行核验：没有运行 Rust parser。若后续选择兼容旧默认中心，应将位置来源标记为 `derived` 并附警告；若坚持要求显式位置，则应把它记录成有意的行为变化，而非遗漏的等价迁移。

以上三个旧解析结果和 Rust 差异判断保留为 F5.78 原审计时的记录。旧 parser 成功只证明当时生成了结构化特征，不等于导出网格或 CATIA B-Rep 验收；当时 Rust 侧没有运行对拍。当前 headless 表面对拍状态见下方 2026-10-08 复核。

## 2026-10-08 当前复核

F5.78 原审计后，三条固定路径已分别由后续实现覆盖：圆形盲凹槽见 [F5.80](./F5.80-quick-round-blind-groove.md)，顺序异种主体添加见 [F5.88](./F5.88-quick-sequential-mixed-base-stacking.md)，未定位单个通孔默认中心见 [F5.90](./F5.90-quick-legacy-unpositioned-through-hole.md)。2026-10-08 保存的 headless 实测输出将各自旧 Quick `Document.build()` raw 网格与 Rust Quick 网格作同世界坐标固定采样对比；本次复核读取现有 STL 与 comparison JSON，没有重建或重跑：

| 固定输入 | 旧 raw → Rust sampled max (mm) | Rust → 旧 raw sampled max (mm) | 采样阈值 | 网格/实体状态 |
|---|---:|---:|---:|---|
| `圆柱直径50高40，然后圆形凹槽直径20深5` | 0.039296 | 0.039333 | 0.08 mm | 旧 raw 非闭合多组件；Rust 为闭合单体 |
| `圆柱直径20高30，再做一个长方体长100宽60高20` | 0.029498 | 0.025351 | 0.08 mm | 旧 raw 非闭合多组件；Rust 为闭合单体 |
| `长方体100x60x20，然后打直径8通孔` | 0.030211 | 0.027372 | 0.08 mm | 旧 raw 非闭合多组件；Rust 为闭合单体 |

三例各方向固定表面采样最大值均低于 `0.08 mm`。这是采样结果，不是连续 Hausdorff 距离上界；旧 raw 网格自身不满足闭合单实体条件，因此其 signed volume 不作为有效实体体积。上述比较只用旧 `Document.build()` raw 与 Rust Quick 输出；**不混用**旧 `Document.build_brep()` 的体积或表面结果。旧 raw/Rust STL、comparison JSON 和来源摘要见[固定样本证据包](../../artifacts/f5.78-legacy-quick-parity/README.md)。

因此这三条固定输入已从“Rust 尚未实测”的待迁移清单移出。它们仍是窄语法/固定样例验收，不证明周边变体、完整旧 Quick 语法、CATIA 或可见 GUI 已通过。
