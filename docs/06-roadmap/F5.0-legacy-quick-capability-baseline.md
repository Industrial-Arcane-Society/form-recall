# F5.0：旧 Python Quick 能力基线

## 基线目的

以旧版 Python Quick 的真实入口和代码行为作为迁移对照，避免把 `Document` 声明的特征种类、自然语言解析成功、几何构建成功和桌面导出成功混为一谈。本文按仓库 `main` 在 `425749a` 的状态盘点；后续迁移应为每项语法固定 Python 输出、Rust 输出和几何验收证据。

## 旧版真实调用路径

### Tk 桌面 Quick

旧桌面端在 `src/legacy/ai_modeler/ui/app.py` 中区分 `quick` 和 `agent`。Quick 明确走本地内置解析规则，不调用 LLM：

1. `generate()` 检查文字/图片输入；Quick 附图时明确拒绝本次请求并保留图片，提示切换到 Agent 模式。
2. Quick 发送调用 `_finish_generate(text, None)`。
3. `_finish_generate()` 调用 `NLP.parse(text)`；解析成功后替换活动 `Document`、显示解析步骤和警告、刷新特征树，再由 `run_build()` 调用 `Document.build()` 生成网格。
4. 解析失败时清空当前预览；旧 Tk UI 可在联网设置开启时另行触发在线查询。该在线查询不是 Quick 的本地解析结果，也不应算作解析器能力。

对应位置：`app.py:1083-1142`、`app.py:1744-1801`、`app.py:1803-1835`。

### 独立 JSONL bridge

`src/legacy/ai_modeler/ui/bridge.py` 另有 `model.quick_build`：拒绝空描述，默认新建模型并调用 `NLP.parse(text)`；成功后异步构建并返回步骤、警告和识别数量。解析失败时，若旧 `online.enabled` 配置开启，会附带 `online_suggestion`。这条 JSONL bridge 是独立入口，不是当前桌面 Vue Quick 的调用链。

对应位置：`bridge.py:334-365`。当前桌面 Vue 在 `src/apps/desktop/src/App.vue` 调用 Tauri Rust `quick_build`；不能把 Python bridge 的行为描述成当前桌面生产路径。

## Python 解析器实际范围

入口为 `nlparser.parse(text).doc`，实现位于 `src/legacy/ai_modeler/core/parsing/nlparser.py`。解析大体按以下优先级处理：

1. 文本规范化、尺寸抽取和子句切分；按特定规则合并跨子句的尺寸与零件描述。
2. 零件库匹配及复合模板。
3. 圆角/倒角、孔位修饰、孔、凹槽、阵列。
4. 回转、拉伸、圆柱/长方体/齿轮/圆锥/球体等基本体。
5. 草图/轮廓以及裸尺寸回退。

具体分派可见 `nlparser.py:680-760`、`980-1157`。解析器提供长方体、圆柱、圆锥、球体、齿轮、草图、拉伸、回转、孔、凹槽、圆角/倒角和线性/圆周阵列等构造路径，也能调用 `parts.partlib` 生成标准零件特征。此清单表示代码中的解析分支，不表示每种输入都能被稳定识别或成功生成有效几何。

旧版显式复合模板包括叶盘、叶片、法兰、阶梯轴、套筒/圆管，见 `nlparser.py:1752-1868`。旧解析器会对缺少的部分尺寸使用默认值，例如长方体补齐尺寸时默认 `100×60×20 mm`，法兰默认外径 120 mm、厚 20 mm，套筒默认外径 60 mm、长度 80 mm，阶梯轴无尺寸时建立三段默认轴。具体默认行为按解析分支而异，不能把它们表述为图像估算或用户给定值。

解析器还可能在未识别的附加子句上写入 warning，同时保留已识别的主体特征。迁移验收必须分别比对 `recognized`、warning、Feature 顺序/参数和最终几何，不能只检查 `ok=true` 或特征数量。

## 从 Python 描述到可见结果

- **解析结果**：有序 `Feature` 列表，含类型、`add/cut` 操作和参数；规则解析器可带默认值和 warning。
- **旧几何结果**：`Document.build()` 使用旧 Python 多边形几何内核生成网格；这和 Rust/OCCT 的 B-Rep 实体不是同一种证据。
- **工程及导出**：旧应用/bridge 有工程读写及网格、文本报告和 CATIA 脚本等出口；任一出口可用都不等于 CATIA 已实际打开并验收。
- **视觉/UI 结果**：旧预览展示 Python 构建出的网格；不能由 parser golden 或 OCCT CLI 测试替代桌面 UI 验收。

`Document.KIND_LABELS`（`src/legacy/ai_modeler/core/model/docmodel.py:89`）列出的名称不是 Quick 语法覆盖表；必须追到 parser 分支、几何 builder 和实际调用入口，才能认定某项旧 Quick 能力。

## 后续逐项迁移与完成条件

每个迁移项都按以下层次新增固定 fixture，并单独验收/提交：

1. **入口与解析**：固定旧 Quick 用户输入；记录 Python `ParseResult`、有序 Feature 参数/来源/warnings，与 Rust 输出逐字段对照。旧默认与 Rust 更安全的澄清行为分开列明，不暗中混成兼容。
2. **几何**：针对旧 Quick 真正支持且当前 Rust 接受的输入生成确定性模型；检查有效闭合实体、外形尺寸、切除/孔位置和体积等有物理意义的指标。只过 schema 不算几何通过。
3. **工程与导出**：对代表性模型保存 AIMODEL、重新打开并重建，再验收支持的网格格式；CATIA 结果单独做真实 CATIA 验收。
4. **桌面入口**：确认当前 Vue/Tauri Quick 调用 Rust 路径，验证可见预览、特征树和失败提示；旧 Tk/JSONL 行为不能作为当前桌面端证据。

不支持的旧输入应返回明确 unsupported/needs-clarification，并说明差异；不得静默遗漏特征后仍声称兼容。F5.24 已为叶片/叶盘建立独立 legacy fixture；后续从 Python 实际 Quick 模板与 parser 分支继续选取单项迁移。
