# F5.15：Quick 多矩形槽

## 范围

迁移旧 Python Quick 的多矩形槽行为：`make_pocket()` 会将一个数量大于 1 的槽描述展开成多个 `pocket/cut` 特征，并按 `pitch = 1.5 × 槽长` 沿 X 轴整体居中。本项只覆盖槽长、槽宽、槽深及数量均可读取的描述，不迁移缺尺寸默认值。

## Python oracle

输入为 `长方体 长100宽60高20，铣两个 20×8 深2 的槽`。oracle 是旧入口 `nlparser.parse(text).doc.to_dict()`；完整结果见 [`quick_multiple_slot_contract.json`](../../src/apps/desktop/src-tauri/tests/fixtures/quick_multiple_slot_contract.json)：

- 主体为 `100×60×20 mm` 长方体。
- 槽数为 2；每个槽长 20 mm、宽 8 mm、深 2 mm；最终切除位置 `x=-15 mm` 和 `x=15 mm`。旧 parser 警告说明采用 30 mm（1.5×槽长）间距并居中。
- 两个槽合计去除 640 mm³，旧几何目标体积为 119360 mm³。

## Rust 迁移

- `build_slot()` 读取受限的阿拉伯数字或单字中文数量，加上 `20×8` 这样的长宽对和显式深度，然后展开为独立 pocket 特征。长宽对仅用于 Quick 矩形槽解析，不改变其他特征的 dimension grammar。
- 每个展开特征有独立 ID；显式槽尺寸保留 user source，位置 `x` 及旧默认的 `axis=Z`、`corner=0` 标为 derived。
- Rust 复刻旧 parser 的固定 1.5×槽长间距和 X 居中位置，并返回 `slot_array_legacy_spacing` 警告。旧 Python 实际也不应用描述中的显式间距或 XY 位置；Rust 会在警告中指出这一点。
- 数量冲突、0、非整数或超过 4096 时要求澄清，不生成 CADPlan。此处对异常槽数采取显式拒绝，不复刻旧实现把 0 当作单槽默认值的行为。
- 缺失槽长、宽或深仍要求用户补充；旧 Python 的 `20×20×5 mm` 默认值是后续迁移缺口。

## 验收

- Python oracle fixture 与 Rust parser 测试核对两个 pocket 的顺序、参数、X 位置和来源，并覆盖 0 数量及相互冲突数量的拒绝。
- Rust Quick parser **20/20** 通过。
- OCCT 集成实测得到 3 个实际构建特征（主体加两个槽）、有效闭合实体 1 个、包围盒 `100×60×20 mm`、体积 `119360.00000000006 mm³`；AIMODEL/STL 导出及 AIMODEL 重载通过。
- F5.12 五个固定几何场景和普通盲孔控制在本次解析器与特征 ID 改动后重新通过。
- 几何证据来自 Rust/OCCT 本地路径，不是 CATIA，也不代表旧 Python Quick 的全部槽语法已迁移。
