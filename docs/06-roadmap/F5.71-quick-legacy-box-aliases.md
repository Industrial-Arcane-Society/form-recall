# F5.71：迁移旧 Quick 基础箱体名称别名

## 范围

旧 Python Quick 支持若干把工件名作为长方体基础体的常用称呼；Rust Quick 原先只识别部分标准箱体名称，导致一组旧输入 `parse_failed`。本项新增窄范围的首词归一化：仅把有明确边界的开头名称转换为 `长方体`，尺寸解释仍交给现有 Quick 解析器。它不会把特征描述中间偶然出现的“箱体/铝板”等字样改写成基础实体。

## Python Quick 对照

| 输入 | 旧 Python 和 Rust 参数（长×宽×高，mm） |
|---|---:|
| `立方体 长20宽20高20` | 20×20×20 |
| `正方体 边长20` | 20×60×20 |
| `方块 20×20×20` | 20×20×20 |
| `矩形体 长20宽10高5` | 20×10×5 |
| `方形块 长20宽10高5` | 20×10×5 |
| `铝板 100×50×3` | 100×50×3 |
| `钢板 100×50×3` | 100×50×3 |
| `箱体 100×50×30` | 100×50×30 |
| `机座 100×50×30` | 100×50×30 |
| `基座 100×50×30` | 100×50×30 |

`正方体 边长20` 特意保留旧 Parser 的实际结果 `20×60×20 mm`；虽然名称与结果不一致，但此次目标是恢复旧 Quick 行为，不在兼容层内重定义尺寸语义。

## 几何与验证

10 个旧 Python 成功样例均用 Rust Release headless/OCCT 运行：解析状态为 `complete`，CADPlan 包含一个 box，几何报告通过、闭合实体数为 1，外包围盒与上表尺寸一致。解析结果同时加入 fixture 驱动的 Rust 契约测试。

- `cargo check --tests --manifest-path src/apps/desktop/src-tauri/Cargo.toml`：通过。
- Rust Release headless/OCCT 十例对照：通过。
- `git diff --check`：通过。
- Windows 定向 Rust 测试进程此前在此环境无法启动（`0xc0000139 / STATUS_ENTRYPOINT_NOT_FOUND`），所以契约测试已编译但未声称实际执行。
- 未做桌面 UI 或 CATIA COM 验收。

## 限制

这是旧 Quick Parser 兼容，不表示所有中文实体名已迁移。具体可接受别名仍受尺寸表达式和既有特殊模板的解析顺序影响；本功能优先覆盖了 10 个旧成功输入，并将其范围锁定在明确的前置实体名称。
