# F5.14：Quick 盲孔深度续写

## 范围

支持旧 Python Quick 可解析的一种常见写法：先描述一个明确的盲孔，再用紧邻的独立片段给出深度，例如：

```text
长方体 长100宽80高20，中心盲孔直径10，10mm深
```

Rust Quick 只在前一片段确认为盲孔、没有通孔语义、没有现有深度，且后一片段只包含深度值时，才把该片段合并到该孔。深度片段紧跟通孔、多个孔或已标注深度的孔时，返回 `hole_depth_continuation_unbound` 澄清项，不猜测它的归属。

## Python oracle 与数据差异

Oracle 是 `src/legacy/ai_modeler/core/parsing/nlparser.py` 的 `nlparser.parse(text).doc.to_dict()`，运行结果保存在 [`quick_blind_hole_continuation_contract.json`](../../src/apps/desktop/src-tauri/tests/fixtures/quick_blind_hole_continuation_contract.json)：

- 旧 parser 对示例生成中心盲孔：直径 10 mm、深度 10 mm、`through=false`、轴向 Z；`diameter` 和 `depth` 均来自用户描述，warning 为空。
- Rust parser 得到相同孔径、孔型、位置及深度，`depth` 的来源标记为用户输入。Rust 保留既有的 `legacy_implicit_dimensions_removed` 和未标单位时的 `unit_interpreted_as_mm` 警告，因此不要求 warning 数组与 Python 相同。
- 对普通中心孔，Rust CADPlan 省略 Python 会显式填入的默认 `axis=Z` 和 `segments=24`；几何执行器对缺省 axis 使用 Z，圆柱 B-Rep 不依赖该 segments 参数。本 feature 不扩大成对旧 parser 默认字段的迁移。
- 通孔后续深度、多个孔后的深度和不能安全归属的情况均无 CADPlan 输出，不会静默变成任一孔的深度。
