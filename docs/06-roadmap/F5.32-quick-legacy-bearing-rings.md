# F5.32：Quick 旧 Python 轴承圆环配方

## 迁移依据

旧 Quick 的真实解析入口是 `src/legacy/ai_modeler/core/parsing/nlparser.py::Parser.parse`，实际建模配方是 `src/legacy/ai_modeler/parts/library/partlib.py::_ring`。本轮固定了深沟球轴承、圆锥滚子轴承和推力球轴承的旧解析输出；三者都只生成外圆柱与中心贯穿孔，并未建立滚动体、保持架、滚道或密封件。

深沟球轴承可按完整的内径、外径、宽度描述建模；也可使用嵌入的 GB/T 276—2013 代号表，例如 `深沟球轴承 轴承代号6204` → 内径 20 mm、外径 47 mm、宽度 14 mm。圆锥滚子轴承使用内径、外径和总宽/装配高，推力球轴承使用内径、外径和高度。旧 Quick 在提供内外径而未提供宽度时会使用默认值，Rust 继续使用并标明其来源：深沟球轴承 14 mm、圆锥滚子轴承 16.25 mm、推力球轴承 3 mm。

旧 `_ring` 对推力球轴承实际回退到 3 mm；零件库的 TYPICAL 表虽写有 H=10 mm，但实际构造器未采用它。Rust 按可复现的实际输出使用 3 mm，并在警告与参数来源中指出该事实。

原始 Python Quick 输出和 Rust 解析契约记录于 [`quick_legacy_bearing_rings_contract.json`](../../src/apps/desktop/src-tauri/tests/fixtures/quick_legacy_bearing_rings_contract.json)。

## Rust Quick 行为

- 支持深沟球轴承、通用“轴承”别名、圆锥滚子轴承和推力球轴承的简化圆环配方；可使用旧 GB/T 276 深沟球轴承代号表的全部本地记录。
- 每个模型按旧顺序创建一个居中 Z 轴圆柱和一个中心贯穿孔。圆柱沿用 64 段设置，孔沿用 48 段设置。
- 代号尺寸优先于同一句中单独写的尺寸，与 Python 实际输出一致；Rust 会发出明确警告，避免用户误以为外径等文字覆盖了标准代号。
- 旧配方缺少宽度时沿用对应历史默认值并标为 `derived`；缺少内径或外径时要求补充，不把球体回退结果称作轴承。
- 额外的滚动体、保持架、密封件、孔槽、倒角、圆角或螺纹请求返回 `unsupported`，避免默默只建一个简化圆环。

## 与旧解析器的差异

- `深沟球轴承 内径20 外径40 宽12` 在旧 `Parser.parse` 的分句路径中被回退为半径 20 mm 的球体。Rust 将“宽12”绑定为宽度，生成 40×40×12 mm 的圆环。
- 只有 `深沟球轴承 内径20` 时，旧 Parser 把内径误当作球体尺寸；Rust 要求补齐外径。
- `深沟球轴承 6204 外径50` 在旧 Parser 中按代号得到 47 mm 外径，静默忽略显式 50 mm。Rust 保持相同几何，但会警告代号覆盖了同句尺寸。
- 旧 Parser 会静默忽略附加密封/滚动体等结构；Rust 将这些请求标记为不支持，不将缺失部件伪装成完整轴承。

## 验收结果

- Python oracle 解析与 Rust parser 定向合同测试：`native_quick_parser::tests::legacy_bearing_ring_recipes_match_python_oracle_and_provenance` 通过。校验了各轴承家族、参数来源、标准代号、历史默认值、错误输入边界、CADPlan schema 与几何 preflight。
- 本地 OCCT 集成验收：`native_quick::acceptance_tests::f5_32_legacy_bearing_rings_build_reopen_and_export` 通过 7 种输入。每个输入均得到 1 个有效闭合实体；包围盒匹配，体积相对旧 Python 网格差约 0.119%–0.145%，低于 0.3% 阈值。
- 每个样例均完成 AIMODEL 保存和重载，并生成 GLB、STL、OBJ；重载后的 CADPlan 特征与构建结果一致。
- OCCT 验收只证明本地 Rust 几何与文件输出，不表示真实 CATIA COM 已打开或验收。
