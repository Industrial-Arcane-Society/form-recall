## 资源与依赖现状

- 桌面 DSH 运行时由 Rust `dsh_runtime` 固定准备 Node 22.23.3 和 DSH `0.2.0-rc.2`，不读取系统 Node。
- Quick/CADPlan/本地网格由 Rust 原生实现，OCCT 运行时采用版本清单与 SHA-256 校验。
- 旧桌面 requirements 仍包含 NumPy、SciPy、Pillow、python-docx、DeepSeek Harness Python SDK、pywin32、CadQuery OCP 与 proxy。该依赖文件服务旧 Python bridge，当前仍有可达兼容入口，不能在本提交中错误替换成 CATIA-only 清单。
- 本提交新增 `desktop-catia-requirements-win-x64.txt`，仅固定 `pywin32==312`。资源 builder 验证 CPython 3.13.16 官方 embeddable ZIP 与 CPython 3.13 x64 pywin32 wheel 哈希，并生成 CATIA 专用 manifest；运行时仅在 CATIA 操作发生时将 Python 与 pywin32 解包到 Tauri 应用私有 LocalAppData 数据目录下的 `runtime/catia-python`。
- pywin32 wheel 的固定版本、下载文件名与哈希来自 [PyPI pywin32 312 官方 JSON](https://pypi.org/pypi/pywin32/312/json)；构建器再对下载文件做本地 SHA-256 校验。
- CATIA 私有运行时在独立目录安装，不会复用或删除旧 `runtime/python`；新建/失效运行时清理前先限定到私有 `runtime` 子目录并拒绝符号链接。
- Builder 仅忽略 `src/legacy` 测试目录与 Python cache。尽管数据集、工具脚本和示例会增加资源体积，它们仍被 legacy backend、CATIA 集成菜单和原生知识库中的视觉样本读取；在 bridge 与菜单迁移验收前不能安全删除。
