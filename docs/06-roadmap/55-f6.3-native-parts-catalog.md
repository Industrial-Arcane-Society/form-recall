# F6.3：Rust 原生零件目录与示例列表

## 输入与范围

- 旧输入契约：`PythonBridge.dispatch("parts.list", {"query": text}, request_id)` 与 `PythonBridge.dispatch("samples.list", {}, request_id)`，定义在 `src/legacy/ai_modeler/ui/bridge.py`。
- `parts.list` 的数据源为 `ai_modeler.parts.partlib.PARTS`、`partlib.load_kb()["by_category"]` 和 `ai_modeler.ui.examples.SAMPLE_VALUES`。旧 Python 路由负责按类别/别名子串过滤，并按 `PARTS` 的插入顺序返回 `category`、`aliases`、`params`、`manual_count`、`sample_prompt`。
- `samples.list` 返回 `ai_modeler.ui.examples.SAMPLES` 原有的 label/prompt 顺序。
- 本 feature 只迁移桌面端这两条只读显示路线。目录元数据和描述示例不能作为几何内核已经实现相应零件的证据。

## 成功标准

1. Rust 嵌入快照逐项等于旧 Python 两个 dispatch 路由的输出：零件字段、参数别名数组、每类计数、示例描述、零件行顺序以及文本样例顺序均对拍。
2. Rust `native_parts_list` 保留旧类别/别名大小写不敏感子串过滤；空查询返回所有行，未知查询返回空数组。
3. Vue 的目录面板和常用文本示例改走 Rust invoke 命令，不再调用 Python `parts.list`/`samples.list`。界面明确说明示例文本不代表几何内核支持对应零件。
4. Rust CLI 能输出完整 snapshot、筛选后的 parts 和 samples，且不启动 Tauri 窗口、Python bridge、DSH 或 CATIA。

## 失败样例

- 查询 `no-such-part-catalog-entry`：成功响应空数组，不报错，也不退回 Python。
- 仅更新旧 Python 的 `PARTS`、KB 计数或 `SAMPLES`：对拍脚本必须失败，直到显式刷新 Rust 嵌入快照并重新对拍。
- 空白查询：返回全部 66 个类别；不能因空字符串匹配失败而隐藏目录。
- 禁止把“目录含某类零件”解释成“当前 Rust/OCCT 几何内核能生成该类零件”；此目录没有承载能力声明。

## 可复现命令

从仓库根目录运行：

```powershell
python src/apps/desktop/src-tauri/examples/native_parts_catalog_parity.py
pwsh -NoProfile -Command '$old = $env:TAURI_CONFIG; try { $env:TAURI_CONFIG = ''{"bundle":{"resources":[]}}''; cargo run --manifest-path src/apps/desktop/src-tauri/Cargo.toml --example native_parts_catalog_cli -- snapshot } finally { $env:TAURI_CONFIG = $old }'
cargo test --manifest-path src/apps/desktop/src-tauri/Cargo.toml --lib native_parts_catalog --offline
node --test src/apps/desktop/src/nativePartsCatalog.test.mjs
```

`native_parts_catalog_parity.py --write-snapshot` 是显式的数据刷新步骤。日常对拍默认只读，不会改写嵌入数据。

## 剩余限制

- 快照来自本次旧 Python bridge 实际输出，共 66 个零件目录行和 17 个文本样例。后续旧 metadata/知识库计数变更需要主动刷新快照并跑 parity 命令。
- `sample_prompt` 只是旧界面拼出的文本建议，不会创建零件，也不保证文本 Quick 或 Agent 能成功建模。
- Rust 搜索沿用目前所有目录名称/别名的 case-insensitive 子串行为；当前已收录字符串的 Unicode lower/casefold 结果相同。
