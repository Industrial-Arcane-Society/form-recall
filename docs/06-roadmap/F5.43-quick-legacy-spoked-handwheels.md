# F5.43：Quick 旧 Python 辐条手轮

## 迁移依据

旧版 Quick 入口为 `src/legacy/ai_modeler/core/parsing/nlparser.py::Parser.parse`，零件库配方是 `src/legacy/ai_modeler/parts/library/partlib.py::_handwheel`，多边形几何由 `src/legacy/ai_modeler/core/geometry/kernel.py::make_spoked_wheel` 生成。旧名称包括“辐条手轮”“辐条轮”“手轮”和“方向盘”。Oracle 输入、旧有序特征、warning、外形尺寸和旧 mesh 统计保存在 [`quick_legacy_spoked_handwheel_contract.json`](../../src/apps/desktop/src-tauri/tests/fixtures/quick_legacy_spoked_handwheel_contract.json)。

旧参数含义有容易误解的部分：`D` 是手轮外径；`H` 是轴向厚度；`d`（零件库别名含“内径/孔径”）实际用于计算轮毂外半径 `max(5, d/2)`，并非中心孔直径。配方默认 `d=20 mm`、`z=5`；轮缘宽度是 `max(3 mm, 0.06×D)`；未给辐条宽度时使用 `max(4 mm, 0.22×(outer_r-hub_r))`。手轮本体的中心孔半径固定为 `max(1 mm, 0.35×hub_r)`。旧 Parser 还会把明确写出的“中心孔 直径 N”追加成一个 Z 向贯穿孔特征。

## Rust Quick 行为

- 外径 `D` 与厚度 `H` 必须明确；缺少时要求补齐。旧 Parser 对“手轮 外径 100 高度 10”会退回普通圆柱，Rust 将其澄清为手轮厚度，避免把圆柱误认为手轮；若同时给出互相冲突的高度与厚度，也要求确认。
- 支持旧名称及其 `D/d/H/z` 字母参数。`d`、`z` 可沿用旧典型值并记录来源；`d` 的轮毂语义会显示 warning。尺寸默认按 mm 解释；中心孔大于或等于外径时要求核对，避免切除整个轮体。
- 辐条数沿用旧几何真正使用的下限 2；低于 2 的输入会按实际生成的 2 根辐条建模并给出 warning。小数要求澄清，超过原生几何上限 512 时返回 unsupported。
- 辐条宽、轮缘宽和中心位置使用旧配方的确定公式。显式同轴中心孔可作为第二个贯穿切除特征。键槽、非中心孔、轮缘/轮毂修饰及其他组合特征尚未迁移，会明确返回 unsupported。
- 本地原生几何将轮缘、轮毂和辐条布尔融合为一个闭合 B-Rep 实体；CATIA 映射仍为近似，不在本项中宣称 CATIA 原生手轮特征已验收。

## 验收

解析合同测试 `native_quick_parser::tests::legacy_spoked_handwheels_match_python_oracle_and_native_boundaries` 对照 Python Quick fixture，覆盖四个旧名称、明确参数、`d/z` 缺省、旧两根辐条下限、中心孔、缺少尺寸、错误“高度”别名、小数辐条数和未迁移键槽；所有生成 CADPlan 均通过 schema 校验和原生 preflight。

OCCT 集成测试 `native_quick::acceptance_tests::f5_43_legacy_spoked_handwheels_build_measure_reopen_and_export` 实际生成 5/6 根辐条、默认值、旧下限钳位和中心孔样例。全部结果为单一有效闭合实体；包围盒分别为 `100×100×10`、`120×120×12`、`100×100×10`、`100×100×10` 和 `100×100×10 mm`。B-Rep 体积分别为 `35504.31488898279`、`66525.84163028654`、`35504.31488898279`、`26486.92402745602` 和 `32747.567335457763 mm³`。五例均通过 AIMODEL 重载及 GLB、STL、OBJ 文件生成检查。

旧多边形几何将轮缘、轮毂与辐条直接拼接，没有布尔融合。旧 `volume_of` 对两个未切孔样例报告 `119279.71430166933 mm³` 和 `212197.90631328546 mm³`；这不是融合后单实体的体积，因此不作为新 B-Rep 的同口径体积断言。迁移验收改用确定参数、包围盒、闭合有效实体、原生 B-Rep 体积、工程重载和导出结果。
