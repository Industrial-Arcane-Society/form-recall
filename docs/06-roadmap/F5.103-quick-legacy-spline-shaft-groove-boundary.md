# F5.103：旧 Quick 花键轴凹槽 modifier 差异基线

## 固定输入与旧入口证据

固定提示词：`花键轴 小径20 大径25 长度40 齿数8 键槽宽5`。本项实际运行旧 Python `Parser().parse → Document.build()` 并保存 raw binary STL；完整 Feature 参数/provenance、解析步骤、统计值和 SHA-256 见 [`legacy_raw_baseline.json`](../../artifacts/f5-spline-shaft-groove/legacy_raw_baseline.json)，网格为 [`legacy_document_build_raw.stl`](../../artifacts/f5-spline-shaft-groove/legacy_document_build_raw.stl)。复跑脚本为 [`capture_legacy_baseline.py`](../../artifacts/f5-spline-shaft-groove/capture_legacy_baseline.py)。

旧 Parser 成功并生成花键轴 prism 与 pocket cut 两个特征。旧 pocket 的 `Feature.provenance` 为空；结合提示词和旧通用凹槽规则可还原来源：只有 `width=5 mm` 来自用户输入的“键槽宽5”；未给槽长时回退为 `length=20 mm`，未给深度时回退为 `depth=5 mm`，`corner=0` 与 `axis=Z` 是旧构造默认值。旧 Parser 没有把这些默认值标记到 Feature provenance 中。

旧几何实现将该特征放在正 Z 端面，而不是轴身侧面：花键主体从 `z=0` 拉伸到 `z=40 mm`；槽中心取主体 XY 包围盒中心 `(0,0)`，默认 `side=positive`。矩形刀具的平面范围为 `x=[-10,10] mm`、`y=[-2.5,2.5] mm`，Z 向从 `z=35 mm` 延伸至约 `z=40.00001 mm`；实际移除部分是该刀具与主体的相交体积。它因此是一个 +Z 端面中心盲矩形 pocket，不能称为工程侧键槽，也没有表达键槽的标准位置、配合或制造要求。

## Rust 窄迁移与验收

`parse_legacy_spline_shaft` 现在接受且仅接受本例的一个显式键槽宽度，并调用旧通用 `build_slot` 语义追加一个 `pocket/cut`。槽宽 5 mm 标记为用户输入；槽长 20 mm、深度 5 mm、corner=0、axis=Z 是 derived 默认；中心 x=y=0、从 positive Z 面切入也明确标记为 derived。Rust plan 只记录 `profile` 为 derived、`height` 为 user；不声称 d/D/z 有逐字段 plan provenance。警告说明“键槽”在旧 Quick 实际落成 +Z 端面中心 pocket，不是轴身侧键槽或制造定义。缺少宽度需要澄清；前置或后置的侧面/多槽表达（包括 `2个`、`一对`、`成对`）和其他 modifier 继续拒绝，不生成 plan。

旧 Python `Document.build_brep()` 另行实测成功，作为更强的实体 oracle：`brep_valid=true`、一个闭合 solid、bbox `[-12.4946,-12.4946,0,12.4946,12.4946,40] mm`、B-Rep 体积 `15251.808174272413 mm³`。其 pocket 深度测量为 +Z 面 `z=40` 到盲底 `z=35`，深度 5 mm，中心 probe `(0,0)`。可复跑捕获脚本和完整报告分别为 [`capture_legacy_brep_oracle.py`](../../artifacts/f5-spline-shaft-groove/capture_legacy_brep_oracle.py) 与 [`legacy_brep_oracle.json`](../../artifacts/f5-spline-shaft-groove/legacy_brep_oracle.json)，固定 B-Rep 三角化网格为 [`legacy_document_build_brep.stl`](../../artifacts/f5-spline-shaft-groove/legacy_document_build_brep.stl)。

ignored Rust 几何验收通过：一个 valid、闭合实体，feature 顺序为 prism 后接 pocket；bbox 与旧 oracle 相同，实体体积 `15251.808174272415 mm³`，pocket cut 体积变化 `-496.6130473275862 mm³`。这项窄测会将 headless Quick STL 复制到 artifact。旧 B-Rep 与 Rust native Quick STL 均为 240 三角形、焊接后 122 顶点、闭合单组件；旧 raw STL 为 810 三角形且有 150 条边界边，仍只作独立 raw surface 诊断，不作为实体/体积 oracle。

[`surface_comparison.json`](../../artifacts/f5-spline-shaft-groove/surface_comparison.json) 记录两种独立对照，均使用 `.08 mm` 表面阈值、`1e-5 mm` 焊接阈值、投影级别 64/128/256：

- 旧 raw vs Rust：双向 sampled max `4.32502654e-7 mm`，bbox max delta `0`；通过采样表面阈值。旧 raw 的边界拓扑差异单独保留，不用其 signed mesh volume 作通过条件。
- 旧 valid B-Rep oracle vs Rust：双向 sampled max `5.01252405e-13 mm`，bbox max delta `0`；采样表面通过，拓扑同为闭合单组件。两端三角形数量同为 240，采样最大差约 `5.0125e-13 mm`。
- 旧 raw vs 旧 B-Rep 的直接采样双向 max 为 `4.32502654e-7 mm`，bbox max delta `0`；采样表面几乎重合，但 raw 仍有 150 条边界边，B-Rep 则闭合。比较 JSON 将两者拓扑分别保留。

比较器对每个三角面做四个确定性重心内采样，再以点到三角面距离计算双向统计；这是离散采样近似，不是连续 Hausdorff 上界。包装报告把 raw-vs-Rust 的体积状态显式标成 `not_comparable_open_raw_mesh`；保留 signed-volume delta 与 comparator allowance 数值，但 allowance 只作 `diagnostic_only`。旧 raw 与旧 B-Rep 的体积/拓扑含义不同，不混合为一个 oracle。CATIA 和桌面 UI 未验证。

## 复跑

在仓库根目录 PowerShell 执行：

```powershell
$env:PYTHONPATH = 'src/legacy'
$env:CARGO_BUILD_JOBS = '1'
python artifacts/f5-spline-shaft-groove/capture_legacy_baseline.py
python artifacts/f5-spline-shaft-groove/capture_legacy_brep_oracle.py
$env:AIMODELER_TEST_OCCT_MANIFEST = (Resolve-Path 'src/apps/desktop/src-tauri/target/debug/occt-runtime/runtime-manifest.json').Path
$env:AIMODELER_F5_103_RUST_STL_OUT = (Join-Path (Get-Location).Path 'artifacts/f5-spline-shaft-groove/rust_native_quick.stl')
cargo test --lib native_quick_parser::tests::legacy_spline_shafts_match_python_oracle_and_default_provenance -- --exact --nocapture
cargo test --lib f5_103_spline_shaft_legacy_generic_pocket_builds_closed_brep_and_exports_stl -- --ignored --nocapture
python artifacts/f5-spline-shaft-groove/compare_legacy_raw_to_rust.py
```

Cargo 测试需串行运行（`$env:CARGO_BUILD_JOBS='1'`）。当前 Windows 环境的测试 exe 需要 Common-Controls v6 sidecar manifest 才能启动；本轮使用目标目录的临时 sidecar 复用已编译 exe，运行后已移除。`capture_legacy_baseline.py` 仅重建旧 raw STL；`capture_legacy_brep_oracle.py` 通过旧 `Document.build_brep()` 重建 B-Rep oracle；最后一个比较脚本独立记录 raw 与有效 B-Rep 两种对照。所有 SHA 和实测数值以 artifacts 中 JSON 为准。
