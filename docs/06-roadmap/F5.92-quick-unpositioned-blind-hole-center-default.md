# F5.92：单个未定位盲孔恢复中心默认

## Oracle 与范围

旧 Python `Parser().parse` 对 `长方体100x60x20，然后打直径8深5盲孔` 实际返回 `ok=true`、一个 box 和一个 hole；hole 参数为 `diameter=8 mm`、`through=false`、`depth=5 mm`、`pos=center`、`axis=Z`、`segments=24`，没有 warning 或 question。Rust Quick 仅在单主体、一个孔的句子里明确给出正直径、盲孔和正深度，并且没有位置、阵列、侧孔或其他 modifier 时，推导中心位置。直径和深度仍是 `user` 来源；推导位置、Z 轴和 24 段默认标为 `derived`，位置同时带有说明和 warning code `legacy_unpositioned_blind_hole_default_center`。

有意不迁移 Python 的计数缺陷：对 `5个直径8深5盲孔` 和 `五个直径8深5盲孔`，旧 Python 实际仍只输出一个中心盲孔；Rust 识别显式多孔计数并澄清，不将它们当成一个孔。因此此处不是完全 parser parity。Rust 还把 `深5`、`深5mm` 视为深度数值而不是孔数；没有明确盲孔词或孔特征时不会据此推导中心盲孔。

显式中心、坐标、阵列/多孔、侧孔、缺直径/深度、非正尺寸、贯穿孔和额外槽/沉孔/倒角/螺纹等修饰均不进入此默认路径。范围只增加普通单个盲孔的位置推导，不更改直径、深度或现有显式位置的来源绑定。

## 验收

- Parser 契约以旧 Python 正向原句对比 Rust；验证一个 hole、直径 8、blind depth 5、中心、Z 轴、derived 位置来源与历史 warning。
- Parser 负例验证无孔径、无深度、非正深度、缺失“盲孔”词、侧孔、阵列、显式多个孔和额外矩形槽均不会使用中心默认。单独断言 `5个/五个` 仍由 Rust 多孔识别，且 `深5` / `深5mm` 不会触发多孔计数误判；旧 Python 的 5/五行为如上列为已知兼容差异。
- OCCT 定向验收确认一个有效闭合实体、包围盒 `100×60×20 mm`、Z 轴中心 Ø8 盲孔、最终 B-Rep 圆柱段实际深度 5 mm、解析体积及 AIMODEL reload。
