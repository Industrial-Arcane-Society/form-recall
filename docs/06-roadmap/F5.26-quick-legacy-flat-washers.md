# F5.26 Quick 旧版平垫圈配方迁移

更新时间：2026-10-07

## 范围

将旧 Python Quick 的平垫圈圆环配方接入 Rust Quick。输入可使用“平垫圈”“平垫”或带明确内外径的“垫片”；当前只生成一个居中圆环，不包含弹簧垫圈开口、额外孔槽或组合零件。

## Python Quick 基准

通过 `Parser().parse()` 检查当前旧入口：

输入：`平垫圈 外径20 内径8 厚度2`

- `ok=true`、`recognized=1`，无 warning、assumed 或 questions。
- 有序特征 1：`cylinder/add`，`radius=10`、`height=2`、`center=(0,0,0)`、`base=false`、`segments=64`。
- 有序特征 2：`hole/cut`，`diameter=8`、`through=true`、`pos=center`、`segments=48`。
- 移除“厚度2”后旧 builder 仍用 `height=2`。Rust 保留这个旧默认，并在警告和 `sources.height` 中标记为默认值。
- 仅输入“平垫圈”时旧 parser 不识别；Rust 会请求补充外径和内径，不创建典型大小的猜测模型。

Python 解析器的原始验证发生在本轮实施时；本报告不把 Python 多边形网格或 CATIA 结果当作 Rust OCCT 几何验收。

## Rust 实现边界

- 在通用基础体解析前识别平垫圈描述，输出旧版顺序的圆柱主体和中心贯穿孔。
- 外径与内径必须用“外径/外圆直径”和“内径/内孔直径”明确给出，且为有限正数、外径大于内径；单位沿用 Quick 的毫米转换规则。
- 厚度未写时沿用旧 Python Quick 的 2 mm 默认值，并返回 `legacy_washer_thickness_defaulted` 警告及 derived 来源。
- 对尺寸冲突、缺失和无效值返回澄清项，不构造不完整模型。
- 弹簧垫圈、矩形垫片垫块、多个零件及额外加工要求均不通过此配方处理；弹簧垫圈明确返回 unsupported。
- 参数来源记录在每个 CADPlan 特征上，圆柱半径由外径推导，孔径取用户给定值。

## 验收状态

- Python 旧 Quick `Document.stats()`：包围盒 `20×20×2 mm`，208 个面、448 个三角形，网格体积 `527.065582484191 mm³`。
- Rust 桌面生产 Quick headless 路径，两种输入（显式厚度、默认厚度）均完成 parser → CADPlan 校验 → OCCT → GLB/STL/OBJ → AIMODEL 保存及重载。结果均为包围盒 `20×20×2 mm`、有效单一闭合实体、2 个特征、1 个已测量中心孔，OCCT 体积 `527.787565803085 mm³`；网格导出文件存在，AIMODEL 重载通过。
- Rust BREP 体积较旧 Python 网格高 `0.721983318894 mm³`（相对 Rust BREP `0.136794%`）。两者包围盒、外径、内径、厚度和中心孔一致；差值来自 Python 旧版 64/48 分段多边形圆环网格与 Rust 分析圆柱 BREP 的表示不同，不是按三角面逐面复刻。
- Rust 生产路径还通过 `平垫`、`垫圈` 与带内外径的 `垫片` 别名；缺尺寸、内外径倒置、零厚度、弹簧垫圈、复合请求和歧义“垫片”都按预期拒绝。
- Parser 合同 fixture 和 Rust 测试已添加。`cargo test` 的测试目标成功编译，但 Windows 在启动隔离测试 exe 时返回 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`；所以不把单元测试计为通过。替代运行证据是上述真实桌面 Quick headless 生产路径。
- `cargo check --manifest-path src/apps/desktop/src-tauri/Cargo.toml --lib --offline` 已通过。未做桌面窗口视觉验收或 CATIA 验收；这两项不属于本配方的已验证范围。
