# F5.33：Quick 旧 Python O 形圈与挡圈圆环配方

## 迁移依据

旧 Quick 的真实入口为 `src/legacy/ai_modeler/core/parsing/nlparser.py::Parser.parse`，配方位于 `src/legacy/ai_modeler/parts/library/partlib.py` 的 `_oring` 与 `_washer`。尽管零件名分别是 O 形圈和弹性挡圈，旧几何都只是居中圆柱加中心贯穿孔：O 形圈的圆截面没有建出来，挡圈的开口也没有建出来。

- O 形圈支持旧别名 `O形圈`、`O型圈`、`密封圈`；`内径20 外径26 线径3` 输出 26×26×3 mm 平环。缺少线径时构造器静默使用 2 mm。
- 挡圈支持 `孔用弹性挡圈`、`轴用弹性挡圈`、`挡圈`、`卡簧`；`内径20 外径25 厚度1` 输出 25×25×1 mm 闭合圆环。缺少厚度时旧配方静默使用 2 mm。
- O 形圈的 `截面直径3` 在旧解析器里被静默忽略，随后输出 2 mm 平环。Rust 将明确要求当前未支持的环面几何，不把圆截面直径当成轴向厚度。

Python 输出、已知解析差异和 Rust 期望记录在 [`quick_legacy_simple_rings_contract.json`](../../src/apps/desktop/src-tauri/tests/fixtures/quick_legacy_simple_rings_contract.json)。

## Rust Quick 行为

- 每个受支持输入生成圆柱加中心通孔，圆柱 64 段、孔 48 段，沿用旧配方的居中 Z 轴放置。
- 内径、外径必须明确且外径大于内径。旧构造器的 2 mm 默认厚度被保留，并标为 `derived` 且伴随警告。
- O 形圈额外出现 `截面直径`、`圆截面` 或 `截面尺寸` 时返回 `unsupported`。若用户明确要求圆截面，当前几何执行器没有对应环面建模，不用平环冒充。
- `O形圈 ... 厚3` 在旧 Parser 会退化为无孔圆柱。Rust 修复别名绑定，生成保留中心孔的平环，并警告该解析差异。
- O 形圈与挡圈附带额外孔槽、开口、密封结构或边缘加工时返回 `unsupported`。

## 验收结果

- Python oracle 定向合同测试：`native_quick_parser::tests::legacy_simple_seal_ring_recipes_match_python_oracle_and_provenance` 通过。检查别名、参数来源、默认值、修正/拒绝边界、CADPlan schema 与几何 preflight。
- 本地 OCCT 集成测试：`native_quick::acceptance_tests::f5_33_legacy_simple_seal_rings_build_reopen_and_export` 通过 4 种输入。每种都生成 1 个闭合实体，包围盒与旧 Python 一致，体积差为 0.020%–0.061%（低于 0.3%）。
- 四种样例均完成 AIMODEL 保存与重载，并产生 GLB、STL、OBJ；重新载入后的 CADPlan 与本次建模结果一致。
- 这些记录证明的是本地 Rust/OCCT 结果；不证明真实 CATIA 已运行，也不代表已迁移环面或开口卡簧几何。
