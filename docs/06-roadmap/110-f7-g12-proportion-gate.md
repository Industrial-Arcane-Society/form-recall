# F7.G12 host-computed proportion gate

`native_proportion_gate` adds an auditable silhouette-envelope check to the native aggregate review. It computes a dimensionless projected body width/height ratio from each reference image and a current native preview. For opaque images, background segmentation builds a compact RGB5 color palette from an inset perimeter (two pixels inside each edge), retains colors represented on at least two edges, and uses three color-distance thresholds. This supports ordinary gradients and repeated viewport colors such as grid lines without treating every non-corner color as foreground. Border-connected foreground residue smaller than 0.2% of the image is discarded as background; a larger component touching the frame is treated as possible crop and returns `unknown`. The largest interior component anchors the body envelope; nearby substantial components are included, small detached components such as axis markers are suppressed, and a substantial disconnected component outside the proximity bound returns `unknown`. The interval spans the observed ratios with an additional 8% margin. The gate compares intervals rather than a single point estimate.

RGBA images with a fully opaque alpha channel follow the RGB path. A genuinely transparent image is measured from alpha only if all four outer edges are transparent and at least 0.5% of the image is substantially opaque foreground; otherwise it returns an alpha-specific `unknown`. Alpha thresholds 16/64/128 form the segmentation sweep. This does not composite an ambiguous alpha matte over an invented background.

## Comparability and evidence binding

- `reference_similarity_history` supplies the previously reviewed pair identity and its `view_comparable`/`view`; the gate does not use score, findings, or the manifest for view labels. A row must bind the same reference ID/source SHA, current revision/generation/fingerprint, and a full-image pair (`roi_norm=null`). False comparability, missing/stale history, or view mismatch stays unknown.
- The matching view selects a native preview for that current geometry; the history `preview_sha256` must match both preview metadata and the current bytes. Projection comes from that preview's native `render_options`; the reference projection is not guessed independently because the vision review already establishes pair comparability.
- The original reference bytes must match the host manifest `sha256`.
- Image reads are capped at 20 MiB; decoded dimensions are capped at 16,384 per side and 16 megapixels with a 128 MiB decoder allocation limit. Hashing and decoding use the same in-memory bytes. Limit/decode failures return fixed unknown reason codes.
- Missing or false comparability in the current `reference_similarity_history` pair, a stale/missing matching preview, missing native projection metadata, pair/hash mismatch, textured or ambiguous background, or failed segmentation yields `unknown`. The aggregate preserves that status and reason as diagnostic evidence; unknown remains non-blocking so ordinary sessions without a current comparable visual-review pair are not rejected.
- Non-overlapping uncertainty intervals yield `mismatch`, adding a host aggregate reason and preventing finish. Overlapping intervals yield `consistent` for this one projected-envelope metric only.
- No-reference sessions return `not_applicable`; this check does not estimate absolute dimensions and does not replace detailed feature/geometry validation.

## Limits and verification

This compares a 2D silhouette proxy, not three independent 3D body dimensions. Background colors are quantized, so foreground colors close to the perimeter palette can be absorbed into the background; foreground/background regions that are connected in the binary mask can still confuse the component heuristic. Perimeters with more than 1,024 distinct RGB5 colors return `unknown`. Transparent input is usable only when transparency frames the subject; partially transparent backgrounds and subjects touching the frame remain unknown. The method is deterministic and dependency-free, but is not a general segmentation model.

The 8% guard band is a heuristic/tunable threshold, and the threshold sweep still needs a labeled real-image calibration set before either is treated as validated. In a read-only probe, all five archived reference images produced intervals; three of the four pin-part preview views produced intervals, while the ISO preview returned `silhouette_components_ambiguous`. These archives are segmentation robustness probes only: the previews are generated candidates, not independent truth, and the probe is not a visual-gate acceptance or threshold calibration. The existing vision review can provide view comparability, but rows with unknown or false comparability remain diagnostic-only so they do not block ordinary sessions. A proportion pass only means this one projected envelope interval overlaps, and does not establish visual correctness. A comparable, hash-bound mismatch blocks finish and becomes an open host finding.

Focused Rust unit tests cover same-view agreement, a clear mismatch, false or missing comparability, stale generation/fingerprint/view remaining unknown, gradient and grid backgrounds, opaque RGBA, framed transparent alpha, a truly cropped body, and suppression of a small detached axis marker. Run them through the repository's `scripts/test-lib.ps1` activation-manifest wrapper. No DSH cold start or real-image calibration was run.
