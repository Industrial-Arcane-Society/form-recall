# F7.G8：原生工具调用审计

## 为什么加审计

冷启动实测 01 中，`cad_add_hole_array` 返回完成，但 CAD revision 没变化。运行记录保存了工具名称和结束状态，没有原始参数、工具返回值或执行错误，因此无法确认它是重复操作、参数没有命中目标，还是工具返回了不改变几何的结果。

## 记录内容

原生 `ToolExecutor::execute` 每次调用后追加一行到当前 session 的 `native-tool-audit.jsonl`：

- DSH `call_id`、工具名称、脱敏后的参数；
- 执行成功或失败；失败时记录分类和原始可读错误；
- 参数接受状态及其依据。当前这是基于 executor 返回值和错误消息的诊断标记，不宣称存在独立 JSON Schema 校验；
- 成功返回的摘要：文本字节数与 SHA-256、图像数量、工具错误标记和执行引擎字段；
- 调用前后可读取到的 CAD revision。

Credential、图片和二进制内容类字段会被替换为 `[REDACTED]`。成功摘要用于关联结果，不保存整个工具返回正文或图片载荷。审计写入失败不会覆盖原工具错误，也不会把已成功提交的建模操作改报为失败。

## 验证与限制

Subagent 报告 4 项定向审计测试通过，覆盖正常调用、脱敏、重复孔位导致的无 revision 变化、参数拒绝和执行错误。当前证据只证明本地审计实现的定向测试通过，不代表真实 DSH 链路已复跑。

本日志不能追溯冷启动实测 01；调用参数、返回内容和错误没有保留就无法事后恢复。审计里的“成功”表示 executor 返回 `Ok`，并不表示模型目标或几何质量已通过审查。下一次生产同源冷启动验收需要同时保存原图 SHA、DSH trace、审计行、CAD state revision、几何报告和单视图审查证据，判断工具调用是否造成了预期几何变化。
