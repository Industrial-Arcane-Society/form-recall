# F5.8：Quick 普通 PCD 孔阵列与相位

## 范围

为普通基础体上的孔特征补充显式 PCD、孔数和可选角度相位解析。目标输入把孔径、孔型、数量和分度圆写在同一个孔子句中；该范围不包含跨子句继承，也不更改法兰模板、四角孔或其他旧零件库规则。

有证据支持的 Python legacy 输入：

- `长方体 长100宽80高20，均布4个直径10的通孔分度圆60`
- 同一语义的别名：`节圆60`、`分布圆60`

在 2026-10-04 从 `nlparser.parse(text).doc.to_dict()` 捕获的 Python 输出中，孔特征为 `kind=hole`、`op=cut`，参数为 `diameter=10`、`through=true`、`axis=Z`、`pos=pcd`、`segments=24`、`count=4`、`pcd=60`；孔径、孔数和 PCD 的 provenance 均为 `explicit`，解析 warnings 为空。完整字段保存在 `src/apps/desktop/src-tauri/tests/fixtures/quick_pcd_contract.json`。Rust 对拍只比较孔特征几何参数及 provenance；Rust 当前额外返回的“未标单位按 mm 解释”和移除 legacy 隐式尺寸警告属于安全语义差异，不要求与 Python 的 warnings 对齐。

Python parser 不支持孔阵列相位：同一输入附加“相位30度”时，legacy `Feature.params` 仍没有 `phase` 字段。Rust Quick 接受显式度制相位作为本机扩展，在 CADPlan 中记录 `phase` 与 `sources.phase.type=user`，并返回 `pcd_phase_native_extension` 警告；不能把这项行为宣称为 Python parity。

## 参数与失败边界

- `pos=pcd` 必须同时有 PCD 直径和孔数。缺少任一项时返回 `needs_clarification`，不生成计划。
- PCD 必须是有限正数；孔数必须是整数 `2..=4096`。`4096` 上限复用几何内核的 `MAX_HOLE_PATTERN_COUNT`，避免解析器与执行器的资源边界漂移。
- PCD、孔数和明确相位都绑定到原始输入的 user provenance。旧模板无关的 `axis=Z` 与 `segments=24` 默认值保留为 derived provenance。
- 相位只按度读取；`°`、`deg`、`度` 或 CADPlan 默认角单位均表示度。当前拒绝带 `rad`/`弧度` 的输入。相位要求有限数值，几何位置公式使用 `pcd/2` 和 `phase` 度；几何内核按 CADPlan 全局原点生成孔中心。
- 同一子句中的 PCD、孔数、中心孔位置冲突，互相矛盾的孔数/PCD、非法计数或孔径缺失均 fail closed。跨逗号的 PCD/数量片段暂不继承到另一孔，避免旧 parser 的 pending 值绑定错孔。
- 旧 parser 在缺少孔数或分度圆时可能把孔放到中心、使用默认数值或丢弃相位；这些历史行为不复制。未给出的定位/数量不被静默补默认值。

## 验收

Rust parser golden 测试读取上述 legacy oracle fixture，核对 PCD 孔全部 legacy 参数和 explicit→user provenance 映射。额外的 Rust 扩展 fixture 覆盖 degree phase。正例检查孔数上下界 `2` 和 `4096`，负例覆盖缺字段、相互冲突的孔数/PCD、低于最小值/零/超过几何上限、非正 PCD，以及弧度相位。几何单测直接核对 PCD 孔中心坐标、全局原点约定、度制相位旋转和孔数边界。

2026-10-04 验证结果：Rust parser 测试组 15/15 通过，几何坐标定向测试 1/1 通过。再次执行 Python legacy parser oracle，分度圆、节圆、分布圆三种输入均输出相同孔参数与 provenance、Python warnings 为空；附加“相位30度”后 legacy 输出仍无 `phase` 字段。Rust 自身的额外安全警告不纳入 Python parity。`git diff --check` 通过。该结果只证明列明的 Quick 语法和孔位置几何契约，不扩展为旧解析器全部语法、CATIA 或 Agent 端到端验收。
