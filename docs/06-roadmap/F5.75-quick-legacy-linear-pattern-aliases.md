# F5.75：迁移旧 Quick 显式线性阵列别名

## 范围

旧 Python Quick 接受 `复制/拷贝/排列/分布 + 数量 + 正间距` 等表达。Rust Quick 只认 `阵列N个` 和英文 `linear array`，导致有些旧语句虽可解析基础体和孔，却静默少建阵列。本项只对一个明确别名、明确整数数量（2–1000）和正间距的请求做归一化；PCD、圆周/等角语义、多个操作和含糊分布仍拒绝改写。

## 轴向与来源

旧 Python 在省略方向时默认沿 Z 轴。Rust 本次只对成功命中的旧别名兼容分支补入 Z 轴，并把该轴来源标为 `derived`，同时返回 `legacy_linear_pattern_default_axis` 警告；显式 X/Y/Z 仍标为用户给定。阵列保留对前序切除特征（例如中心孔）的 `pattern_source` 关系。

## Python Quick 对照与几何验收

旧 Python 公开入口实测下列 3 例均返回 box + through-hole + linear pattern，尺寸均为 `100×80×20 mm`：

| 输入别名 | 阵列数量 | 旧轴/步距（mm） | Rust 结果 |
|---|---:|---|---|
| `复制4个，间距2` | 4 | Z / [0, 0, 2] | 一致；缺省 Z 标为 derived 并产生警告 |
| `沿X方向排列4个，间距10mm` | 4 | X / [10, 0, 0] | 一致；轴向标为 user |
| `沿Z方向分布4个，步距2` | 4 | Z / [0, 0, 2] | 一致；轴向标为 user |

Rust Parser 契约 fixture 断言 3 个特征、阵列参数、切除阵列关系和轴来源。实现复用既有 Quick 线性阵列到 OCCT 的建模路径。

首轮 headless 复核还发现显式 `X 方向` 阵列子句会污染基础体的轴向，错误地把长方体外形从 `100×80×20 mm` 变为 `20×100×80 mm`。实现中已将阵列及其间距子句从基础体参数收集隔离；回归用例要求阵列方向只作用于 pattern，不能旋转基础长方体。

## F5.75 验收结果

- `cargo check --tests` 通过，Rust 契约测试可编译。
- Release headless/OCCT 三条迁移用例均为 `complete`，包围盒均为 `100×80×20 mm`，几何报告 `passed`，闭合实体数为 1；阵列轴、步距与来源类型符合 fixture。
- 额外负例验证：X 方向只出现在孔子句、而 `分布4个` 子句未给方向时，不会把孔方向误当成阵列方向；该输入只生成基础体与孔，不误建 pattern。
- `cargo test --lib ...legacy_linear_pattern_aliases_match_python_quick_contract` 未能启动测试可执行文件，Windows 返回 `0xc0000139 (STATUS_ENTRYPOINT_NOT_FOUND)`。因此报告不将 Rust 单元测试记为已执行通过；当前行为证据来自 Release headless/OCCT 矩阵。
- F5.75 后重新运行 66 项旧 Python/Rust Quick 全目录审计。60 项旧 Python 成功样例均在 Rust `complete`，几何报告 `passed`、各有一个闭合实体；另外 6 项两端都没有生成模型。与 F5.69 快照比较，66 项输入相同，状态、包围盒、几何状态、闭合实体数和体积变化均为 0。该目录集不含本次新增的三条别名用例，因此另保留上面的定向几何验收。

全目录快照：`src/apps/desktop/src-tauri/tests/fixtures/quick_legacy_catalog_baseline_after_f5_75.json`。

## 限制

这是窄范围旧语法归一化，不表示所有自然语言复制、排列或孔阵列已支持。无正间距、非数字/歧义数量、多个阵列操作、PCD 和圆周排列不会自动猜测。完整桌面 UI 与 CATIA COM 未在本项验证。
