# F5.93：Quick 体积差异归因与表面比较验收工作包

## 范围与证据边界

本记录基于 `main` 提交 `8a93170`，归纳 F5.89 的 66 项对照快照、F5.25 齿轮 B-Rep 对拍记录、F5.48/F4.2.5 活塞验收记录，以及旧 Python 与 Rust 的当前源码。此次只做静态证据审计，没有运行 Cargo、没有重建几何、没有导出新的对照模型。

F5.89 的审计工具并没有比较两端保存的表面几何：旧端读取 `Parser.parse()` 得到的 `Document`，再用 `doc.stats()` 取得 `dimensions_mm` 和 `volume_mm3`；`Document.stats()` 调用 `Document.build()` 网格并用 `K.volume_of()` 计算旧网格体积。Rust 端读取 Quick B-Rep 几何报告中的尺寸和 OCCT B-Rep 体积。比较器输出特征、参数、细分、说明、包围盒和体积差异，但没有持久化或加载两端网格，也没有拓扑、表面距离、体素或轮廓投影对照。因此 F5.89 的大体积差异表是筛查信号，不能单独判定新旧实体不等价。

入口与测量链：[`Parser.parse`](../../src/legacy/ai_modeler/core/parsing/nlparser.py#L680) → [`Document.build`](../../src/legacy/ai_modeler/core/model/docmodel.py#L838) → [`Feature.build`](../../src/legacy/ai_modeler/core/model/docmodel.py#L245) → [`Document.stats`](../../src/legacy/ai_modeler/core/model/docmodel.py#L954) → [`K.volume_of`](../../src/legacy/ai_modeler/core/geometry/kernel.py#L2184)。旧 B-Rep 是独立路径：[`Document.build_brep`](../../src/legacy/ai_modeler/core/model/docmodel.py#L789) → [`occ_kernel.build_document`](../../src/legacy/ai_modeler/core/geometry/occ_kernel.py#L1893)。F5.89 的采集脚本实际只走前一条旧网格路径：[`audit_quick_legacy_samples.py`](../../tools/audit_quick_legacy_samples.py#L40)；比较器只对报告中的标量和参数作比较：[`compare_quick_legacy_parity.py`](../../tools/compare_quick_legacy_parity.py#L212)。

## 斜齿轮源码入口更正

F5.89 中指向 `kernel.py` 齿廓函数的链接只能说明通用齿廓定义，不是旧 Quick 建立该样例的实际入口。目录实际运行链是 `Parser.parse()` → `Document.build()` 的逐特征循环 → `Feature.build(ctx)` 的 `helical_gear` 分支。对应代码位于 [`Document.build`](../../src/legacy/ai_modeler/core/model/docmodel.py#L838)、它调用 `f.build(ctx)` 的循环，以及 [`Feature.build` 的 `helical_gear` 分支](../../src/legacy/ai_modeler/core/model/docmodel.py#L407)。

该分支把 `helix_deg` 保留为特征参数，但实际构造并未应用螺旋角：有中心孔时调用 `K.make_twisted_tube(..., h, 0.0, ...)`（`twist_deg=0.0`）；无中心孔时直接挤出直齿轮廓。旧 Quick 这条路线生成的是直齿近似，不是真实斜齿表面。`Document.build_brep()` 则是另一条 OCP 路径，F5.25 的 B-Rep 体积记录属于它，不能与 F5.89 的 `Document.build()` raw mesh 混为一谈。

## 下一验收工作包：可复跑的表面等价对照

下一轮对每个争议样例建立单独目录，保存源输入、解析特征、构建配置、软件/内核版本、单位和 SHA-256，并保留三种几何路径的身份标签：旧 `Document.build()` 原始网格、旧 `Document.build_brep()`（仅适用且成功时）、Rust Quick OCCT B-Rep。不得覆盖或把旧 OCP 修正结果标记成 raw mesh oracle。

1. **保存两端几何与运行元数据。** 保存原始 Python 多边形网格；保存 Rust 可重开的 AIMODEL 与 B-Rep 导出/OCCT 三角网格；需要验证旧 OCP 路径时另外保存其 STEP/B-Rep 和报告。每项都记录输入文本、特征参数、单位、构建路径、OCCT/OCP 版本、容差及文件哈希。
2. **先做拓扑与网格健康检查。** 对 B-Rep 检查 valid、闭合壳/实体数、面与边数量、连通分量和非流形/退化；对网格检查边界边、非流形边、连通分量、退化三角形、自交、面法向一致性和有向体积。raw mesh 的有向体积若超过 bbox 体积或对法向翻转敏感，应标为无效测量并定位具体面片，不作为对拍门槛。
3. **统一公差重新网格化。** 对有效的两端 B-Rep 使用相同线性偏差、角度偏差、单位、法向与三角化设置重新采样；另把旧 raw mesh 原样保留，避免重网格掩盖它的问题。网格尺寸/面数只作为采样记录，不要求面数相同。
4. **做双向表面距离。** 计算三角面表面的双向最近距离，至少报告对称 Hausdorff 最大距离、Chamfer 均值及 P95/P99；采用固定、记录的采样策略并报告空间单位。齿轮和活塞增加齿廓/环槽截面与轴向关键截面距离。
5. **做体素和正交投影对照。** 在多个记录明确的体素尺寸下报告交并比、双向漏出/缺失体素比例；对六个正交方向和一张等轴方向渲染同尺度、同相机与轮廓阈值的 silhouette，对比轮廓交并比与边界距离。弹簧需额外比较中心线/圈距；涡旋盘需比较壁线和背盘连接；手轮需检查辐条、轮毂和轮缘交接处。
6. **按路径给结论，不用单指标代替形状。** 每行结果分别判定 `raw_mesh_validity`、`old_ocp_brep_vs_rust_brep` 和 `legacy_raw_mesh_vs_rust_surface`。只有同时满足预先制定的拓扑门、包围盒门、距离门、体素门及关键投影/截面门，才标几何等价；参数/包围盒/体积相等单独不够。

## 当前不作出的结论

- 齿轮旧 B-Rep 与 Rust B-Rep 体积相等，不代表表面相同；F5.89 的旧 mesh 体积差也不能推翻该 B-Rep 证据。
- 活塞旧 raw mesh 的不可能体积揭示了旧网格路径缺陷；它不代表旧 OCP B-Rep 路径同样错误。
- 涡旋盘和辐条手轮的旧构件拼接体积超出 bbox，能够否定该 scalar 作为实体体积，却不能判断当前 Rust 外轮廓细节是否等价。
- 两种弹簧的具体体积差成因仍未知。
- 包围盒一致、闭合实体有效、AIMODEL 可重载或 CATIA 未参与，都不能替代表面级复核；本记录没有声称已完成新的几何重建或 CATIA 验收。
