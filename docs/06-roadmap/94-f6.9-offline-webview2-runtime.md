# F6.9：将 WebView2 离线安装器打入桌面安装包

日期：2026-10-05

## 目标

F6.8 已将 DSH/Node 和 npm 依赖改为随安装包分发；这仍留下 Tauri Windows 安装器在目标机器缺少 WebView2 Runtime 时联网下载的默认行为。本项让 MSI 与 NSIS 都携带 WebView2 x64 离线安装器，使缺少该运行时的机器也可以离线完成安装。

WebView2 是 Vue 桌面界面的渲染运行时。CATIA 本体和 AI provider 服务不属于桌面包资源：使用 CATIA 导出/推送仍要求机器安装兼容的 CATIA；调用在线 provider 仍需用户配置和网络。

## 实现

- 在 `src/apps/desktop/src-tauri/tauri.conf.json` 将 `bundle.windows.webviewInstallMode` 设为 `offlineInstaller`，并启用静默安装。Tauri 在 MSI Binary 表和 NSIS `$TEMP` 安装阶段资源中嵌入 WebView2 x64 离线安装器。
- 在 `build_desktop_resources.mjs` 生成的 `RUNTIME-INFORMATION.txt` 中注明 MSI/NSIS 含离线安装器。
- 当前安装包将 WebView2 离线安装器与 F6.8 DSH/Node ZIP、按需 CATIA Python/pywin32、OCCT DLL 和应用静态资源一起分发。DSH ZIP 首次使用时从安装资源解压到用户数据目录；不在目标机执行 `npm install`。

## 构建与静态验收

- 构建命令：`npm.cmd --prefix src/apps/desktop run tauri:build`。Vue production build、Rust Release build、OCCT 19 个 hash 校验 DLL staging、DSH 离线 ZIP SHA 校验及 MSI/NSIS 构建均通过。
- 两种安装包抽取后均含 212,272,848-byte 的 `MicrosoftEdgeWebView2RuntimeInstaller.exe`；安装程序 EXE 的文件版本元数据为 `1.3.271.7`。MSI 中位于 `Binary.MicrosoftEdgeWebView2RuntimeInstaller.exe`，NSIS 中位于 `$TEMP\MicrosoftEdgeWebView2RuntimeInstaller.exe`。
- MSI 与 NSIS 的 Tauri 资源映射均为 208 项，按文件路径、长度和 SHA-256 对拍结果分别是 `missing=0, extra=0, hash mismatch=0`。其中包括应用/知识库、Python 3.13、CATIA bootstrap、OCCT Runtime 和 `RUNTIME-INFORMATION.txt`。
- 用两包抽取目录内的应用资源分别运行 `ai-modeler-headless-smoke.exe`：均返回 `status=ok`，由 Rust/OCCT 生成 100×60×20 mm 的闭合实体并导出 AIMODEL、GLB、OBJ、STL；运行时将 PATH 限制为 System32，并清除了 Python/Node 环境变量，结果报告 `globalPythonRequired=false`、`globalNodeRequired=false`、没有启动 Python/Node 子进程。

## 边界与后续

- 本项未在主机上安装 MSI/NSIS，也未启动可见 Tauri GUI。CLI smoke 只验证抽取后的应用资源能支持本地 Quick 几何流程，不证明 GUI 首屏显示、安装后 WebView 初始化、DSH provider 对话或真实 CATIA COM 导出。
- Tauri 官方文档说明 Windows 10 1803 及更新版本、Windows 11 通常已随系统提供 WebView2；本包仍携带离线安装器，以覆盖目标机器缺少运行时的情况。[Tauri Windows Installer 文档](https://v2.tauri.app/distribute/windows-installer/)
- CATIA 本体仍由用户另行安装；AI provider 请求仍受相应服务的账号、配置和联网要求约束。完整离线安装依赖不等于离线 AI 推理。
