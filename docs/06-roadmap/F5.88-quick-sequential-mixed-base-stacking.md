# F5.88 Quick 顺序异种基础体堆叠兼容

## 范围

只迁移旧 Python Quick 已明确成功的顺序：圆柱后接长方体，输入为：

`圆柱直径20高30，再做一个长方体长100宽60高20`

两段都必须显式给出完整正尺寸，并以“再做/然后做”明确分隔。第一圆柱按全局 Z、底面 z=0 建立；第二长方体的底面从第一实体实际顶面 Z=30 mm 起算。关系来源记为 derived/depends_on，不在 CADPlan 中保留 Python 私有 `stack=true`。

迁移补丁仅处理这一个已证实的次序。反序“长方体……再做圆柱……”旧 Python 虽返回成功，却丢掉长方体并错误生成 Ø20×20 圆柱；这是旧端 bug，不作为迁移目标。补丁对其它顺序返回给现有通用 Quick 路径，不为其增加兼容行为。当前通用路径会因多种基础体返回 `multiple_base_shapes`。无明确连接词、同类实体、第三个主体、显式位置/坐标、重叠或非 Z 轴语义，以及附加孔槽等请求均不生成部分可执行计划。

## 旧 Python 入口实测

通过 `Parser().parse()` 公共入口后对 `result.doc` 调用 `Document.build()`、`Document.stats()`，使用 `python -B` 在本地重放：

- 输入 `圆柱直径20高30，再做长方体长100宽60高20`：`ok=true`、`recognized=2`，特征是 Z 向 Ø20 高30 圆柱和 100×60×20 长方体；第二特征带 `stack=true`。构建成功，215 faces、426 triangles，bbox `[-50,-30,0,50,30,50]`、尺寸 100×60×50、体积 `129397.88583984367 mm3`、面积 `20283.61012182812 mm2`。
- 反序输入 `长方体长100宽60高20，再做圆柱直径20高30`：`ok=true` 但只识别到一条圆柱特征，得到 Ø20、高20 的圆柱，原长方体及文字高度30均被吞并，没有解析警告。它不是旧端成功堆叠路径。

## Rust 当前根因与变化

在验收基线 `95c8f0c`，`native_quick_parser.rs` 的 `parse()` 收集全文 `base_kinds`；出现 Box 与 Cylinder 两类时进入 `multiple_base_shapes` unsupported，计划为空。通用几何实现虽可以表达底面和位置，但 parser 没有将顺序两体变成两个可验证特征。

隔离候选在 parser 前置路由中只处理清晰的两个异种基础体，并进一步限制为 Cylinder→Box。第二基体的 Z 底面由第一基体中心和高度推导，记录 `sources.center` 与 `depends_on`。其它请求有负向 parser contract；OCCT 测试按目前测试约定读取 `AIMODELER_TEST_OCCT_MANIFEST`。

## 验收

- Parser contract：唯一旧端成功输入得到 2 个特征；第二个 Box `center=[0,0,30]`、`base=true`、`axis=Z`；CADPlan validator 和 native geometry preflight 均通过；无私有 `stack` 字段；来源和依赖关系完整。
- 无连接词、重叠、显式坐标、同类重复、不支持类型、缺失尺寸和第三实体均拒绝生成计划；反序不属于本迁移验收项，其旧端错误输出只保留在差异报告。
- Ignored OCCT geometry test：单闭合实体；bbox `[-50,-30,0,50,30,50]`；尺寸 100×60×50；解析 B-Rep 体积 `120000 + π×10²×30 = 129424.7779607694 mm3`；AIMODEL round-trip 保留 CADPlan。旧 Python 体积来自 48 边网格，`129397.88583984367 mm3`；只按圆柱多边形离散差异说明，不能把它当解析实体体积真值。
