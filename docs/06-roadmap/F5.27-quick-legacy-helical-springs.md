# F5.27 Quick 旧版螺旋弹簧配方迁移

更新时间：2026-10-07

## 范围

将旧 Python Quick 的圆柱螺旋弹簧和锥形螺旋弹簧单件配方接入 Rust Quick。解析结果沿用 `helix/add` 与旧版采样参数；Rust 通过本地 OCCT 构造缝合的近似 facet-BREP。此迁移不声称解析扫掠曲面或 CATIA 原生螺旋特征已实现。

## Python Quick 基准

使用 `Parser().parse()` 从旧入口核对了相关输入：

- `螺旋弹簧 外径20 线径2 高度30 圈数8` 识别为一个 `helix/add`，参数为 `radius=8.991371039419848`、`wire_r=1.0086289605801528`、`height=27.982742078839696`、`turns=8`、`center=[0,0,-13.991371039419848]`、`seg_per_turn=16`、`wire_seg=24`、`taper=0`、`taper_start=0`；无 warning/assumed/questions。
- `锥形弹簧 外径24 线径2 高度40 圈数6` 生成相同截面参数，`radius=10.991371039419848`、`height=37.98274207883969`、`center.z=-18.991371039419846`、`turns=6`、`taper=0.5`、`taper_start=1/6`。
- 缺线径时旧 Python 零件库采用线径 2 mm。缺少外径或高度则旧 Parser 未识别，不应调用库默认尺寸猜造完整弹簧。
- 旧 Python 对锥形弹簧输入 `6圈` 未绑定圈数，实际仍产生 8 圈、`taper_start=0.125`；显式 `圈数6` 会正确生成 6 圈。Rust 保留旧几何结果，并用 warning 提示该旧输入歧义，建议使用“圈数6”。
- 圆柱弹簧可识别裸写的 `8圈`。各别名及正负样本记录在 [`quick_legacy_helical_springs_contract.json`](../../src/apps/desktop/src-tauri/tests/fixtures/quick_legacy_helical_springs_contract.json)。

公式对应旧 Python `partlib._spring_params`：`wire_r=max(0.2,d/2)/cos(pi/24)`、`radius=max(0.5,D/2-wire_r)`、`height=max(1,H-2*wire_r)`、`center.z=-H/2+wire_r`。Rust 对线材不适配给定外径/高度的情况返回澄清，以免旧版钳制公式改变用户输入的外形尺寸。来源字段区分用户尺寸、推导值和旧版默认值。

## Rust 行为与边界

- 单独接受圆柱螺旋和锥形螺旋弹簧；显式外径和高度为必需参数，线径沿用旧默认 2 mm，圈数沿用旧构造器 8 圈默认值并给出 warning。
- 圆柱螺旋支持“圈数N”与“N圈”；锥形输入的裸“N圈”按 Python 实际结果沿用 8 圈并发出兼容 warning，避免把旧缺陷隐藏起来。
- 碟簧、板簧、扭簧、弹簧片及组合孔槽等请求明确返回 unsupported，不会落入普通圆柱回退。
- 对半径、轴向尺寸不匹配的线径、无效圈数、冲突圈数返回澄清。
- 旧 Python 的 24 边线材截面和每圈 16 段路径保留为几何参数；来源信息说明外径、自由高度到 helix 内部参数的换算。

## 验收

- Python 旧 Parser 对拍样例、预期 helix 参数、来源和拒绝边界见 fixture；Rust parser 测试校验 CADPlan 和 native preflight，测试目标已编译。
- 使用打包 app resources 和 OCCT 7.9.3 的 `ai-modeler-headless-smoke.exe` 实际生产路径完成圆柱与锥形样例：圆柱弹簧为单个有效闭合实体，包围盒 `20×20×30 mm`、6192 三角面、体积 `1391.543508413009 mm³`；锥形弹簧为单个有效闭合实体，包围盒 `24×24×40 mm`、4656 三角面、体积 `1009.9939760458617 mm³`。两者 AIMODEL 重载通过，GLB/STL/OBJ 文件均存在。
- 同一生产 CLI 还验证线径与圈数默认值有 warnings、锥形裸写“6圈”仍按旧版 8 圈输出且明确警告，以及缺外径、扭簧、复合孔要求和冲突圈数均不会生成模型。
- Windows 无法启动隔离 Rust 测试 exe，进程退出码为 `-1073741511`（`0xC0000139`）；因此不将 Rust 单元测试运行计为通过。生产 headless 路径提供了上述几何验收证据。
- 预览视觉未核对，CATIA 未执行；CLI 的 `visual_status=not_reviewed` 和 `catia_executed=false` 保持原样。
- facet-BREP 是当前 Rust 本地几何结果；不代表旧 Python 网格逐面一致，也不代表 CATIA 已执行。
