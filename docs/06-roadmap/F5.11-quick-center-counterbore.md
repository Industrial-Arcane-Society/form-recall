# F5.11：Quick 显式中心通孔与沉孔

## 范围

迁移旧 Python Quick 的一项高频两段式切除：同一修饰子句显式描述中心通孔，并用“带”连接沉孔直径与沉孔深度。只接受 `中心孔`/`中心通孔`、`通孔`、`带`、`沉孔` 这些明确标记；中心通孔和沉孔都必须给出唯一的正直径，沉孔深度必须显式为正，且沉孔直径必须大于通孔直径。

Rust Quick 依次生成两个 `hole/cut` feature：小径中心通孔，然后大径中心盲孔。两个 feature 均以完整原始 prompt 作为用户证据；显式直径、通孔类型、中心位置和深度保留为 user provenance。未指定轴时沿用旧 Python 孔特征的 Z 轴默认值并标为 derived；固定 24 段也沿用旧 Python 参数并标为 derived。沉孔的 `through=false` 由显式“沉孔”语义推导。

## Python oracle

Oracle 为 `src/legacy/ai_modeler/core/parsing/nlparser.py` 的 `make_hole()`、`_diameters_in()` 和 `_add_hole()`，输入及旧 feature 参数/顺序实测后保存在 `src/apps/desktop/src-tauri/tests/fixtures/quick_counterbore_contract.json`。显式深度样例生成小径 through hole 后接大径 blind hole；两者 `axis=Z`、`pos=center`、`segments=24`，第二项显式 `depth=5`。Fixture 另记录旧 parser 无深度时默认 `depth=5.0` 的实测结果。

为保持新解析的可审查性，Rust 不迁移这个旧默认：沉孔缺深度、缺径、冲突直径/深度、非正尺寸或沉孔直径不大于通孔直径时返回 `needs_clarification` 且不生成 plan。对应的 Python fixture 重放同时核对 explicit-depth 正例和旧 parser 默认深度边界；Rust 回归逐字段核对旧 feature 顺序/参数，并检查新 CADPlan 的 sources 与验证状态。

## 限制与验收边界

- 只支持一个普通基础形体加一个中心沉孔修饰子句；阵列、四角、坐标、多个切除组合及非中心位置返回 `unsupported`。
- `扩孔`、`沉台`、`沉坑`、`锪孔`、`埋头孔` 属于不同或未迁入的语法，明确拒绝，不把它们映射成沉孔。
- 不迁移旧 parser 省略深度时的 5 mm 默认值，不推导缺失直径或位置。
- 这项只验收 Quick parse、CADPlan 参数/source 和 plan validation，不代表 OCCT 几何、CATIA、GUI、Agent 或 Quick→Agent 端到端验收。
