# F5.90：恢复旧 Quick 未定位单个通孔的中心默认

## 旧入口行为与迁移边界

旧 Python `Parser.parse` 的 `make_hole()` 在通孔未提供位置时默认 `pos=center`。Rust 之前对同类输入返回 `hole_position_missing`，与旧 Quick 的单孔默认行为不同。

本项只恢复明确、无歧义的窄场景：一个受支持的主体、一个有直径或半径的通孔，且没有位置、侧面、孔阵列或多孔分布提示。推导出的中心位置、Z 轴和 24 段圆周细分均标记为 `derived` 并带有说明。未定位的多个孔、左右/两边/上下分布孔、侧孔和复合修饰仍要求澄清；不会把它们静默折算成一个中心孔。直径数字不再误判为孔数，“一个孔”也不单独触发 PCD 阵列。

F5.84 的沉孔先导孔继承仍要求位置来源为用户明确给定。F5.90 推导出的中心孔不能冒充显式 pilot，因此不会被后续沉孔误继承。

## 验收证据

固定输入：`长方体100x60x20，然后打直径8通孔`。

- Parser 输出 `ready`，生成长方体和一个 `diameter=8 mm` 的贯穿孔；孔中心为原点、切入轴为 Z，默认 `segments=24`。推导参数来源记录该完整输入。
- 负例覆盖侧面通孔、多个未定位通孔、左右/两边/上下各一孔，以及缺失半径数值；这些请求均澄清且不留下部分 CADPlan。
- OCCT 定向集成用例通过：生成 1 个闭合实体，包围盒 `100×60×20 mm`，验证一个居中、Ø8 mm 的贯穿孔；几何报告体积与盒体减去圆柱孔的解析体积一致，AIMODEL 可重新载入且特征树保留。
- F5.84/F5.86 的 source-binding 回归合同和 F5.88 顺序混合主体 parser 合同通过。

本项不覆盖桌面 GUI、CATIA COM 或所有旧 Python parser 的复合孔语法；相关证据仍需独立验收。实现提交为 `4a70634`，代码与 parser/OCCT 测试位于 `src/apps/desktop/src-tauri/src/native_quick_parser.rs`。
