# F6.6 按需 CATIA COM adapter

## 边界

- Rust 当前活动模型是唯一输入来源；交接包含 F5 `ai-modeler` v1 工程、generation、revision、geometry fingerprint 与原始 CADPlan sources/evidence。
- 只在用户选择 CATPart 导出或“推送到 CATIA”时，由 Tauri 启动独立 Python 进程。常规 Quick、Agent、预览、保存和资源状态读取均不触碰 adapter。
- `src/legacy/ai_modeler/catia_com_adapter.py` 只读取固定 JSON 协议；不导入 Python `Document`、旧建模器、旧 Python Agent worker 或 MCP。它把可表达的 F5 特征映射成 Sketch/Pad/Pocket 操作，并把不支持项写入结果和 `.CATPart.report.json`。
- 当前 adapter 映射范围：矩形 box、等半径 cylinder、Z 向 prism、point/center/corners/PCD hole、Z 向矩形 pocket。结果逐特征标记 `approximate_feature_mapping`，因为 F5 的语义特征会被重建为通用 Sketch + Pad/Pocket，不能保留一对一原生特征类型和完整参数历史；单个操作的 `operation_parameters_transferred` 仅描述输入参数传入，不代表整体特征等价或 B-Rep 已验收。圆角、锥台及其他不支持种类逐项列出原因并标为跳过；没有可支持操作时在连接 COM 前失败。
- 已运行 CATIA 时 adapter 附着到现有进程；普通导出关闭刚创建的 Part，若 adapter 自己启动了 CATIA 则随即退出。用户明确执行“推送”并成功时才显示/保留创建的 Part。CATIA 提示设置会在结束后恢复。

## 验收证据

- Rust 单元测试确认 request 使用活动记录的 `.aimodel` document 与 CADPlan 来源证据，并校验 model id/generation/fingerprint；拒绝空模型、非 F5 文档。
- Python stdlib unittest 4/4 通过：headless preflight 与近似/跳过逐特征标记、mock COM 导出/来源 sidecar、mock push 成功后可见保留、以及全部特征不支持时不创建 COM 实例。
- mock 输出明确标记 `catpart_verified_in_catia=false`。真实 CATIA V5/pywin32 COM 行为、CATPart 结构/几何、系统上 Python 依赖安装、安装包冷启动均未验证，留待能安全运行 CATIA 的机器做验收；F6.7 负责依赖与安装包收缩。

可复跑命令：

```powershell
python -B -m unittest src.legacy.tests.test_catia_com_adapter -v
pwsh -NoProfile -File src/apps/desktop/src-tauri/scripts/test-lib.ps1 -Offline -Filter native_catia_adapter::tests::
npm run build
```
