# PR 与分支流程（照 BiliSum 那套来，加上我们的判据门禁）

> 结论：**值得这么做**。你朋友那套（功能分支 → PR → 描述四段 + 验证勾选 → 复核 → 合并主分支）
> 正好补上本项目最缺的一环：**改动可追溯 + 判据可见**。
> 本项目的特殊性是"判据很硬"，所以我把 PR 模板末尾加了 **判据对比表** 和 **回滚点**。

---

## 一、日常流程（5 步）

```
1. 从 main 拉功能分支      git switch -c feat/egt006-型材内腔
2. 改代码 + 本地跑判据       scripts\04_验收基准.ps1
3. 推分支、开 PR            git push -u origin feat/egt006-型材内腔
4. 填 PR 模板（四段 + 判据对比表 + 回滚点）→ 复核
5. Squash 合并到 main → 删除分支
```

对应关系（你们聊的那几句）：

| 微信里说的 | 落地做法 |
|---|---|
| 「参照我这个项目」 | 用同一套：`概要 / 原因 / 改动 / 验证` 四段 |
| 「功能商定完了就合并到主分支」 | 功能**只在分支上做**；商定（复核通过）+ 判据不变红 → Squash 合并 `main` |
| 他截图里的 AI 复核 | 打开 **Copilot code review**（Settings → Code review）或人工复核；我们的 CI 会另外贴判据数字 |

## 二、分支命名

| 前缀 | 用途 | 例 |
|---|---|---|
| `feat/` | 新功能/新零件族 | `feat/阀岛实测B-Rep` |
| `fix/` | 修 bug | `fix/catia孔位换轴` |
| `bench/` | 判据/工具改动 | `bench/图像相似度容差口径` |
| `docs/` | 文档 | `docs/云端训练方案` |

## 三、PR 模板里为什么要有"判据对比表"

本项目的判据是**可量化的硬门禁**（几何 99.8%、图像 84.5%、CATIA 523/523、自检 42/42）。
把它们写进 PR 的好处：

* 复核的人**不用读代码**也能判断这次改动值不值得合；
* 出现退化时，退化幅度写在明面上，不会被悄悄合进去；
* 半年后回头看，能知道"这一版为什么是这个分数"。

模板文件：`.github/pull_request_template.md`（GitHub 会自动带进新 PR 的正文）。

## 四、CI 自动跑（已配好）

`.github/workflows/acceptance.yml`：每次 PR / 推 main 自动跑

1. 自检（必须 42/42）
2. 自研布尔等价性（`check_bsp_local.py`，体积 + 封闭性）
3. 几何判据**抽样一族**（快，几分钟）
4. 报告存成构建产物（可下载）

> ⚠️ **全量判据不进 CI**：几何全量要 120 MB 实测网格、图像全量要 518 张真实照片，
> 这些是"可重建的大数据"（README 第三节），CI 里拉不动也存不下。
> 全量在**本地或云端**跑：`scripts\04_验收基准.ps1` / `scripts\02_跑全流程.ps1`。

## 五、分支保护（可选但推荐）

GitHub 网页：仓库 → **Settings** → **Branches** → **Add branch protection rule**
→ 分支名 `main` → 勾：

- [x] **Require a pull request before merging**（至少 1 个 approve，按需）
- [x] **Require status checks to pass**（选 `验收门禁 / 自检 + 核心判据`）
- [x] **Require conversation resolution before merging**（对应你朋友截图里的 "Resolved 对话"）
- [ ] Require linear history（用了 Squash 就够，可不勾）

> 说明：**私密仓库的分支保护需要 GitHub Pro/Team 套餐**（免费私有仓库不一定能开）。
> 开不了也不影响流程 —— 靠 PR 模板 + CI + 约定同样能守住；
> 等团队人多或要严格门禁时再升级套餐即可。

## 六、合并方式

* 用 **Squash and merge**：一个功能在 `main` 上只留一条干净的提交；
* 合并后**删除分支**（页面上的 "Delete branch"）；
* 写清楚提交信息：`feat(族名): 一句话` + 判据变化，例如：

```
feat(型材): 用实测 B-Rep 复刻外轮廓（含型腔/筋/台阶）

判据：几何 91.9→99.8（≥95% 431→498），图像 62.1→84.5，自检 42/42
```

## 七、复核要看的四件事

1. **判据对比表**填了没有、有没有退化；
2. 改动是否**只碰该碰的地方**（本项目几何逻辑很敏感）；
3. 涉及几何/CATIA 的，有没有并排图 / 真机日志；
4. 回滚点写得够不够具体（要能照着退回去）。
