# 参考图首轮读图（提交几何之前填一次）

**只回答下面四个问题。** 不要做三维重建，不要给坐标轴命名，不要逐个面写小作文。

> 为什么不要求你在图里建坐标系：这个零件是**从零新建**的，没有任何绝对基准。
> 把它叫成 X 宽 Y 深、还是 X 深 Y 宽，**零件是同一个**，叫反了不算错。
> 唯一会出错、也必须定下来的，是**孔和槽的相对关系**——那才是第 2 题问的东西。
> 你不需要判断"哪个斜向是 X"，也不需要为正负号纠结。

## 1. 数

- `visible_openings`：图里看得见的孔口总数（圆或椭圆，所有面上加在一起）。
- `hole_count`：孔的个数 = `visible_openings ÷ 2`。
  **每个通孔在两个面上各留一个孔口**（入口 + 出口）。同一个孔的两端都看得见时（例如透过槽看到出口），
  必须归并成一个孔。数错了就会把孔打多一倍。
- `walls`：壁的数量（几堵竖壁夹出一条槽）。**没有槽的整块板就写 0，不要为了填一个"合法数"编一个。**

数完就往下走，不要反复重数。

## 2. 孔相对槽的方向（唯一的判断题，二选一）

- `through_thickness`：孔**穿过壁的厚度**，也就是孔轴与"两壁分开的方向"**平行**。
  典型样子：销孔穿过两片耳，从外侧大面进、从槽内侧出；两片耳上的孔是对着的一条线。
- `along_face`：孔**平行于壁的大面**，也就是孔轴与"两壁分开的方向"**垂直**。
- `none`：图上没有孔（此时 `visible_openings` 和 `hole_count` 都写 0）。

判据（必须写一条，别写"看起来"）：

- **孔口椭圆被压扁的短轴方向 = 孔轴方向。** 拿这个方向和"两壁分开的方向"比：平行就是
  `through_thickness`，垂直就是 `along_face`。
- 或者看孔口开在哪个面上：开在壁**朝槽或朝外的两个大面**上 → `through_thickness`；
  开在壁的窄侧面（厚度面）上 → `along_face`。

两种判据应当互相印证。写清楚你用的是哪一条。

## 3. 颜色

一句话声明：**颜色只用于区分子面与特征**，不是材质、尺寸或工艺依据。
同一组孔在两个面上颜色不同，默认解释就是"同一个孔的两端"，**不要当成渲染噪声忽略**。

## 4. 判不出来就问

如果第 2 题在你这里仍然是两可：**调用 `ask_user`**，一次问清，并给出两个候选和各自的判据
（例如"孔口椭圆短轴与两壁分开的方向平行还是垂直，我这里是两可"）。
**不要"选一个看起来合理的"往下走**——猜错要整轮重做，多问一句只要几秒。

## 提交格式

```json
{
  "visible_openings": 9,
  "hole_count": 6,
  "walls": 2,
  "hole_vs_walls": "through_thickness",
  "evidence": "左面 3 个孔口 + 槽内侧 3 个孔口是同一组孔的两端，归并后 6 个孔；孔口椭圆短轴与两壁分开的方向平行",
  "color_usage": "颜色仅用于区分面与特征"
}
```

## 程序会检查什么

1. `visible_openings`、`hole_count`、`walls` 必须是正整数，且 `hole_count ≤ visible_openings`。
2. `hole_vs_walls` 必须是 `through_thickness` 或 `along_face`。
3. `evidence` 不得使用"大概/看起来/似乎/差不多"这类词。
4. 有几何之后：程序从槽（切除特征）自己算出**两壁分开的方向**，再核对计划里每个孔的轴线是否
   符合 `hole_vs_walls`：声明 `through_thickness` 就必须沿分开方向，声明 `along_face` 就必须垂直。
5. 结束时：计划里的孔数必须等于 `hole_count`，且每个通孔都要能被网格沿孔轴核验为贯通。

读图结果每轮都会重新提供；后续修改不得与之冲突。确需修正就整份重交，并说明改了哪一项。
